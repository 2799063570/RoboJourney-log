## 遇到第一个问题 陷入局部最优

如果 Step 4240 时 Loss 已经低至 0.0002 且基本不动，这通常不是因为模型学得太好了，而是因为模型**变懒了**（陷入了局部最优解）。

![[ompl/img/image-1.png#pic_center]]

### 解决方法 轨迹降采样

均匀采样是“盲目”的，它不管这一段路是直道还是急转弯，一律按固定间隔砍。

后果：在急转弯（Corner）处，如果把中间的关键点砍掉了，剩下的点连成直线，路径就会“切角”。在有障碍物的情况下，“切角”=“撞墙”。

我们需要的是**“自适应降采样” (`Adaptive Downsampling`)**：

直路：多删点（步长变大，也没风险）。
弯道：少删点（步长变小，保留形状）。

在计算机图形学和机器人领域，解决这个问题的标准算法叫做 `Ramer-Douglas-Peucker` (**`RDP`**) 算法。

但是同时，需要想到了两个问题分别是：1）步长应不应该设置一个最大步长的限制，那么这个步长是否可以自适应呢 2）`RDP`算法中的阈值epsilon应该如何设置，是否也可以自适应呢

## 损失函数的设计

单纯的`MSE Loss`并不能很好地反映路径的质量

我想的是通过分情况来进行计算：预测点在障碍物内、预测点在障碍物外但是路径与障碍物相交给予很大的惩罚；预测点与真实点方向相反给予较大惩罚；预测点不动了给以惩罚；预测点是否在四个历史点和目标点组成的延长线上；加入平滑度的计算；预测点与目标点之间的距离

如果你的显存和算力允许，最完善的 Loss 应该是这样的：
$$L_{total} = \lambda_1 L_{pos} + \lambda_2 L_{dir} + \lambda_3 L_{smooth} + \lambda_4 L_{coll\_body} + \lambda_5 L_{limit} + \lambda_6 L_{stag}$$

1. $L_{pos}$ (MSE): 基础，必须有。
2. $L_{coll\_body}$: 改为全身检测，比单点检测重要得多。
3. $L_{limit}$: 加上这个，否则上真机必报错。
4. $L_{dir}$: 对于 MPNet 这种一步步走的模型，这个对收敛帮助很大。
5. $L_{smooth}$: 加权平滑。
6. $L_{stag}$: 防停滞。

这个时候我想到的是像障碍物一样去做映射，映射到一个固定标准的体素网络中。但是机械臂的6维空间还是比较大，所以现在考虑的是将关节空间映射到末端的笛卡尔空间中去，然后在笛卡尔空间中做体素网格的映射。如果要映射的化，那么就需要确定一个映射的范围，这个范围应该是机械臂能够到达的空间范围。刚开始考虑的是100*100*50，带来将近50万个体素。

后来思考了一下，把 6维关节空间的路径（Joint Space）强行映射到 3维笛卡尔空间的体素网格（Cartesian Space），确实会丢失大量信息。丢失主要体现在以下两个方面：1）同一个笛卡尔空间点对应多个关节空间点；2）机械臂的姿态信息完全丢失（只保留了末端位置）。

解决方法就是采用一种双流架构，我们将输入分为两路：1）视觉流：障碍物信息+机械臂末端轨迹痕迹；2）本体流：输入历史状态序列

### 损失函数的损失平衡问题

我们设置了几种不同的损失，形成一个多任务学习（Multi-Task Learning, MTL）或多目标优化（Multi-Objective Optimization, MOO）的场景。

但是每个损失都有自己的量级（Scale），这会导致训练过程中某些损失主导了梯度更新，而其他损失被忽视。

有一种方式是自动学习权重(Alex Kendall 在 CVPR 2018)

假设每个任务都有一个“不确定性” $\sigma$。如果某个任务很难（Loss 很大），网络会自动增大 $\sigma$ 来降低该 Loss 的权重，但为了防止 $\sigma$ 无限大，公式中有一项 $\log \sigma$ 作为惩罚。

公式：$$L_{total} = \frac{1}{2\sigma_1^2} L_1 + \frac{1}{2\sigma_2^2} L_2 + ... + \log(\sigma_1\sigma_2...)$$为了数值稳定性，通常令 $s = \log(\sigma^2)$，公式变形为：$$L_{total} = \sum ( \frac{1}{e^{s_i}} L_i + \frac{1}{2} s_i )$$

```python
import torch
import torch.nn as nn

class MultiTaskLoss(nn.Module):
    def __init__(self, num_tasks):
        super(MultiTaskLoss, self).__init__()
        # 这里的 params 就是 s = log(sigma^2)
        # 初始化为 0.0，相当于初始 sigma=1，权重=1
        self.log_vars = nn.Parameter(torch.zeros(num_tasks))

    def forward(self, losses):
        """
        losses: list or tensor containing [loss_pos, loss_limit, ...]
        """
        total_loss = 0
        for i, loss in enumerate(losses):
            # 核心公式： exp(-s) * loss + 0.5 * s
            # 这里的 exp(-s) 相当于自动学习到的权重 w
            weight = torch.exp(-self.log_vars[i])
            total_loss += weight * loss + 0.5 * self.log_vars[i]
        
        return total_loss

# --- 使用方法 ---
# 假设您有 7 个 loss 分量
mtl_layer = MultiTaskLoss(num_tasks=7).to(device)
# 将 mtl_layer 的参数也加入优化器
optimizer = torch.optim.Adam(
    list(model.parameters()) + list(mtl_layer.parameters()), 
    lr=1e-4
)

# 在训练循环中
losses = [loss_pos, loss_limit, loss_coll, loss_dir, loss_smooth, loss_stag, loss_goal_align]
total_loss = mtl_layer(losses)
total_loss.backward()
optimizer.step()
```

### transformer部分


我们设定的输入序列是这样的（共 110 个 Token）：

* **Token 0 (`curr`)**: 机器人现在的姿态。
* **Token 1 (`goal`)**: 机器人想去的姿态。
* **Token 2~109 (`grid`)**: 地图上 108 个不同区域的障碍物特征。

假设我们设置了 **4 个头 (Heads)**。这意味着我们将把 128 维的特征切分为 4 个 32 维的子空间。

虽然代码里是矩阵乘法，但在物理意义上，模型正在把 Token 0 (`curr`) 的 128 维信息拆解给 4 个不同的**专家**（head）去处理。

每个专家（Head）都有自己独立的  权重矩阵，这意味着它们**关注的重点完全不同**：

* **Head 1 (导航员)**：它专门学习“位置与目标”的关系。
* **Head 2 (安保队长)**：它专门学习“本体与障碍物”的距离关系。
* **Head 3 (几何学家)**：它关注地图空间的连通性（哪块路和哪块路是通的）。
* **Head 4 (运动协调员)**：它关注关节角度的合理性。

此时，Token 0 (`curr`) 被切成了 4 份，分别送到了这 4 个专家的办公室。

---

**第二步：专家会诊 (Scaled Dot-Product Attention)**

这是最精彩的部分。我们看看每个专家是如何利用 Attention 机制来处理 Token 0 的。

**场景 1：Head 1 (导航员) 的办公室**

* **Query ()**: Token 0 (`curr`) 发出查询：“我的目标在哪里？”
* **Key ()**: 所有的 110 个 Token 都在展示自己的标签。
* Token 1 (`goal`) 举手说：“我是目标！” -> **匹配度极高 (Score 高)**。
* Token 50 (`grid`) 举手说：“我是墙。” -> **匹配度低 (Score 低)**。

* **Value ()**:
* Head 1 几乎把 90% 的注意力权重都给了 Token 1。
* **结果**：Head 1 输出的新向量里，融合了大量的 `goal` 信息。它得出的结论是：“我们要往东北方向走。”


**场景 2：Head 2 (安保队长) 的办公室**

* **Query ()**: Token 0 (`curr`) 发出查询：“我不关心目标，我只想知道谁离我太近了？”
* **Key ()**:
* Token 1 (`goal`) 说：“我是目标。” -> **匹配度低**（安保不关心目标）。
* Token 5 (`grid`) 说：“我是左下角的墙。” -> **匹配度极高**（因为 `curr` 刚好在左下角）。
* Token 100 (`grid`) 说：“我是右上角的墙。” -> **匹配度低**（离太远，构不成威胁）。


* **Value ()**:
* Head 2 疯狂吸收 Token 5 的信息。
* **结果**：Head 2 输出的新向量里，包含了强烈的“左边有墙”的警告信息。

---

**第三步：情报汇总 (Concatenation)**

现在，4 个专家都完成了各自的分析：

* **Head 1 结果**: [32维向量] -> “建议向目标移动向量 ”
* **Head 2 结果**: [32维向量] -> “警告！左侧距离 0.1m，需反向修正 ”
* **Head 3 结果**: [32维向量] -> “当前所在区域联通性良好 ”
* **Head 4 结果**: [32维向量] -> “关节角度正常 ”

**拼接 (Concat)**：
模型把这 4 个 32 维的向量首尾相接，拼回成一个 **128 维** 的完整向量。

---

**第四步：最终决策 (Final Linear)**

拼起来的向量虽然包含了所有信息，但还很生硬（导航员想往东，安保队长想往西，可能冲突）。

** (Output Linear)** 就像是**总指挥官**。

* 它接收拼好的 128 维向量。
* 它进行一次加权融合（矩阵乘法）。
* **决策**：“虽然导航员想往东（直奔目标），但安保队长说东边有墙。综合考虑，我们**向东南方向**移动。”

---

**总结：在这个过程中，Token 0 发生了什么变化？**

* **处理前 (Token 0)**：它只知道“我现在的关节角度是 ”，它是个**近视眼**，不知道目标在哪，也不知道旁边有墙。
* **处理后 (Token 0')**：经过 Multi-Head Attention 一层层处理，现在的 Token 0 依然代表当前状态，但它**吸星大法**吸取了全局精华：
* 它融合了 `goal` 的指引信息。
* 它融合了 `grid` 中关键障碍物的警示信息。

这就解释了为什么最后你只取 `x[:, 0, :]` (即处理后的 Token 0) 就能预测出正确的下一步——因为此时的 Token 0 已经是一个**“全知全能”**的超级 Token 了。

**对应的数学/代码流程图解**

1. **输入**:  `(Batch, 110, 128)`
2. **分头**:
*  (针对 Head 1~4)
*  (针对 Head 1~4)
*  (针对 Head 1~4)


3. **Attention Map (110 x 110)**:
* 在 Head 1 的 Map 里，Row 0 (Curr) 和 Col 1 (Goal) 也是亮的。
* 在 Head 2 的 Map 里，Row 0 (Curr) 和 Col 5 (Obstacle) 是亮的。


4. **加权**: 
5. **输出**:  `(Batch, 110, 128)` (融合了多方意见的新特征)。

### 路径的生成

采用先进的可以优化的算法进行路径规划，比如说RRT*、BIT*
设置优化目标、增加规划时间、限制采样的步长
同时调用一些后处理的算法

规划中会出现一些问题，例如规划出的路径并不是好的路径，例如“彩虹桥” 路径：虽然起点和终点离得不远，但机械臂却非要“绕一大圈”举高高再下来。

**原因分析**：

- **步长（Range）太大**，生长过程中跨度太大；
- **缺乏捷径优化（Shortcut）**，原始路径包含了很多冗余的弯路，直接做 B 样条平滑（Smooth B-Spline）会把这些弯路变成一个巨大的圆弧；
- **关节构型差异（Elbow Up vs Down）**，起始状态是“肘部朝上”，而 Goal 是“肘部朝下”，机械臂必须挥舞一圈才能切换姿态。

**解决方案**：

- 限制步长
- 添加路径长度优化目标（阈值是否可以自适应）
- 添加捷径优化处理，然后再平滑处理

这里路径长度的优化目标我们选择的是起始结束状态之间的直线距离乘以一个大于1的常数

### 数据读取

因为我们预测是单个点，所以我们可以通过拆分，将一个路径拆分为多个训练样本。例如，我们创建50个场景，每个场景创建10条路径，每条路径有100个点，那么我们就可以创建 50 * 10 * (100 - 1) = 49500 个训练样本。需要注意的是，需要存储历史状态信息，从而投影至网格中。想象一下，每个训练样本要包含几十个点的历史信息。对于很多的场景和路径，这会导致数据量非常大，可能会超出内存限制。因此，我们需要设计一个高效的数据读取机制，按需加载数据，而不是一次性将所有数据加载到内存中。

解决方法就是索引法，我们存储不应该是具体的数据，而是存储数据的索引。每次训练时，根据索引动态加载所需的数据片段。例如，我们分别存储一个路径的列表，存储一个索引列表。索引列表中的每一个元素为{路径列表中索引，当前点在路径中的位置}。这样我们就可以根据索引动态加载数据，避免内存溢出的问题。

## 新网络

旧的方案存在一些问题：
	需要循环的调用网络模型去预测采样点，造成时间复杂度很高
	由于一次出错后，下面预测出的路径并不连续

思考：神经网络输出空间概率分布（Heuristic） + RRT 采样

YOLO方案：
	工作空间体素化，整个 3D 空间进行离散化，网络去评估每一个栅格成为最优路径点的概率。
	高分栅格转化回机械臂姿态

CVAE方案：
	不是去评估所有的点，而是**直接输出（生成）那些高概率的有效状态**。
	x**直接定义为 Aubo i5 机械臂的 6 维关节角度 $(\theta_1, \theta_2, \dots, \theta_6)$**。这意味着，网络生成的直接就是关节空间（Joint Space）的构型。**这完全绕过了运动学逆解（IK）的过程**



网络不再负责“连点成线”（那是旧方案中自回归模型干的脏活累活），网络现在只负责“天女散花”——即撒下一组高质量的候选点，由 RRT 负责将它们串联起来


RRT应该加入一个什么机制，正向的采样，避免回退原地采样呢（是否可以考虑人工势场）
100 个由 CVAE 生成的机械臂关节状态（6 维向量）通过正向运动学（FK）映射回 3D 物理空间，你会发现它们的分布**绝对不是均匀散布的**，而是呈现出一种特定的几何形态：

1. **聚集性（形成“概率管道”）**：这 100 个点会紧密地围绕着一条“理论最优路径”分布，形成一个类似“香肠”或“管道”的高密度点云。
2. **两头密集，中间发散**：通常在起点和终点附近，点会非常密集（因为这些状态是确定的）；而在路径的中段（远离障碍物的开阔区域），点的分布会稍微散开一些，因为在这里机械臂有更多的自由度去挥舞，只要不碰到障碍物，走哪条弧线都可以。
3. **由潜变量 $z$ 驱动**：你从 $\mathcal{N}(0, I)$ 抽取的 $z$ 越接近均值 $0$，生成的点越贴近那条绝对最优的骨干路径；$z$ 的方差越大，生成的点就越向管道的边缘试探。

所以我们应该如何设置概率分布呢？


论文创新点考虑：

- **原始点云（Point Cloud）与 PointNet 特征提取**
	1. **相机数据获取**：将 RealSense 视野内的所有点云数据，作为障碍物点云集合 $P = \{p_1, p_2, \dots, p_n\}$。
	2. **下采样（Downsampling）**：由于原始点云太庞大，使用体素滤波（Voxel Grid Filter）或最远点采样（FPS），将点云数量固定压缩到一个很小的规模（例如 512 个点或 1024 个点）。
	3. **PointNet 编码**：将这 1024 个无序的 3D 坐标 $(x, y, z)$ 直接输入到一个极轻量级的 PointNet 编码器中。PointNet 强大的地方在于它能利用对称函数（如 Max Pooling）完美处理无序点云，并输出一个固定长度的全局特征向量 $f_{obs}$（比如 256 维）。这个向量极其精准地刻画了当前场景的“空间拥挤程度和几何瓶颈”，**完全不在乎物体是什么形状、属于什么类别**。

	- 目前考虑的是$$y = [q_{start}, q_{goal}, f_{obs}]$$
- RRT算法方面
	单纯引入 CVAE 只是应用，而在 OMPL 的采样机制上做数学上的改进才是论文的“硬核”部分。
	- **动态采样权重机制**：不要使用固定的比例（比如 70% 神经采样，30% 均匀采样）。
	- 可以设计一个基于网络生成点空间方差的自适应函数。
	- **算法逻辑**：每次规划前，网络批量生成一批样本集合 $S = \{x_1, x_2, \dots, x_k\}$。计算这批样本在关节空间中的协方差矩阵的迹（Trace），记为样本散度 $\sigma^2$。散度 $\sigma^2$ 越小，说明网络对当前 OBB 环境越自信（生成的点高度聚集在最优路径附近）；散度越大，说明遇到了未知的复杂障碍物分布。
	- **自适应公式**设计：定义神经网络采样的概率 $P_{neural}$ 为：$$P_{neural} = \max \left( P_{min}, 1 - \lambda \cdot \sigma^2 \right)$$其中，$\lambda$ 是缩放系数，$P_{min}$ 是保障算法概率完备性的最小均匀采样率（例如 0.2）。在改进的 RRT 树扩展阶段，生成 $[0, 1]$ 之间的随机数 $r$，如果 $r < P_{neural}$，则从集合 $S$ 中抽取节点；否则在整个关节空间进行均匀随机采样。
	- 自定义加权距离度量 (Custom Distance Metric)
		- **痛点**：在 RRT 树寻找“最近节点（Nearest Node）”时，OMPL 默认计算的是 6 个关节角度的欧氏距离。但实际上，基座关节（Joint 1）动 10 度，和末端腕部关节（Joint 6）动 10 度，机械臂在 3D 空间扫过的体积是完全不一样的！基座动一下很容易撞，腕部动一下可能很安全。
		- **你的设计**：在 OMPL 中继承并重写 Distance 函数。为 Aubo i5 的 6 个关节赋予不同的权重矩阵 $W$。基座关节权重设得极高，末端关节权重设低。$$D(q_1, q_2) = \sqrt{(q_1 - q_2)^T W (q_1 - q_2)}$$
		- **论文写点**：“针对机械臂连杆带来的空间扫描体积差异，提出了一种基于运动学灵敏度的加权距离度量策略，有效降低了树扩展时的碰撞概率……”
	-  局部启发式的 RRT 连线策略 (Heuristic Local Planner)
		- **痛点**：即使网络生成了很好的引导点，RRT 在把起始树往这个引导点上连的时候，默认是走直线的（在关节空间中线性插值）。如果在关节空间走直线，在 3D 物理空间可能是一条诡异的弧线，很容易蹭到桌子边缘。
		- **你的设计**：修改 RRT 的 `steer`（扩展）函数。如果检测到这一步扩展距离障碍物很近，不要走直线插值，而是引入一小段基于梯度的优化（类似斥力场），让这根新生成的树枝自动“绕”开障碍物一点点。
		- **论文写点**：“在神经引导采样的基础上，设计了一种具备局部斥力感知能力的树扩展函数，进一步提升了狭窄通道内的穿透成功率……”
