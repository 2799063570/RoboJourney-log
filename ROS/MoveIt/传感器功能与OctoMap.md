# MoveIt 传感器功能与 OctoMap（ROS1）

## 结论

MoveIt 不直接“控制传感器”；它通过规划场景监视器把机器人状态、碰撞物和传感器生成的环境信息汇总为 Planning Scene。OctoMap 是常用的三维占据表达，可让碰撞检测考虑传感器观测到的障碍物。

## 数据链路

```text
深度相机 / 点云
    → 传感器坐标系与 TF
    → point cloud / depth image updater
    → OctoMap 或碰撞对象
    → Planning Scene
    → 碰撞检测与规划
```

## 配置前提

- 传感器 frame 必须能通过 TF 连接到机器人规划坐标系。
- 点云或深度图的消息类型、topic 名和时间戳必须与配置一致。
- 机器人自身应被正确过滤，否则机械臂本体会被误认为障碍物。
- 规划场景更新频率、地图分辨率和最大范围需要在精度、延迟和内存之间取舍。

## 验证步骤

1. 在 RViz 中同时显示机器人模型、TF 与原始点云。
2. 确认传感器 frame 相对 `base_link` 的位置和方向正确。
3. 启动规划场景监视后，观察 OctoMap/碰撞场景是否随障碍物变化。
4. 放入已知障碍物，验证规划结果会绕开它；再验证移除障碍物后的更新行为。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 场景中没有障碍物 | topic 名、消息类型、updater 是否启动、TF 是否可查。 |
| 机械臂被自己的点云阻挡 | 自身过滤、传感器安装位姿、深度裁剪范围。 |
| 规划明显变慢 | 点云密度、OctoMap 分辨率、更新频率和场景大小。 |
| 障碍物位置漂移 | TF 时间戳、传感器 frame 和固定外参。 |
