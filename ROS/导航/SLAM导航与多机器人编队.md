# SLAM、导航与多机器人编队

## 系统数据流

```text
编码器 + IMU → 里程计 → odom → base_link
激光雷达 → Gmapping → map 与地图
已有地图 + 激光 + odom → AMCL → map → odom
目标点 + 定位 + costmap → move_base → cmd_vel
主机器人位姿/速度 → UDP → 从机器人编队控制 → cmd_vel
局部激光近障检测 → 安全覆盖/减速停车
```

## 坐标系主线

- `map`：全局稳定但定位校正时可能跳变。
- `odom`：局部连续，长期会漂移。
- `base_link`：机器人本体坐标系。
- 常见 TF 链：`map → odom → base_link → laser`。

里程计通常发布 `odom → base_link`；AMCL 发布 `map → odom`。如果两个节点同时发布同一条 TF，会造成跳变或冲突。

## Gmapping 与 AMCL

Gmapping 是基于 Rao-Blackwellized Particle Filter 的二维激光 SLAM，结合粒子表示的机器人轨迹和条件栅格地图，并通过 scan matching 改善位姿提议。重点调试里程计质量、激光参数、更新阈值、粒子数和地图分辨率。

AMCL 在已知地图上用粒子滤波估计位姿。输入包括地图、激光、里程计和初始位姿；定位质量取决于传感器模型、运动模型、粒子数、TF 和时间同步。机器人被“绑架”后需要全局重定位或重新初始化。

## move_base

`move_base` 把全局规划、局部规划、代价地图和恢复行为组织起来：

- 全局规划器在全局 costmap 上生成到目标的路径。
- 局部规划器结合局部障碍物和机器人运动学输出速度。
- 静态层、障碍层和膨胀层共同构成 costmap。
- footprint/robot radius、inflation radius、传感器清除范围和 TF 超时是高频故障点。

出现“有路却规划失败”时，依次检查 TF 与时间戳、地图/传感器数据、机器人 footprint、起终点是否在障碍或膨胀区、全局路径、局部控制和控制器输出。

## RRT-Exploration

前沿是已知自由空间和未知空间的边界。典型流程为：检测前沿候选点、聚类去重、过滤不可达点、按信息增益与行驶代价计算效用、发送目标、到达或失败后重新选择。

覆盖率必须先定义分母。更合理的是“已探索可达区域 / 真实可达区域”，并明确未知栅格、障碍栅格、地图边界和分辨率的处理。

## 主从编队控制

假设主机器人状态为 $(p_l,v_l)$，从机器人期望相对位移为 $d_i$，可构造位置误差：

$$
e_i=p_l+d_i-p_i
$$

简化速度命令可写为：

$$
v_i^{cmd}=v_l+K_pe_i
$$

实际系统还需处理航向角、非完整约束、速度/加速度限幅、通信延迟、丢包和局部避障。安全优先级应高于保持队形：检测到近障或主机消息超时，先减速/停车或进入避障状态，再恢复编队。

## UDP 15 Hz 的解释

15 Hz 只是更新频率，不代表实时性或可靠性。面试时应补充消息包含的时间戳/序号、丢包率、端到端延迟和抖动、超时阈值、陈旧消息处理以及从机控制循环频率。UDP 适合低延迟状态广播，但应用层必须承担序号、校验、超时和安全降级。

## 指标定义

- 地图覆盖率：已探索可达栅格数 / 可达真值栅格数。
- 导航成功率：在规定超时和目标容差内到达的次数 / 总任务数。
- 编队稳态误差：进入稳态窗口后，相对位姿误差的均值、RMSE 或最大值；必须说明采用哪一个。
- 通信频率：建议按有效接收消息的时间戳统计，同时报告丢包率和 P95 间隔。

## 高频追问

### 为什么融合编码器和 IMU？

编码器能提供平移和转动增量，但受打滑与轮径误差影响；IMU 提供角速度/加速度信息，短期响应好但存在偏置。融合能利用互补信息，但不能消除所有系统误差。

### `map` 和 `odom` 为什么不能合并？

控制需要局部连续坐标，全球定位又需要长期不漂移。`odom` 保持连续，`map → odom` 吸收全局校正，两者分工能避免把定位跳变直接传给局部控制。

### 编队与避障冲突怎么办？

把安全设为更高优先级：局部避障或安全状态机限制/覆盖编队速度；障碍解除后再平滑恢复相对队形，避免两套控制器直接相加导致振荡。

### 主机器人失联怎么办？

用序号和时间戳检测陈旧消息；短时可预测或保持有限时长，超过超时阈值后减速停车并上报状态，不能继续追踪旧位姿。
