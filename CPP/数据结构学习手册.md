## 2. 基础概念与复杂度

### 2.1 数据结构究竟是什么

数据结构描述数据的组织方式及操作规则。

| 层次 | 回答的问题 | 例子 |
|---|---|---|
| 逻辑结构 | 元素之间有什么关系？ | 线性序列、树、图 |
| 存储结构 | 数据如何放进内存？ | 连续数组、节点与指针 |
| 抽象数据类型 | 对外提供哪些操作？ | 栈提供入栈、出栈、读栈顶 |
| 算法 | 如何完成某项任务？ | 二分查找、树遍历、最短路径 |

**同一抽象数据类型可以有不同实现。** 栈可以用数组或链表实现；图可以用邻接矩阵或邻接表实现。

#### 面试问答：概念与抽象

**Q2-01：数据结构和算法有什么区别？**

**参考回答：** 数据结构负责组织和保存数据，算法负责利用这些数据完成任务。例如图的邻接表是一种存储方式，BFS 是在图上查找可达顶点或最少边数路径的算法。结构会影响算法成本，所以两者应结合设计。

**Q2-02：栈是逻辑结构还是某一种具体存储方式？**

**参考回答：** 栈首先是规定后进先出操作规则的抽象数据类型，不规定内存必须如何存储。可以用连续数组实现，也可以用链表实现。数组栈通常具有更好的局部性，链式栈可以逐节点增长，但有分配和指针成本。

### 2.2 时间复杂度

令 `n` 表示输入规模。大 O 表示增长的渐近上界，不是精确耗时；描述具体操作时，还要说明分析的是最坏、平均还是摊还成本。

| 复杂度 | 典型操作 | 输入变大后的直觉 |
|---|---|---|
| O(1) | 数组按下标访问 | 操作次数基本不随 n 增长 |
| O(log n) | 有序数组二分查找 | 每次排除约一半候选 |
| O(n) | 遍历全部元素 | 数据翻倍，工作量约翻倍 |
| O(n log n) | 归并排序 | n 个元素参与约 log n 层处理 |
| O(n²) | 枚举全部元素对 | 数据翻倍，工作量约变为四倍 |
| O(2ⁿ) | 枚举所有子集 | 规模稍增，成本就迅速上升 |

常见推导：

```cpp
for (int i = 0; i < n; ++i) { /* 常数时间工作 */ } // O(n)

for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j) { /* 常数时间工作 */ } // O(n²)

// n > 0，每一步把规模减半
for (int k = n; k > 1; k /= 2) { /* 常数时间工作 */ } // O(log n)
```

嵌套循环不一定是 O(n²)：若两个指针都只向前移动，总移动次数仍可能是 O(n)。调用函数的成本也必须计入，不能只数外层循环。

#### 面试问答：复杂度推导

**Q2-03：O、Ω、Θ 有什么区别？**

**参考回答：** O 表示渐近上界，Ω 表示渐近下界，Θ 表示上下界同阶。例如遍历 n 个元素并做常数工作，运行时间为 Θ(n)，当然也满足 O(n²)，但 O(n²) 不是紧确的描述。面试中通常会尽量给出最有信息量的界。

**Q2-04：两个嵌套循环为什么有时仍然是 O(n)？**

**参考回答：** 应计算总操作次数，而不是机械地乘循环层数。如果内层指针不回退，它在全部外层迭代中最多前进 n 次，总成本仍为 O(n)。滑动窗口与双指针经常具备这种性质；若内层每次都从头扫描，则可能变为 O(n²)。

**Q2-05：为什么二分查找是 O(log n)？**

**参考回答：** 每轮把候选区间缩小到原来的约一半，k 轮后剩余规模约为 n/2ᵏ。令它降到常数，得到 k 约为 log₂n，所以比较次数为 O(log n)。不同常数底的对数只相差常数倍，复杂度通常省略底数。

### 2.3 平均、最坏与摊还

- **最坏复杂度**：一次操作在最不利情况下的成本。
- **平均复杂度**：在指定输入分布或模型下的期望成本。
- **摊还复杂度**：把一串操作的总成本分摊到每次操作，不依赖输入随机。

例如 `vector::push_back` 通常只写入一个元素，但扩容时需要搬移已有元素。一次追加最坏 O(n)，连续追加的摊还成本是 O(1)。

哈希表平均 O(1) 查询依赖哈希分布等条件；它不能推出最坏查询也是 O(1)。

#### 面试问答：摊还与最坏成本

**Q2-06：请推导动态数组追加的摊还 O(1)。**

**参考回答：** 以容量按 2 倍增长的动态数组为例，追加 n 个元素时，扩容搬移次数约为 1 + 2 + 4 + …，总和小于某个常数倍的 n。加上 n 次正常写入，总成本 O(n)，分摊到每次是 O(1)。关键是几何增长；标准库不规定 `vector` 必须采用某个具体增长倍数。

**追问：每次追加前都调用 `reserve(size() + 1)` 呢？**

**回答：** 这可能破坏正常的增长策略，导致频繁重新分配，累计搬移成本可能达到 O(n²)。更合理的是有规模估计时一次预留，或让容器自行增长。

**Q2-07：平均复杂度和摊还复杂度可以互换吗？**

**参考回答：** 不可以。平均分析需要指定输入或随机模型，摊还分析考察一段操作序列的总成本。哈希查找的平均 O(1) 与动态数组追加的摊还 O(1) 来源不同，也都不等于单次最坏 O(1)。

### 2.4 空间复杂度

区分**输入本身的存储空间**与**算法额外使用的辅助空间**。

- 扫描数组求最大值：辅助空间 O(1)。
- 复制数组后处理：辅助空间 O(n)。
- 递归遍历高度为 h 的树：递归栈空间 O(h)。
- 返回 n 个结果：输出空间 O(n)，需说明是否计入分析。

> 复杂度相同，实际性能也可能不同。连续内存通常更利于缓存；节点结构需要额外指针和内存分配。

#### 面试问答：空间与实际性能

**Q2-08：递归没有显式创建数组，为什么还需要算空间？**

**参考回答：** 每层调用都需要保存参数、局部状态和返回信息，因此占用调用栈。树遍历的最大同时活跃调用层数与树高有关，辅助空间为 O(h)。退化树的 h 可以为 n，存在栈耗尽风险；平衡树通常为 O(log n)。

**Q2-09：O(n) 的方案一定比 O(n log n) 快吗？**

**参考回答：** 不一定。渐近复杂度描述规模增长趋势，实际耗时还受常数、缓存命中、分配、键比较成本和数据分布影响。对较小数据，复杂度较高但常数低的方案可能更快；选型应先满足正确性与规模要求，再用代表性负载测量。

## 3. 数组与动态数组

### 3.1 原理

数组把同类型元素放在连续内存中。第 i 个元素的位置可以由首地址与元素大小计算，所以按下标访问是 O(1)。

```text
下标     0    1    2    3
元素   [10] [20] [30] [40]

在下标 1 插入 99：后面的元素向右移动
       [10] [99] [20] [30] [40]
```

| 操作 | 复杂度 | 原因 |
|---|---|---|
| 按下标访问 | O(1) | 直接计算位置 |
| 无序数组按值查找 | O(n) | 可能检查全部元素 |
| 有序数组二分查找 | O(log n) | 每轮缩小搜索区间 |
| 中间插入或删除 | O(n) | 后续元素需要移动 |
| 动态数组末尾追加 | 摊还 O(1)，单次最坏 O(n) | 扩容时搬移元素 |

#### 面试问答：数组存储

**Q3-01：数组随机访问为什么快？中间插入为什么慢？**

**参考回答：** 连续内存允许用首地址加 `i * sizeof(T)` 定位第 i 个元素，按下标访问 O(1)。为了维持序列顺序，中间插入需要将后面的元素后移，因此最坏 O(n)。若元素不要求保序，删除时可以用末尾元素覆盖待删位置，再删除末尾，实现 O(1) 删除，但会改变顺序。

**Q3-02：二维数组的行优先存储有什么影响？**

**参考回答：** 真正连续、按行存储的二维数组，按行遍历通常更利于缓存，因为相邻访问位置靠近。按列遍历可能产生较大地址跨步。`vector<vector<T>>` 的每一行分别管理内存，不能据此认为整个矩阵连续；需要整体连续时可以使用扁平数组并用 `row * cols + col` 索引。

### 3.2 C++ 对应容器

- `std::array<T, N>`：编译期确定长度，适合固定维度数据。
- `std::vector<T>`：运行时可改变长度，适合大多数序列任务。
- `std::deque<T>`：支持两端高效操作及 O(1) 下标访问，整体存储不保证连续。

```cpp
#include <vector>

std::vector<int> values{10, 20, 30};
values.reserve(100);                   // 预留容量，size 仍是 3
values.push_back(40);                  // size 变成 4
values.insert(values.begin() + 1, 99); // 10, 99, 20, 30, 40
values.erase(values.begin() + 2);      // 10, 99, 30, 40
int x = values.at(0);                  // 带边界检查的访问
```

**`size` 是元素数量，`capacity` 是已有存储可容纳的元素数量。** `reserve` 不创建元素，`resize` 会改变元素数量。

#### 面试问答：vector 与 deque

**Q3-03：`reserve` 和 `resize` 的区别是什么？**

**参考回答：** `reserve` 预留存储，元素数量不变；`resize` 改变实际元素数，扩大时构造新元素，缩小时销毁多余元素。例如空 `vector<int>` 执行 `reserve(10)` 后不能访问 `v[0]`；执行 `resize(10)` 后才有 10 个元素。容量并不等于已构造元素数。

**Q3-04：`vector` 的迭代器什么时候失效？**

**参考回答：** 发生重新分配时，指向其元素的全部迭代器、指针和引用失效。未重新分配时，中间插入使插入位置及之后的迭代器和引用失效；删除使被删位置及之后的迭代器和引用失效。即使追加不扩容，原来的尾后迭代器也会失效，不能跨修改保存旧 `end()` 来控制循环。

**Q3-05：`vector`、`list`、`deque` 如何选择？**

**参考回答：** 默认序列容器通常先考虑 `vector`，因为连续存储、随机访问与遍历性能好。频繁两端增删可以考虑 `deque`；持有稳定节点位置、频繁拼接或在已知位置增删时可以考虑 `list`。不能只看到 `list` 插入 O(1)，还要计入查找位置、分配和缓存成本。

**追问：为什么 deque 可以 O(1) 随机访问却不保证整体连续？**

**回答：** 常见实现用多个存储块与索引结构，通过下标计算所在块和块内偏移，定位仍可为 O(1)。跨块元素未必连续，因此不能把所有元素当作一段普通数组传给要求连续内存的接口；具体分块布局属于实现细节。

### 3.3 二分查找：练习边界管理

前提：数组按非递减顺序排列。下面寻找第一个大于或等于目标值的位置，返回值可以等于数组长度。

```cpp
#include <vector>
#include <cstddef>

std::size_t lower_bound_index(const std::vector<int>& a, int target) {
    std::size_t left = 0, right = a.size(); // 搜索边界使用 [left, right)
    while (left < right) {
        std::size_t mid = left + (right - left) / 2;
        if (a[mid] < target)
            left = mid + 1;
        else
            right = mid;
    }
    return left;
}
```

检查目标是否存在：`p < a.size() && a[p] == target`。空数组、重复元素和不存在的值均可处理。

**常见错误：** 越界；把 `reserve` 当成 `resize`；扩容后继续使用原有指针、引用或迭代器。插入与删除也可能使部分迭代器失效。

**练习：** 原地删除有序数组中的重复值；实现左右边界查找；解释为什么数组随机访问比链表方便。

#### 面试问答：二分边界

**Q3-06：二分查找如何证明不会漏掉答案？**

**参考回答：** 先确定目标是第一个 `>= target` 的位置，再维护不变量：`left` 左侧都小于目标，`right` 起及其右侧都不小于目标，边界位置可等于 n。当 `a[mid] < target` 时排除到 mid；否则答案不可能在 mid 右侧，令 right = mid。区间不断缩小，最终 left == right 就是答案边界。

**Q3-07：怎样找到重复元素的左右边界？**

**参考回答：** 左边界是第一个 `>= target` 的位置，右侧的排他边界是第一个 `> target` 的位置。如果左边界没有命中目标，目标不存在；否则重复区间为 `[lower, upper)`，个数为 upper - lower。不要通过 `target + 1` 寻找右边界，否则整数最大值可能溢出。

**Q3-08：链表能做二分查找吗？**

**参考回答：** 可以按有序性减少比较次数，但它不能 O(1) 取得中点，所以通常无法获得数组二分那样的 O(log n) 总运行时间。标准泛型二分算法在非随机访问迭代器上可能需要线性次数的迭代器移动，应区分比较次数与实际访问成本。

## 4. 链表

### 4.1 原理

链表的节点分散存储，通过指针连接。

```text
单链表：head → [10 | next] → [20 | next] → [30 | null]
双链表：null ← [10] ⇄ [20] ⇄ [30] → null
```

| 操作 | 单链表复杂度 | 条件 |
|---|---|---|
| 按位置或按值查找 | O(n) | 从头顺序遍历 |
| 头部插入、删除 | O(1) | 已有头指针 |
| 在已知前驱后插入、删除后继 | O(1) | 无需额外查找 |
| 尾部插入 | O(1) 或 O(n) | 是否维护尾指针 |
| 删除尾节点 | O(n) | 需要寻找前驱；仅有尾指针不够 |

双链表已知待删节点时，修改两侧连接即可 O(1) 删除。

**“链表插入删除快”有前提：操作位置已知。** 如果先查找第 k 个节点，总成本仍可能是 O(n)。

#### 面试问答：链表操作条件

**Q4-01：单链表和双链表的区别是什么？**

**参考回答：** 单链表每个节点保存后继，双链表还保存前驱。双链表能向两个方向移动，已知节点时一般可 O(1) 删除；单链表通常需要前驱才能修改连接。双链表付出的成本是额外指针、更多连接维护与更大的节点空间。

**Q4-02：有尾指针的单链表，删除尾节点是否 O(1)？**

**参考回答：** 不是。尾指针让尾部插入容易，但删除尾节点仍需要找到它的前驱，并更新尾指针，单链表没有反向连接，通常要从头遍历 O(n)。双链表若维护尾指针，则可以通过前驱 O(1) 删除尾节点。

**Q4-03：为什么链表题常使用哑节点？**

**参考回答：** 哑节点放在真实头节点之前，使删除头节点、头部插入与普通位置操作采用统一的前驱修改逻辑，减少分支。哑节点不是有效数据节点，返回真实头时应返回它的 next；它的生命周期也不能被错误地作为返回结果暴露。

### 4.2 反转单链表

```cpp
struct ListNode {
    int value;
    ListNode* next;
};

ListNode* reverse_list(ListNode* head) {
    ListNode* prev = nullptr;
    ListNode* cur = head;
    while (cur != nullptr) {
        ListNode* next = cur->next; // 改指针前保存后继
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}
```

循环不变量：`prev` 指向已经反转的前缀，`cur` 指向尚未处理的后缀。时间 O(n)，辅助空间 O(1)。假设输入为无环链表。

示例只处理连接关系，不负责分配和释放节点。学习原始指针时必须另外明确所有权；工程中优先考虑标准容器或合理的 RAII 管理。

#### 面试问答：反转与指针安全

**Q4-04：反转链表为什么需要先保存 next？**

**参考回答：** 修改 `cur->next` 后，原来指向未处理后缀的连接会丢失。先保存 next，再反转当前连接，最后前移 prev 和 cur，才能保留所有节点。每个节点只访问一次，时间 O(n)，使用固定数量指针，辅助空间 O(1)。

**Q4-05：递归反转链表与迭代反转有什么区别？**

**参考回答：** 两者时间都为 O(n)。迭代版使用几个指针，辅助空间 O(1)；递归版需要 O(n) 调用栈，长链表容易耗尽栈。递归完成子链反转后，还要断开原正向连接，否则可能形成环。

### 4.3 选择与陷阱

- `std::forward_list` 对应单链表，常用 `insert_after`、`erase_after`。
- `std::list` 对应双链表，适合已知迭代器下的插入、删除和节点转移。
- 链表不支持 O(1) 随机访问；节点有额外空间及分配成本。
- 在许多遍历密集的任务中，`vector` 即使需要移动元素，也可能更快，应按实际负载测量。

**练习：** 快慢指针找中点；检测环；合并两个有序链表。检测环时，解释为什么快指针每轮需要检查两个后继位置。

#### 面试问答：链表经典题

**Q4-06：快慢指针为什么能检测环？怎样找到入口？**

**参考回答：** 慢指针每次走一步，快指针走两步。有环时，两者在环内的相对距离每轮变化一步，最终会相遇；无环时快指针会到空位置。相遇后，把一个指针放回头节点，另一个留在相遇点，两者每次各走一步，再次相遇的位置就是环入口。时间 O(n)，辅助空间 O(1)。

**追问：入口结论如何推导？**

**回答：** 设头到入口距离为 a、入口到相遇点沿环距离为 b、环长为 c。相遇时慢指针路程为 a + b + k·c，快慢路程差是整圈，得到 a + b 是 c 的倍数，因此从相遇点再走 a 步会到入口，与从头走 a 步同时到达。

**Q4-07：只给待删除节点指针，能 O(1) 删除单链表节点吗？**

**参考回答：** 如果节点不是尾节点，且允许改变其存储内容，可以把后继的值复制过来，再删除后继，达到逻辑上的删除效果。但这改变了节点身份，对存在外部节点引用或不可复制数据的场景不适用；尾节点也无法使用该技巧。一般删除仍需要前驱信息。

**Q4-08：如何找两个无环单链表的相交节点？**

**参考回答：** 使用两个指针分别从两个头出发，到链尾后切换到另一条链的头。两者最多走过各自链长之和，消除前缀长度差，最终在首个公共节点或空位置相遇。比较的是节点地址，不是数值；有环链表需要另外分类讨论。

## 5. 栈

栈遵循**后进先出（LIFO）**。只能通过栈顶进出，基本入栈、出栈、读栈顶通常为 O(1)；动态数组实现的入栈为摊还 O(1)。

```text
push(1), push(2), push(3)
栈顶 → 3
       2
       1
pop() 先移除 3
```

用途：括号匹配、表达式求值、撤销操作、显式模拟递归、深度优先搜索。

#### 面试问答：栈与调用栈

**Q5-01：为什么递归通常可以改写成栈？**

**参考回答：** 函数调用本来就需要用调用栈保存尚未完成的状态。显式栈把这些状态转成程序自己管理的记录，如当前节点、处理阶段和局部变量。简单前序遍历只需保存节点；复杂递归可能需要保存返回后继续执行的位置，不能认为把参数压栈就等价于所有递归。

**Q5-02：如何实现支持 O(1) 获取最小值的栈？**

**参考回答：** 使用普通数据栈和辅助最小值栈。每次入栈时，辅助栈记录截至当前深度的最小值；出栈时两栈同步弹出。取辅助栈顶即可得到最小值，操作为 O(1)，空间 O(n)。也可只在出现不大于当前最小值时入辅助栈，但必须正确保存重复最小值的次数。

### 5.1 括号匹配

```cpp
#include <stack>
#include <string>

bool valid_brackets(const std::string& s) {
    std::stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (st.empty()) return false;
            char expected = c == ')' ? '(' : (c == ']' ? '[' : '{');
            if (st.top() != expected) return false;
            st.pop();
        }
        // 本示例忽略非括号字符
    }
    return st.empty();
}
```

时间 O(n)，辅助空间最坏 O(n)。`"([{}])"` 合法，`"([)]"`、`"("`、`")"` 不合法。

**常见错误：** 在空栈上调用 `top()` 或 `pop()`；以为 C++ 的 `pop()` 会返回被移除的值。

#### 面试问答：括号与表达式

**Q5-03：为什么括号匹配用栈，而不是只维护计数？**

**参考回答：** 多种括号不仅要求数量相等，还要求嵌套顺序正确。栈保存尚未闭合的左括号，右括号只能匹配最近一个未闭合的左括号。单一括号可以用计数并检查任意前缀计数非负，但多个独立计数不能识别 `([)]` 这样的交叉匹配。

**Q5-04：栈如何用于表达式求值？**

**参考回答：** 后缀表达式可以用一个操作数栈：遇到数就入栈，遇到二元运算符先弹右操作数，再弹左操作数，计算后入栈。中缀表达式还需维护运算符优先级、结合性和括号，常使用运算符栈与操作数栈。还要处理一元负号、非法表达式、除零和数值溢出。

### 5.2 单调栈入门

问题：对每个元素找到右侧第一个更大的元素。

维护一个存储下标的栈，使栈中对应值从底到顶非递增。遇到更大的新值时，它就是被弹出元素的答案。每个下标只进栈、出栈一次，总时间 O(n)。

例：`[2, 1, 3]` 的答案值为 `[3, 3, 不存在]`。相等元素如何处理，取决于题目要求“严格更大”还是“大于等于”。

#### 关键操作：单调栈手动模拟

输入 `[2, 1, 3]`，栈存下标：

| 当前元素 | 操作 | 当前栈（对应值） | 已确定答案 |
|---|---|---|---|
| 2 | 下标 0 入栈 | [2] | 无 |
| 1 | 不能解决 2，下标 1 入栈 | [2, 1] | 无 |
| 3 | 弹出 1，再弹出 2；最后入栈 | [3] | 1 和 2 的右侧第一个更大值都是 3 |

没有出栈的元素在右侧没有更大的值。使用下标便于返回位置、计算距离并处理重复值。

#### 面试问答：单调栈

**Q5-05：单调栈有内层 while，为什么仍是 O(n)？**

**参考回答：** 每个元素只入栈一次，且最多出栈一次。虽然某次遍历可能连续弹出多个元素，但全部 while 执行的出栈总次数不超过 n，整体时间 O(n)。这属于对整段操作计数，不能把每轮的最坏出栈次数直接相乘。

**Q5-06：单调栈和单调队列有什么区别？**

**参考回答：** 两者都通过删除被新元素支配的候选维护单调性。单调栈从一端操作，适合求最近更大或更小的位置；单调队列还会从队首删除过期元素，适合维护滑动窗口的极值。窗口问题需要知道候选是否离开窗口，因此通常保存下标。

**练习：** 用两个栈实现队列；实现最小栈；完成右侧第一个更大元素。

## 6. 队列、双端队列与环形缓冲区

### 6.1 队列

队列遵循**先进先出（FIFO）**：尾部入队，头部出队。

```cpp
#include <queue>

std::queue<int> q;
q.push(10);
q.push(20);
if (!q.empty()) {
    int first = q.front(); // 10
    q.pop();              // 移除 10
}
```

适合任务调度、消息排队、层序遍历和 BFS。默认底层容器为 `deque`，基本两端操作 O(1)。

#### 面试问答：FIFO 与双栈队列

**Q6-01：为什么 BFS 用队列，而 DFS 用栈？**

**参考回答：** 队列先处理较早发现的节点，使 BFS 先完成当前距离层，再处理下一层。栈则优先处理最近发现的节点，使 DFS 沿新路径深入。换容器会改变探索顺序，进而影响最短路径等性质，不能随意互换。

**Q6-02：怎样用两个栈实现队列？复杂度是多少？**

**参考回答：** 一个输入栈接收入队元素，一个输出栈负责出队。只有输出栈为空时，才把输入栈全部倒入输出栈，反转顺序后最早入队的元素位于栈顶。一次倒转最坏 O(n)，但每个元素只转移一次，连续操作的摊还成本 O(1)，空间 O(n)。

**追问：每次出队都倒转一次可以吗？**

**回答：** 输出栈非空时不应把新元素混入，否则容易破坏 FIFO，也增加不必要搬移。输入栈与输出栈分别表示较新和较旧的两批元素，输出栈必须优先消费。

### 6.2 双端队列

`std::deque` 可以在两端插入、删除。与优先队列不同，它不会自动按优先级选择元素。

**单调队列**常用于滑动窗口最大值：存储候选元素的下标，删除窗口外元素，并从尾部移除不可能成为最大值的候选。每个元素最多进出一次，总时间 O(n)。

#### 面试问答：滑动窗口

**Q6-03：滑动窗口最大值为什么可以删除队尾较小元素？**

**参考回答：** 新元素既不小于旧候选，又更晚离开窗口，所以只要两者同时有效，旧候选不可能优于新元素；旧候选失效时，新元素仍可能有效。因此可以删除被支配的旧候选。队首保存当前窗口最大值的下标，时间 O(n)，辅助空间 O(k)，k 为窗口长度。

**Q6-04：为什么只存数值不存下标容易出错？**

**参考回答：** 仅凭值难以判断某个候选是否已经滑出窗口，重复值还可能无法区分。保存下标可以直接通过 `index <= i - k` 删除过期元素。完整实现还需要先处理 k <= 0、k > n 等输入，并避免无符号下标减法下溢。

### 6.3 固定容量环形队列

用长度为 C 的数组、头位置 `head` 和元素数 `count` 表示队列，要求 C > 0。

```text
空：count == 0
满：count == C
入队位置：(head + count) % C
入队：写入后 count++
出队：head = (head + 1) % C，count--
```

数组被循环使用，无需搬移所有元素，也不需要每次操作动态分配内存。

机器人轨迹缓冲区可以采用这种结构，但必须定义满队列策略：拒绝新数据、覆盖最旧数据，或在允许等待的上下文中阻塞。共享缓冲区还需要单独设计并发同步。

**常见错误：** 用 `head == tail` 同时表示满和空，却没有额外状态；容量为零时做取模；读取已过期轨迹点。

**练习：** 实现容量为 4 的环形队列；连续入队、出队超过 8 次，验证回绕与 FIFO 顺序。

#### 面试问答：环形队列与并发

**Q6-05：环形队列如何区分空和满？**

**参考回答：** 常见方案有三种：维护元素数 count；额外记录满标志；预留一个槽位使空为 head == tail、满为下一写入位置等于 head。预留方案的有效容量比数组长度少 1。应明确所用约定，不能在同一实现中混用不同判断方法。

**Q6-06：为什么控制系统中常考虑固定容量队列？**

**参考回答：** 固定容量可提前分配内存，避免运行期扩容带来的复制、分配和延迟波动，也限制积压的数据量。但还必须定义队列满时的策略，并验证同步、任务调度和最坏耗时；固定容量只是其中一项设计措施。

**Q6-07：环形队列能天然支持多线程吗？**

**参考回答：** 不能。head、tail、count 以及元素读写都可能产生数据竞争。最直接的方案是在共享操作上加锁；单生产者单消费者可以按严格协议使用原子索引，但需要保证先写数据再发布写入位置、读方正确观察发布结果。多生产者多消费者要处理额外竞争，不能简单把两个索引换成原子变量就宣称正确。

## 7. 哈希表

### 7.1 从键到桶

哈希表先对键计算哈希值，再映射到桶的位置。

```text
键 "joint_1" → hash(key) → 桶索引 → 对应记录
```

不同键可能进入同一个桶，称为**哈希冲突**。常见处理方法：

- 链地址法：桶关联多个记录，查找时进一步比较键。
- 开放寻址法：发生冲突后，按探测规则寻找其他槽位。

负载因子通常表示元素数与桶数之比。负载升高可能增加冲突成本；扩容后往往需要重新组织元素。

#### 面试问答：哈希机制

**Q7-01：什么是哈希冲突？好哈希函数能完全消除吗？**

**参考回答：** 不同键映射到同一个桶就是冲突。有限桶空间面对更大的键空间，冲突无法普遍避免；好的哈希函数尽量分散实际输入，降低聚集。查找命中桶后仍需比较键是否相等，哈希相同不代表键相同。

**Q7-02：链地址法和开放寻址法有什么取舍？**

**参考回答：** 链地址法通过桶关联记录处理冲突，删除相对直接，但可能有节点分配和指针访问成本。开放寻址将元素放在槽位数组中，通常局部性较好，但高负载下探测链变长，删除还要维持查找路径。不同实现应根据内存、负载与稳定引用需求选择。

**追问：开放寻址删除时为什么经常需要墓碑？**

**回答：** 若把中间槽位直接标记为“从未使用”，查询可能在这里提前停止，漏掉探测链后面的键。墓碑表示查询应继续，但插入可以考虑复用。墓碑积累可能降低性能，某些实现通过重新整理或移动元素处理。

**Q7-03：负载因子为什么影响性能？**

**参考回答：** 装入元素越多，平均桶链或探测路径通常越长。控制负载因子并增加桶数量有助于降低冲突，但会增加内存。开放寻址通常在高负载下更敏感，不能把不同冲突处理方案的性能公式直接通用。

### 7.2 C++ 使用

```cpp
#include <unordered_map>
#include <string>
#include <vector>

std::unordered_map<std::string, int> freq;
for (const auto& word : std::vector<std::string>{"a", "b", "a"}) {
    ++freq[word]; // 缺失时创建计数 0，再递增
}

auto it = freq.find("c"); // 查询不会创建新键
if (it != freq.end()) {
    int count = it->second;
}
```

`unordered_map` 存储键值对，`unordered_set` 存储不重复的键。在通常的良好哈希条件下，查询、插入、删除平均 O(1)，单次最坏可达 O(n)。字符串哈希还需要计入键长度成本。

#### 面试问答：unordered_map 使用细节

**Q7-04：为什么查询时一般用 find，而不是 operator[]？**

**参考回答：** `operator[]` 在键不存在时插入默认构造的值，因此会改变容器，甚至触发扩容。`find` 只查询，返回迭代器或 end。计数时 `++freq[key]` 很合适，但判断某配置是否存在时，隐式插入可能掩盖缺失数据。

**Q7-05：rehash 对迭代器、引用和指针有什么影响？**

**参考回答：** 对标准 `unordered_map`，rehash 会使迭代器失效，但指向现有元素的引用和指针仍有效。删除元素会使指向该元素的引用、指针和迭代器失效。不要把哈希表的规则与 `vector` 重新分配的规则混淆，也不要将这些保证套到所有第三方哈希容器上。

**Q7-06：自定义键的相等比较和哈希必须满足什么条件？**

**参考回答：** 如果两个键按相等比较视为相等，它们必须得到相同哈希值；反过来，相同哈希不要求相等。键在容器中存储期间，其用于哈希与比较的语义应保持稳定，否则查找可能找不到它。比如忽略大小写比较时，哈希也要采用一致的大小写处理。

**补充：reserve 与 rehash。** `unordered_map::reserve(n)` 根据负载因子为大约 n 个元素准备桶数量；`rehash(b)` 按桶数要求重新组织。这里的 reserve 与 `vector` 的连续存储容量不是同一个概念，预留桶也不等于预先构造 n 个键值记录。

### 7.3 何时不适合

- 需要有序遍历或范围查询：考虑 `std::map`、`std::set` 或排序后的数组。
- 需要可预测的最坏查询界限：不能只依据哈希表的平均复杂度。
- 数据量很小：线性扫描可能更简单，并有较低常数成本。

**常见错误：** 把 `operator[]` 当成只读查询；依赖无序容器的遍历顺序；自定义相等关系与哈希函数不一致。

**练习：** 统计词频；判断重复元素；用哈希表求两数之和，并说明为什么必须先查询再记录当前元素。

#### 面试问答：哈希应用与选型

**Q7-07：如何用哈希表做两数之和？**

**参考回答：** 从左到右扫描当前位置 i，先查询是否已有值等于 target - a[i]；有就返回对应下标与 i，否则记录当前值及下标。先查再存可避免同一个元素与自己配对，也能处理两个相同数值。平均时间 O(n)，空间 O(n)，计算差值时要考虑整数溢出。

**Q7-08：map 和 unordered_map 哪个更好？**

**参考回答：** 取决于需求。`map` 提供有序遍历、范围查找以及 O(log n) 的按键操作界限；`unordered_map` 不维护顺序，通常能获得平均 O(1) 按键访问。还应考虑键的长度、比较和哈希成本、内存开销及恶劣输入，不能只根据复杂度符号判断。

## 8. 树与二叉树

### 8.1 术语

树是一种层次结构。每个非根节点有一个父节点，节点可以有多个子节点；二叉树每个节点最多两个子节点。

```text
        A            深度 0
       / \
      B   C          深度 1
     / \
    D   E            深度 2
```

- 根：A；叶节点：C、D、E。
- 本手册按**边数**计算深度与高度：根深度为 0，上图高度为 2，空树高度约定为 -1。
- 节点的度：子节点数量。
- 子树：某节点及其全部后代构成的树。

注意术语区别：

| 名称 | 性质 |
|---|---|
| 普通二叉树 | 每个节点最多两个子节点 |
| 满二叉树（此处指 perfect binary tree） | 每层都填满，叶节点都处于同一层 |
| 完全二叉树 | 除最后一层外都填满，最后一层从左向右连续排列 |
| 严格二叉树（full/proper binary tree） | 每个节点有 0 或 2 个子节点 |
| 平衡二叉树 | 高度受到约束；不同平衡方案约束不同 |

中文与英文教材对“满二叉树”的使用可能不同，读资料时应核对具体定义。

#### 面试问答：树的性质

**Q8-01：为什么 n 个节点的树有 n - 1 条边？**

**参考回答：** 在根树中，每个非根节点恰好有一条连接父节点的边，根没有父边，所以边数为 n - 1。这里指连通且无环的树；一般图不满足此结论，森林则要按连通分量数计算。

**Q8-02：完全二叉树为什么适合数组存储？**

**参考回答：** 完全二叉树的节点按层序从左向右连续占位，没有大量空洞。数组下标可以直接推导父子位置，无需保存指针，因此二叉堆常用这种表示。任意稀疏二叉树若强行采用相同下标规则，可能浪费大量空间。

**Q8-03：树的高度和深度有什么区别？**

**参考回答：** 节点深度衡量从根到它的距离，节点高度衡量从它到最远后代叶节点的距离。树高就是根的高度。本手册按边数计算，单节点树高度为 0；有些教材按节点数计算为 1，所以先说明约定，避免公式差一。

**追问：高度为 h 的满二叉树有多少节点？**

**回答：** 按边数计高度，各层节点数为 1、2、4，直到 2ʰ，总节点数为 2^(h+1) - 1，叶节点数为 2ʰ。这个精确公式不适用于任意普通二叉树。

### 8.2 四种遍历

以上图为例：

| 遍历 | 顺序规则 | 结果 |
|---|---|---|
| 前序 | 根 → 左 → 右 | A B D E C |
| 中序 | 左 → 根 → 右 | D B E A C |
| 后序 | 左 → 右 → 根 | D E B C A |
| 层序 | 从上到下，每层从左到右 | A B C D E |

```cpp
#include <vector>

struct TreeNode {
    int value;
    TreeNode* left;
    TreeNode* right;
};

void inorder(const TreeNode* root, std::vector<int>& out) {
    if (root == nullptr) return;
    inorder(root->left, out);
    out.push_back(root->value);
    inorder(root->right, out);
}
```

遍历时间 O(n)，递归栈空间 O(h)，另有 O(n) 输出空间。高度 h 最坏为 O(n)；很深的树应考虑显式栈，避免递归栈耗尽。

**练习：** 求树高；统计叶节点；实现层序遍历；用显式栈完成前序遍历。

#### 面试问答：遍历与构造

**Q8-04：前序、中序、后序分别适合做什么？**

**参考回答：** 前序先处理根，适合从上向下传递状态；中序在 BST 上得到有序键序列；后序先处理子树，适合计算树高、子树统计或汇总结果。遍历次序应由依赖关系决定，不能仅凭记忆模板选择。

**Q8-05：怎么用栈实现中序遍历？**

**参考回答：** 从当前节点不断沿左孩子入栈，直到为空；弹出栈顶并访问，再转向它的右孩子，重复直到当前节点为空且栈空。栈保存尚未访问的祖先，每个节点入栈出栈一次，时间 O(n)，辅助空间 O(h)。

**Q8-06：知道前序和中序能唯一恢复二叉树吗？**

**参考回答：** 在节点标识唯一且序列有效的前提下可以。前序第一个元素是根，在中序中定位根后确定左右子树范围，再递归构造。若每次线性查找根位置，最坏 O(n²)；用哈希索引可获得平均 O(n) 构造时间，但仍需检查序列是否匹配。存在重复值时通常不能仅靠值唯一确定。

**Q8-07：前序和后序为什么一般不能唯一恢复？**

**参考回答：** 当节点只有一个孩子时，前序与后序无法判断它是左孩子还是右孩子。例如根 A 和一个孩子 B，两种结构的前序都是 A B，后序都是 B A。若额外限制每个内部节点都有两个孩子且标识唯一，结论才可能改变。

**Q8-08：怎样序列化二叉树后确保能恢复结构？**

**参考回答：** 例如采用前序遍历，同时记录空孩子标记。只有数值而没有结构信息，可能无法区分不同形状；空标记补齐左右孩子是否存在的信息。反序列化时按同样规则读取，检查输入是否完整及是否有额外无效内容，时间和数据量都为 O(n)。

## 9. 二叉搜索树与平衡搜索树

### 9.1 搜索树的约束

采用不允许重复键的版本：对每个节点，左子树所有键都更小，右子树所有键都更大。

```text
        8
       / \
      3   10
     / \    \
    1   6    14
```

查找 6：与 8 比较后向左，与 3 比较后向右，命中 6。

查询、插入、删除都与树高 h 有关，为 O(h)。平衡时 h = O(log n)，退化成链时 h = O(n)。**普通 BST 不自动保证 O(log n)。**

#### 面试问答：BST 不变量

**Q9-01：为什么 BST 查找只需要进入一棵子树？**

**参考回答：** BST 对整个左右子树作大小约束。目标小于当前键时，它不可能在右子树；大于当前键时，不可能在左子树，因此可以每轮排除一侧。操作次数与路径长度有关，为 O(h)，是否达到 O(log n) 取决于树高。

**Q9-02：如何正确判断一棵树是不是 BST？**

**参考回答：** 可以递归传递允许的上下界，进入左子树收紧上界，进入右子树收紧下界，检查每个节点都在合法范围。也可以检查中序遍历是否严格递增。若允许重复键，必须先定义重复键放在哪侧，再调整条件；整数边界不要简单通过加减 1 处理，以免溢出。

### 9.2 删除的三种情况

1. 没有子节点：直接从父节点断开。
2. 只有一个子节点：让子节点接替当前位置。
3. 有两个子节点：用中序后继或前驱的键值记录替换，再删除那个后继或前驱节点。

若节点存储键和值，替换时应保持记录完整；还要处理根节点变化与内存释放。

#### 删除示例：两个孩子的节点

删除前面示例中的 8：右子树最小节点是 10，它是 8 的中序后继。用 10 的完整键值记录替换根，再删除原位置的 10，把 14 接到对应位置。

如果后继还有右孩子，就让右孩子接替后继位置；后继不可能有左孩子，否则它就不是右子树最小节点。

#### 面试问答：BST 删除

**Q9-03：为什么删除双孩子节点可以用中序后继替换？**

**参考回答：** 中序后继是右子树中的最小键，它大于左子树中的所有键，又不大于右子树其余键。替换后仍满足 BST 顺序关系。随后删除原后继节点，它最多只有一个右孩子，转为较简单的删除情况，总时间 O(h)。

**Q9-04：BST 删除为什么容易出现内存问题？**

**参考回答：** 除修改父子连接外，还要处理根节点更新、被删节点释放和外部引用失效。若先释放节点再读取它的孩子，会形成释放后访问；若忘记断开连接，会留下悬空指针；若只移除连接不释放拥有的节点，可能泄漏。实现前要明确节点所有权。

### 9.3 平衡机制与 STL

- AVL 树：约束左右子树高度差，通过旋转维护平衡。
- 红黑树：用颜色与结构约束保证高度为 O(log n)。
- `std::map`、`std::set` 提供有序键访问，按键查询、插入与删除为 O(log n)；常见实现使用红黑树，但标准不要求特定树种。

有序容器支持 `lower_bound` 等范围操作，哈希表不提供同样的键序关系。

**常见错误：** 只比较父子节点来判断 BST。应检查整棵子树的取值范围，或验证中序序列是否满足规定的顺序与重复键策略。

**练习：** 查找最小值；判断 BST；演示依次插入 1、2、3、4 后普通 BST 如何退化。

#### 面试问答：AVL、红黑树与旋转

**Q9-05：旋转为什么能调整高度又保持 BST 顺序？**

**参考回答：** 以右旋为例，将根 y 的左孩子 x 提升，把 x 的右子树移到 y 的左侧，再让 y 成为 x 的右孩子。原先满足 `x 的左子树 < x < x 的右子树 < y < y 的右子树` 的中序关系没有变化，改变的只是父子结构。旋转只改常数个连接，单次 O(1)，但维护高度或颜色可能沿祖先继续进行。

**Q9-06：AVL 和红黑树有什么区别？**

**参考回答：** AVL 对每个节点要求左右子树高度差不超过 1，平衡约束较严格。红黑树通过颜色、红节点相邻约束和黑高一致等规则保持高度 O(log n)，允许更宽松的局部形状。二者按键操作都为 O(log n)，实际取舍与读写比例、实现和缓存有关，不能断言某一种在所有负载下都更快。

**Q9-07：红黑树为什么不会退化成链？**

**参考回答：** 关键约束包括根为黑、空叶为黑、红节点不能有红孩子，以及从任一节点到空叶的路径具有相同黑节点数。红节点不能连续，使最长路径不会超过最短路径的约两倍；结合黑高与节点数的关系，可得到树高 O(log n)。空叶一般指概念上的 NIL，不是实际数据节点。

**Q9-08：`map` 必须用红黑树实现吗？**

**参考回答：** 不是。标准规定接口、有序性和复杂度等要求，不要求某种具体内部结构。红黑树是常见实现。面试时可以说明常见实现，但不能把实现细节当作标准保证，也不能把 `map` 的值视为可随意修改的键。

#### AVL 插入失衡的四种形态

以插入路径方向命名，找到最近的失衡祖先后选择旋转：

| 形态 | 插入示例 | 修复 |
|---|---|---|
| LL | 依次插入 30、20、10 | 对 30 右旋 |
| RR | 依次插入 10、20、30 | 对 10 左旋 |
| LR | 依次插入 30、10、20 | 先对 10 左旋，再对 30 右旋 |
| RL | 依次插入 10、30、20 | 先对 30 右旋，再对 10 左旋 |

四个示例最终都可得到根为 20、左孩子 10、右孩子 30 的结构。旋转后要按孩子到父节点的顺序更新高度，避免使用旧高度。删除后的失衡判断还需要结合子节点平衡因子，不能只记插入路径。

## 10. 堆与优先队列

### 10.1 堆的性质

二叉堆同时满足：

1. 结构上是一棵完全二叉树。
2. 大根堆中父节点不小于子节点；小根堆中父节点不大于子节点。

**堆只保证局部的父子顺序，不保证整体有序。** 大根堆的根是最大值，但左右子树之间没有排序关系。

用从 0 开始的数组存储：

```text
节点 i 的左孩子：2*i + 1
节点 i 的右孩子：2*i + 2
节点 i 的父节点：(i - 1) / 2，要求 i > 0
```

| 操作 | 复杂度 | 原理 |
|---|---|---|
| 查看堆顶 | O(1) | 读取数组首元素 |
| 插入 | O(log n) | 末尾插入，然后上浮 |
| 删除堆顶 | O(log n) | 末尾替换堆顶，然后下沉 |
| 自底向上建堆 | O(n) | 多数节点靠近叶子，下沉距离短 |
| 查找任意值 | O(n) | 无法像 BST 一样排除一半子树 |

逐个插入建堆的最坏成本为 O(n log n)，与自底向上建堆要区分。

#### 操作示例：上浮与下沉

小根堆数组 `[3, 8, 5]` 插入 2：先追加成 `[3, 8, 5, 2]`，2 与父节点 8 交换，再与父节点 3 交换，得到 `[2, 3, 5, 8]`。

弹出 2：用末尾 8 替换堆顶并移除末尾，得到 `[8, 3, 5]`，再与较小孩子 3 交换，得到 `[3, 8, 5]`。下沉时必须在两个孩子中选更合适的那个。

#### 面试问答：堆的复杂度

**Q10-01：堆和 BST 的顺序关系有什么区别？**

**参考回答：** BST 对整棵左子树和右子树规定键序，可以按目标选择一侧查找；堆只规定父节点和孩子的大小关系，左右子树之间无顺序。堆因此擅长取极值，但查找任意键通常 O(n)。两者不能因为都是树就认为能力相同。

**Q10-02：自底向上建堆为什么是 O(n)？**

**参考回答：** 从最后一个非叶节点开始下沉。接近叶子的节点数量很多，但最多下沉一两层；需要下沉很多层的节点很少。按高度求和，工作量受 `n × Σ(h/2^h)` 的常数倍约束，因此为 O(n)。把每个节点都按最坏 O(log n) 相乘，会得到不紧的上界。

**Q10-03：堆删除某个已知下标的元素能做到 O(log n) 吗？**

**参考回答：** 可以。用末尾元素覆盖它并移除末尾，再根据与父节点及孩子的关系选择上浮或下沉，调整最多 O(log n)。但如果只知道值而不知道位置，查找位置可能 O(n)；想按 ID 高频更新，需要额外维护 ID 到下标的映射，并在每次交换时同步映射。

### 10.2 C++ 使用

```cpp
#include <queue>
#include <vector>
#include <functional>

std::priority_queue<int> max_heap; // 默认大根堆
std::priority_queue<int, std::vector<int>, std::greater<int>> min_heap;

for (int x : {8, 3, 10}) min_heap.push(x);
int smallest = min_heap.top(); // 3
min_heap.pop();                // 移除 3
```

适合持续取最值、Top K、事件调度，以及 Dijkstra 的候选节点管理。

#### 面试问答：priority_queue 与更新

**Q10-04：priority_queue 可以直接修改任意元素的优先级吗？**

**参考回答：** 标准 `priority_queue` 不提供按位置访问、任意删除或 decrease-key 接口。可以改用带位置映射的自定义堆，或采用惰性删除：更新时插入新记录，取出时检查记录是否过期。后者实现简单，但会保留过期项，增加空间和弹出次数。

**Q10-05：C++ 小根堆比较器为什么用 greater？**

**参考回答：** `priority_queue` 默认采用 `less`，把最大的元素放在 top；采用 `greater` 则让较小的元素优先处于 top。自定义记录时比较器应满足严格弱序，不能用 `<=` 代替 `<`。相同优先级是否需要按时间或 ID 再排序，应根据业务明确，默认不保证 FIFO 稳定性。

### 10.3 Top K 的选择

找 n 个元素中最大的 k 个，且 `1 <= k <= n`：维护大小为 k 的小根堆，堆顶是当前候选中的最小值。新值更大时替换堆顶。

时间 O(n log(k + 1))，空间 O(k)。结果若要求从大到小排列，还需要排序。与排序整个输入的 O(n log n) 比较时，应考虑 k、是否需要改动输入及输出顺序。

**常见错误：** 认为堆数组是排序结果；空堆上调用 `top()`；把“最大的 k 个”误写成维护大根堆淘汰最大值。

**练习：** 手画一次插入上浮与删除下沉；求第 k 大元素；合并多个有序序列。

#### 面试问答：Top K 与多路归并

**Q10-06：求第 k 大元素，为什么维护小根堆？**

**参考回答：** 保留当前最大的 k 个候选，候选中最小的值就是淘汰门槛，所以需要小根堆。新值不大于堆顶时无需进入候选；更大时替换堆顶。处理完后堆顶是第 k 大值。需先确认 k 合法，以及题目按出现次数还是按不同值计算排名。

**Q10-07：如何合并 k 个有序序列？**

**参考回答：** 小根堆保存每个非空序列当前尚未输出的首元素及来源。弹出最小项后，把同一序列的下一个元素放入堆。总元素数为 N 时，时间 O(N log(k + 1))，堆辅助空间 O(k)，输出空间另计。每次只需在各序列当前首项中选择最小值。

**Q10-08：Top K 除了堆还有什么方案？**

**参考回答：** 全量排序适合同时需要完整顺序；快速选择平均 O(n)，但朴素实现最坏 O(n²)，且通常改变输入；数据流更适合固定大小堆。选择后如需候选内部排序，要再计入 O(k log k)。应从是否在线、能否修改输入和是否要求有序输出判断。

## 11. 图

### 11.1 基本概念与存储

图由顶点 V 和边 E 组成。边可以有方向和权重；图可能有环，也可能不连通。以下用 V、E 同时表示对应数量，具体含义由上下文判断。

| 存储 | 空间 | 判断一条边是否存在 | 枚举某顶点邻居 | 适用场景 |
|---|---|---|---|---|
| 邻接矩阵 | O(V²) | O(1) | O(V) | 稠密图、频繁查询边 |
| 邻接表 | O(V + E) | 普通列表需 O(deg(v)) | O(deg(v)) | 稀疏图、遍历 |

无向图的邻接表通常把一条边存两次；复杂度仍是 O(V + E)。加权图可以在邻接记录中保存 `(邻居, 权重)`。

#### 面试问答：图存储

**Q11-01：什么时候用邻接矩阵，什么时候用邻接表？**

**参考回答：** 稠密图或频繁判断某条边存在时，矩阵简单且边查询 O(1)，但空间 O(V²)。稀疏图和邻居遍历通常优先邻接表，其空间 O(V + E)，访问某顶点邻居只需与度数成正比的时间。若邻接表的邻居使用哈希集合，边查询特性又会改变，应说明具体表示。

**Q11-02：加权图矩阵中能用 0 表示没有边吗？**

**参考回答：** 如果允许零权边，就不能只用 0 区分“无边”和“权重为零”。可以另设存在标记或使用专门的无穷值表示无边。使用整数无穷值参与路径相加时还要避免溢出，不能直接对未到达状态做加法。

### 11.2 广度优先搜索 BFS

BFS 用队列按距离层层扩展，可以求无权图中从起点到其他顶点的最少边数。

```cpp
#include <vector>
#include <queue>

// 顶点编号 0..g.size()-1，邻接表内编号必须有效
std::vector<int> bfs_distances(const std::vector<std::vector<int>>& g,
                               int start) {
    std::vector<int> dist(g.size(), -1); // -1 表示不可达
    if (start < 0 || static_cast<std::size_t>(start) >= g.size())
        return dist;

    std::queue<int> q;
    dist[start] = 0;
    q.push(start);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : g[u]) {
            if (dist[v] != -1) continue;
            dist[v] = dist[u] + 1; // 入队时标记，避免重复入队
            q.push(v);
        }
    }
    return dist;
}
```

使用邻接表时，时间 O(V + E)，辅助空间 O(V)。想恢复路径，需要另外保存每个顶点首次被发现时的前驱。

#### 面试问答：BFS 正确性

**Q11-03：BFS 为什么第一次发现节点就能确定最少边数？**

**参考回答：** 队列按发现顺序处理节点，距离 d 的节点会在距离 d + 1 的节点之前扩展，因此第一次到达某节点时，不可能还有更少边数的路径尚未探索。这个证明依赖每条边贡献相同代价；权重不同时，先发现不等于最小总代价。

**Q11-04：为什么建议入队时标记，而不是出队时标记？**

**参考回答：** 入队时标记表明该顶点已经被安排处理，其他父节点不会重复加入它。若出队才标记，需要额外控制重复项，否则可能多次入队、重复扩展并浪费空间。示例用 dist 同时表示已发现状态与距离，不再额外需要 visited。

**Q11-05：如何做多源 BFS？**

**参考回答：** 将所有起点先标记为距离 0 并一起入队，再按普通 BFS 扩展。得到的是每个顶点到任一起点的最少边数，适合最近出口、多个传播源等问题。重复起点应去重或确保只入队一次；恢复路径时还可以记录对应源点。

### 11.3 深度优先搜索 DFS

DFS 沿一条路径深入，无法继续时回退。可以使用递归或显式栈。

- 用途：可达性、连通分量、搜索与回溯。
- 图中必须管理访问状态，否则有环时可能无限访问。
- 无向图判环需要区分父边；有向图判环通常需要区分未访问、正在访问、已完成三种状态。
- 要遍历整个不连通图，需要从每个尚未访问的顶点启动搜索。

#### 面试问答：DFS 与判环

**Q11-06：有向图为什么不能只用 visited 判环？**

**参考回答：** 指向已经访问完成的节点可能只是不同路径汇合，不一定有环。需要区分正在当前 DFS 路径中的节点与已完成节点；若遇到指向“正在访问”节点的边，说明形成回路。常用白、灰、黑三色状态，或 visited 配合当前递归路径标记。

**Q11-07：无向图判环为何需要记录父节点？**

**参考回答：** 无向边在邻接表中通常存两次，从子节点回到父节点只是同一条边的反向记录，不应判为环。简单无向图可跳过父节点；若允许平行边，应跳过具体父边 ID，而不是跳过所有连接父节点的边，否则可能漏掉由平行边形成的环。

### 11.4 图算法选择

| 问题 | 方法 | 前提或关键点 |
|---|---|---|
| 可达性、连通分量 | BFS / DFS | 有向图需明确所问的连通性定义 |
| 最少边数路径 | BFS | 无权图，或所有边代价相同 |
| 非负权最短路径 | Dijkstra | 不允许负权边；常用小根堆 |
| 含负权边的单源最短路径 | Bellman–Ford | 可检测从源点可达的负环 |
| 依赖任务排序 | 拓扑排序 | 有向无环图；有环时无法完成 |
| 无向图的最小生成树 | Kruskal / Prim | 不连通时得到生成森林 |

最短路径优化两点之间的路径代价；最小生成树优化连接全部顶点的总边权，两者目标不同。

#### 面试问答：最短路径、依赖与生成树

**Q11-08：Dijkstra 为什么要求非负权？**

**参考回答：** 算法每次确定当前距离最小的未确定节点，依赖后续路径不会通过负边把它的距离进一步降低。存在负权时，已确定结果可能被推翻。含负权边可以考虑 Bellman–Ford；若存在从源点可达且可到达目标的负环，则目标没有有限的最短路径值。

**追问：使用标准 priority_queue 没有 decrease-key 怎么办？**

**回答：** 每次改进距离就插入新的 `(距离, 顶点)`，弹出时如果记录距离不是当前 dist，就跳过过期项。按严格改善插入的常见实现，堆最多保留 O(E) 量级记录，时间可写为 O((V + E) log(V + E)) 的上界；简单图中常简写为 O((V + E) log V)。

**Q11-09：权重只有 0 和 1 时，可以比普通 Dijkstra 更简单吗？**

**参考回答：** 可以用 0–1 BFS。发生松弛时，经过权重 0 的边将顶点放队首，权重 1 的边放队尾，使处理顺序符合距离变化，使用邻接表可实现 O(V + E)。它需要维护距离并进行松弛，不能直接套用普通 BFS 的“首次发现后不再更新”。

**Q11-10：如何用拓扑排序判断依赖关系是否有环？**

**参考回答：** Kahn 算法先把入度为 0 的节点入队，移除节点时减少其后继入度，后继降为 0 再入队。如果最终处理节点数小于 V，剩余部分存在有向环。拓扑序可能不唯一，复杂度 O(V + E)；“有环”只说明不存在完整拓扑序，不能据此认为所有剩余节点都直接位于环上。

**Q11-11：Kruskal 和 Prim 有什么区别？**

**参考回答：** Kruskal 把边按权重排序，从小到大选择不造成环的边，通常配合并查集，典型时间 O(E log E)。Prim 从一个顶点出发，不断选择连接已选集合与未选顶点的最小边，邻接表加堆常为 O((V + E) log V)，朴素矩阵版 O(V²)。不连通图要分别处理分量得到森林，两种方法都允许负边权。

**Q11-12：最小生成树一定给出任意两点的最短路径吗？**

**参考回答：** 不一定。最小生成树最小化连接全部节点的总边权，不单独最小化某两点的路径。三角形边 AB=2、BC=2、AC=3，生成树选 AB 和 BC，总权 4；但树上 A 到 C 路径权为 4，比原图直接边的 3 大。

**Q11-13：Bellman–Ford 如何处理负权边并检测负环？**

**参考回答：** 重复扫描所有边并进行松弛：若源端可达且经过这条边能改善终点距离，就更新。没有相关负环时，最短路径可选为至多 V - 1 条边的简单路径，所以 V - 1 轮足够；若第 V 轮仍能改善可达顶点，说明存在源点可达的负环。典型时间 O(VE)，距离辅助空间 O(V)，一轮没有更新时可以提前结束。

**追问：检测到负环就代表所有目标都没有有限最短路吗？**

**回答：** 不是。只有源点能到达该负环、且该负环又能到达目标时，目标距离才可无限降低。可以从仍可松弛的顶点出发传播受影响状态，区分不可达、有限距离与受负环影响的目标。

**练习：** 在网格中做四方向 BFS；统计无向图连通分量；对课程依赖关系做拓扑排序并判断是否有环。

## 12. 进阶结构：按问题选学

基础结构掌握后，再根据需求学习下列内容，无需一开始全部手写。

| 结构 | 解决的问题 | 核心原理 | 典型复杂度 |
|---|---|---|---|
| 并查集 | 动态合并集合、判断是否同组 | 父指针、路径压缩、按秩或大小合并 | 两种优化配合时，m 次操作约 O(m α(n))，另计初始化 |
| Trie | 字符串前缀查找 | 沿字符逐层分支 | 直接字符索引下插入与查询 O(L) |
| 树状数组 | 单点更新、前缀和 | 用 lowbit 管理分块区间 | 更新与查询 O(log n) |
| 线段树 | 区间查询及更新 | 递归划分区间、合并信息 | 常见范围聚合查询 O(log n)，建树 O(n) |
| B/B+ 树 | 外存索引 | 多路分支降低树高 | 重点分析页面读写次数 |
| 空间索引 | 空间范围与近邻查询 | k-d 树、四叉树等空间划分 | 取决于维度、数据分布和查询类型 |

`L` 为字符串长度，`α(n)` 为反阿克曼函数，增长极慢。线段树区间更新通常需要懒标记等机制，且更新操作必须能与维护的信息兼容。

**并查集不能直接回答一般图的最短路径，也不擅长直接处理删边。** Trie 的内存开销取决于字符集及子节点存储方式。

机器人运动规划中可能需要近邻查询，但 k-d 树在高维或不利分布下可能退化，不能笼统宣称任何查询都为 O(log n)。

### 12.1 并查集：维护动态集合

每个元素保存 parent，沿父指针找到代表元。`find` 查询代表元，`unite` 合并两个集合。初始化时每个元素自成一组。

- **路径压缩**：查询后让路径节点更直接地指向根。
- **按大小合并**：把较小集合的根挂到较大集合的根下。
- 代表元只是集合标识，不天然等于最小元素或最早加入的元素。

```cpp
#include <vector>
#include <numeric>
#include <utility>

class DSU {
    std::vector<int> parent;
    std::vector<int> sizes;
public:
    // 前提：n >= 0，后续 x、y 都是合法下标
    explicit DSU(int n) : parent(n), sizes(n, 1) {
        std::iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    bool unite(int x, int y) {
        x = find(x);
        y = find(y);
        if (x == y) return false;
        if (sizes[x] < sizes[y]) std::swap(x, y);
        parent[y] = x;
        sizes[x] += sizes[y];
        return true;
    }
};
```

应用：连通分量合并、Kruskal 判环、等价关系维护。标准并查集支持不断合并，不直接维护一般删边后的连通性。

**Q12-01：路径压缩和按大小合并分别解决什么？**

**参考回答：** 路径压缩减少已查询路径的后续访问长度；按大小合并避免小规模合并反复拉高大树。两者配合后，一串操作具有接近常数的摊还成本 O(α(n))，不是严格的每次最坏 O(1)。初始化 n 个元素还需要 O(n) 时间和空间。

**Q12-02：并查集为什么不擅长删边？**

**参考回答：** 它保存的是集合归属及父指针结构，不保存所有原始图边与替代路径。删除一条边后，无法仅靠代表元判断集合是否应拆分。某些离线问题可通过逆序加入或带回滚并查集处理，但这需要额外条件和设计。

### 12.2 Trie：前缀组织字符串

从根沿字符走边，路径代表字符串前缀，节点另有“完整单词结束”标记。例如 `car` 与 `cat` 共享 `c → a` 路径，但在第三个字符分叉。

查询前缀成功不等于完整单词存在；删除单词时也不能破坏其他单词共用的前缀。可维护终止次数与通过次数处理重复词和删除。

**Q12-03：Trie 和字符串哈希集合如何选择？**

**参考回答：** 只问完整单词是否存在，哈希集合通常简单；需要前缀判断、前缀计数和词典遍历时，Trie 的结构更直接。Trie 按字符串长度 L 逐字符访问，直接子节点索引时 O(L)，但节点数与字符集会带来较大内存开销。哈希字符串同样通常需要 O(L) 读取键，不能忽略这部分成本。

**Q12-04：Trie 查到路径末尾就表示单词存在吗？**

**参考回答：** 不一定。仅插入 `apple` 时，路径 `app` 也存在，但 `app` 未必是单词。必须检查终止标记或终止计数。若支持 Unicode，还应明确沿字节、码点还是其他单位组织，不能默认每个字符都等于一个字节。

### 12.3 树状数组：动态前缀和

通常使用从 1 开始的下标。`lowbit(i)` 取 i 的最低有效二进制位，树状数组的 `tree[i]` 保存长度为 lowbit(i)、以 i 结束的一段聚合值。

```text
lowbit(12) = 4，因此 tree[12] 覆盖 [9, 12]
查询前缀：i → i - lowbit(i) → ... → 0
单点更新：i → i + lowbit(i) → ... → 超出 n
区间和 [l, r] = prefix(r) - prefix(l - 1)
```

例如查询前 13 项，分块读取 `[13,13]`、`[9,12]`、`[1,8]`。每次去掉一个有效二进制位，操作次数 O(log n)。

**Q12-05：为什么不能把树状数组更新下标设为 0？**

**参考回答：** 常见 1-based 模板中 lowbit(0)=0，更新步骤 `i += lowbit(i)` 不会前进，会无限循环。外部使用 0-based 数据时应先转换为内部的 i+1，并统一前缀查询的端点含义。

**Q12-06：前缀和数组和树状数组有什么区别？**

**参考回答：** 静态前缀和预处理 O(n)，区间求和 O(1)，但单点变化可能影响后面所有前缀值，需要 O(n) 更新。树状数组把数据分块，使单点更新和前缀查询均为 O(log n)，适合频繁更新又需要求和的任务。一般区间和可做前缀差，是因为求和有对应的逆运算。

### 12.4 线段树：维护区间信息

线段树递归划分区间，叶子保存单个元素，父节点保存两个子区间合并后的结果。常见信息包括和、最小值、最大值及自定义统计。

- 单点更新：修改叶节点，再沿祖先重算。
- 区间查询：把目标区间分解成若干完整节点区间。
- 懒标记：完整区间更新时暂存效果，必要时再向孩子传播。
- 合并操作需满足结合性；左右顺序不可交换的聚合仍可处理，但查询时必须保持顺序。

**Q12-07：线段树的懒标记为什么能提高区间更新效率？**

**参考回答：** 遇到完全覆盖的节点时，直接更新该节点的聚合值，并记录尚未下传的更新，不逐个访问叶子。后续查询或部分更新进入孩子时，再传播标记。这样常见的区间加与区间和可以做到 O(log n)，但标记合成和聚合更新必须正确，不能认为任何更新都能简单套一个标记。

**Q12-08：区间加 d 时，节点区间和为什么加 d×长度？**

**参考回答：** 区间内每个元素都增加 d，若节点覆盖 len 个元素，总和增加 d×len。懒标记也累计 d，传播时按各孩子长度修改其和。若同时支持区间赋值与区间加，赋值可能覆盖旧标记，必须定义操作先后顺序，不能只把所有标记相加。

**Q12-09：树状数组与线段树如何选择？**

**参考回答：** 单点增量与前缀和优先考虑树状数组，实现简洁、空间常数较小。更一般的区间聚合或兼容懒标记的区间更新可以考虑线段树。不能说树状数组只支持求和，但其他信息往往需要额外限制；选择时要明确更新和查询的代数性质。

### 12.5 B 树与 B+ 树：外存索引

外存访问通常以页面或块为单位。多路树每个节点容纳许多键，降低树高，从而减少一次查询需要读取的页面数量。

典型 B+ 树将数据记录或其引用放在叶节点，内部节点主要保存路由键，叶节点还通过链接支持有序扫描。具体记录布局取决于索引实现。

**Q12-10：数据库索引为什么经常采用 B+ 树而不是二叉搜索树？**

**参考回答：** 多路分支可让单个页面存更多路由键，减少树高和页面访问；B+ 树叶节点有序且常有链接，适合范围扫描。二叉树每个节点分支少，用于外存时可能需要更多随机页面访问。这里重点是 I/O 与页面布局，不只是抽象比较次数。

**Q12-11：B 树和 B+ 树的区别是什么？**

**参考回答：** 典型 B 树可以在内部节点和叶节点保存记录；典型 B+ 树内部节点用于导航，记录集中在叶层，叶层支持顺序扫描。B+ 树完整键查询通常走到叶层，B 树可能在内部节点命中。它们都维护平衡和多路结构，细节应按具体数据库实现核对。

### 12.6 空间索引：近邻与范围查找

k-d 树通过按坐标轴划分空间组织点集；查询时先探索可能更近的区域，再用距离下界决定是否需要访问其他区域。四叉树常用于二维空间递归划分。

**Q12-12：k-d 树近邻查询为什么不保证总是 O(log n)？**

**参考回答：** 剪枝效果依赖维度、点分布与划分质量。高维时许多区域的距离下界不足以排除候选，查询可能访问大量节点，最坏达到线性。应按实际维度和负载比较线性扫描、精确空间索引与近似近邻方法。

**Q12-13：运动规划中的近邻距离能直接使用坐标欧氏距离吗？**

**参考回答：** 需要先看状态空间。位置可以用欧氏距离，但关节角存在周期性，旋转还有自身几何结构，多种状态量的量纲也不同。距离定义必须与状态空间和规划目标一致，否则索引找到的“近”节点可能并不符合运动上的接近。

## 13. 常用结构速查与选型

下表默认比较、哈希及单元素操作成本为常数；复杂键应另计自身处理成本。

| 结构 | 查询 | 插入 | 删除 | 主要优势 |
|---|---|---|---|---|
| 无序动态数组 | 下标 O(1)，按值 O(n) | 尾部摊还 O(1)，中间 O(n) | 尾部 O(1)，中间 O(n) | 连续存储、遍历高效 |
| 有序数组 | 二分 O(log n) | O(n) | O(n) | 静态数据查询、范围扫描 |
| 单链表 | O(n) | 已知前驱 O(1) | 已知前驱删后继 O(1) | 连接修改简单 |
| 栈 / 队列 | 顶端 / 队首 O(1) | 通常 O(1) | O(1) | 限制访问顺序 |
| 哈希表 | 平均 O(1)，最坏 O(n) | 平均 O(1)，最坏 O(n) | 平均 O(1)，最坏 O(n) | 按键定位 |
| 平衡搜索树 | O(log n) | O(log n) | O(log n) | 有序键与范围查询 |
| 二叉堆 | 堆顶 O(1)，任意值 O(n) | O(log n) | 堆顶 O(log n) | 持续提取最值 |

具体需求可以这样匹配：

| 需求 | 优先考虑 | 判断理由 |
|---|---|---|
| 按下标读取轨迹点 | `vector` | 随机访问与连续存储 |
| 6 个关节的固定状态 | `array<double, 6>` | 长度固定，无需改变容量 |
| 按到达顺序处理事件 | `queue` / 环形队列 | FIFO |
| 返回待处理的最高优先级任务 | `priority_queue` | 堆顶始终是极值候选 |
| 按关节名称找到配置 | `unordered_map` | 按键查找，通常无需顺序 |
| 按时间戳查找一段记录 | `map` / 有序 `vector` | 有序范围访问；更新频率决定取舍 |
| 缓存淘汰最近最少使用的项 | 哈希表 + 双链表 | 定位节点与维护访问顺序 |
| 网格最少步数 | 队列 + 距离数组 | BFS 的逐层扩展 |
| 动态查询是否属于同一集合 | 并查集 | 合并与连通关系维护 |

先写清“最频繁的操作是什么”，再选容器。对于时间敏感的控制循环，还应考虑分配、扩容、锁等待和最坏耗时，不能只看平均复杂度。

### 13.1 面试中的选型回答模板

```text
数据规模与输入特性：大约多少条，是否有序或存在重复？
操作分布：读多还是写多，按下标还是按键，是否需要范围查询？
限制：内存、稳定引用、并发、最坏延迟、能否改变输入？
候选：说明两个可行结构。
选择：给出操作成本、主要优势与代价。
验证：用真实或代表性负载比较关键指标。
```

**Q13-01：只有几条数据，也应该用哈希表优化查询吗？**

**参考回答：** 不一定。少量数据使用数组线性扫描可能更简单、更紧凑，也避免哈希和分配开销。首先确认查询频率与规模，再比较实际耗时；大 O 帮助判断增长趋势，不能代替对小规模负载的测量。

**Q13-02：需要保存有序时间戳，选 map 还是 vector？**

**参考回答：** 若记录按时间单调追加、查询多，可用有序 `vector` 追加和二分，再顺序扫描范围；若频繁任意位置插入删除，`map` 通常更方便。还需处理重复时间戳：`map` 不允许重复键，可考虑 `multimap` 或把时间戳与序号组成键。对单调数据，不要因为“有序”就直接选择树。

**Q13-03：容器线程安全意味着什么？多个线程只读可以吗？**

**参考回答：** 多线程只读取已经安全发布且不再修改的容器通常可以，但只要存在并发结构修改，就必须满足容器规定的并发保证并进行适当同步。尤其插入、删除、扩容会改变结构与迭代器状态；不能以“操作不同键”推断任意容器都可以并发写入。发布时的数据可见性和元素自身的线程安全也要处理。

**Q13-04：为什么性能测试要记录尾延迟，而不只看平均值？**

**参考回答：** 扩容、缓存未命中、锁竞争等可能只影响少数操作，却造成明显延迟峰值。交互或控制系统可能更在意这些峰值。应结合业务记录吞吐、延迟分布、分配次数和内存占用，并在代表性负载下评估；某次测试的最大观测值仍不等于理论最坏界限。

**Q14-01：怎么验证自己写的数据结构正确？**

**Q14-02：如何在面试中介绍轨迹缓冲区项目？**

**参考回答：** 先说明生产轨迹点和消费轨迹点的速度可能不同，因此需要有界缓冲。再解释固定容量环形队列如何以 O(1) 操作维护 FIFO、如何处理满队列和过期时间戳，最后给出空满回绕等验证证据。若只实现单线程，应明确该范围，不把未做的并发或实时保障描述成已完成。

**Q14-03：队列积压后直接扩大容量是不是解决方案？**

**参考回答：** 扩大容量能吸收短时突发，但若长期生产速度超过消费速度，只会推迟满队列并增加数据延迟。需要分析消费能力、背压、过期数据处理及业务允许的丢弃策略。对轨迹执行尤其应判断旧点是否仍然有效，而不是只追求不丢数据。

## 16. 查找与排序：配套必学算法

数据结构面试通常会结合查找与排序考察。这一章用于把容器的性质与算法选择连接起来。

### 16.1 顺序查找、二分查找与有序边界

- 无序数据顺序查找：最坏 O(n)，不需预处理。
- 有序随机访问序列二分查找：O(log n)，要求排序关系与比较规则一致。
- 若仅查询一次，先排序再二分未必划算；若反复查询静态数据，排序成本可以分摊。
- `lower_bound` 找第一个不小于目标的边界，`upper_bound` 找第一个大于目标的边界。

**Q16-01：有 n 条无序数据，需要一次查找，要先排序吗？**

**参考回答：** 通常不需要。一次线性查找 O(n)，比较排序加二分通常 O(n log n) + O(log n)，成本更高。若后续有许多查询或需要有序范围处理，预先排序才可能有价值，也可以根据按键访问需求考虑哈希索引。

**Q16-02：为什么不能拿升序排序的数据用降序比较器做二分？**

**参考回答：** 二分要求搜索区间满足与比较器一致的划分条件。排序与查询规则不一致，算法依赖的不变量不成立，结果无法保证。自定义对象尤其要明确按哪个字段排序，并用一致的规则执行边界查询。

### 16.2 排序复杂度与稳定性

以下为典型数组实现，辅助空间不计输入本身；算法实现变体可能改变空间或最好复杂度。

| 算法 | 最好时间 | 平均时间 | 最坏时间 | 辅助空间 | 典型稳定性 |
|---|---|---|---|---|---|
| 冒泡排序（含提前结束） | O(n) | O(n²) | O(n²) | O(1) | 稳定 |
| 选择排序（直接交换） | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入排序 | O(n) | O(n²) | O(n²) | O(1) | 稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 可稳定 |
| 快速排序（常见划分） | O(n log n) | O(n log n) | O(n²) | 平均 O(log n)，最坏 O(n) 递归栈 | 不稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 计数排序 | O(n + K) | O(n + K) | O(n + K) | O(n + K)，典型稳定输出实现 | 可稳定 |

堆排序这一行给出常见通用上界；在大量相等键等特殊输入下，采用提前停止下沉的实现可能做更少工作。讨论“最好时间”时应说明实现与输入约束。

稳定性指**相等排序键的元素保留输入中的相对顺序**。例如同分学生按输入先后排列，稳定排序不会打乱这个顺序。稳定不是“运行时间稳定”，也不是“结果一定唯一”。

**Q16-03：为什么排序稳定性有用？**

**参考回答：** 当相同主键记录还有原有顺序意义时，稳定性可保留该信息。例如先按姓名排序，再稳定地按分数排序，最终相同分数内仍按姓名排列。也可直接使用分数与姓名的组合比较器一次排序，但需求与实现方式不同。

**Q16-04：选择排序为什么不稳定？插入排序为什么可以稳定？**

**参考回答：** 选择排序的远距离交换可能让相同键跨越彼此。例如 `[2a, 2b, 1]` 把 1 与 2a 交换后得到 `[1, 2b, 2a]`。插入排序只移动严格大于当前键的元素，相等元素不向后搬移，因此保留相对顺序；若把移动条件改成大于等于，就可能失去稳定性。

### 16.3 插入排序：理解“已排序前缀”

```cpp
#include <vector>
#include <cstddef>

void insertion_sort(std::vector<int>& a) {
    for (std::size_t i = 1; i < a.size(); ++i) {
        int value = a[i];
        std::size_t j = i;
        while (j > 0 && a[j - 1] > value) {
            a[j] = a[j - 1];
            --j;
        }
        a[j] = value;
    }
}
```

不变量：第 i 轮之前 `[0, i)` 已排序，本轮把 `a[i]` 插入正确位置。近乎有序的小规模输入通常移动较少。

**Q16-05：插入排序最坏 O(n²)，为什么还值得学习或使用？**

**参考回答：** 它实现简单、额外空间小，并且对近乎有序输入移动少，最好 O(n)。在较小区间上，常数开销可能低于复杂排序，因此有些混合排序会用它处理小段。实际是否更快仍需看实现、元素类型和数据规模。

### 16.4 快速排序：划分而不是先排序子数组

选一个基准，将元素按大小划分，再递归处理两侧。比较均衡的划分产生 O(log n) 层，每层处理 O(n) 元素，得到 O(n log n)。极端不均衡时每层只减少一个元素，累积 O(n²)。

**Q16-06：快速排序什么时候退化？如何改善？**

**参考回答：** 简单地固定选择端点基准，在有序输入上可能连续产生极端划分；大量相同元素也可能使某些二路划分退化。随机基准、三数取中和三路划分可改善常见情况，但不都提供最坏保证。若要最坏 O(n log n)，可采用深度超限时切换堆排序的内省式方案。

**追问：快排为什么不总是 O(1) 空间？**

**回答：** 划分本身可能只用常数临时变量，但递归需要栈。普通递归平均深度 O(log n)，最坏 O(n)。优先递归较小子区间、用循环处理较大区间，可以控制栈深，但这不自动消除最坏 O(n²) 时间。

### 16.5 归并排序：先排子数组，再合并

把数组分成两半，各自排序，再用双指针把两个有序区间合并到缓冲区。划分层数 O(log n)，每层合并总工作 O(n)，时间 O(n log n)。典型数组实现需要 O(n) 缓冲区。

**Q16-07：归并排序如何保证稳定？适合链表吗？**

**参考回答：** 合并时两个键相等，优先选择左区间的元素，即可保持原相对顺序。链表可以通过修改连接完成有序合并，不必像数组一样移动大量元素，所以归并常适合链表排序。但递归链表归并仍需要调用栈，不能不加区分地说全部实现都是 O(1) 辅助空间。

### 16.6 堆排序、计数排序与标准库

堆排序先建大根堆，再反复把堆顶与未排序区间末尾交换并下沉，最终得到升序数组。计数排序通过整数键频次及累计位置安排结果，依赖较小的键范围 K。

**Q16-08：为什么堆排序最坏 O(n log n)，却不一定比快速排序快？**

**参考回答：** 最坏界限只是一个指标。堆的父子跳跃访问与比较方式可能带来较差局部性，而快速排序的划分常以线性扫描进行。实际性能取决于数据、元素类型和实现；堆排序的优势是常数辅助空间与最坏时间保证，代价包括不稳定性等。

**Q16-09：计数排序 O(n + K)，是否推翻比较排序的 Ω(n log n) 下界？**

**参考回答：** 没有。该下界针对一般比较排序模型。计数排序利用键为有限范围整数等额外结构，通过直接索引计数，不仅靠两两比较。当键范围 K 很大时，时间与内存也可能不划算；负数可通过偏移处理，但需注意范围计算溢出。

**Q16-10：C++ 中 sort、stable_sort 和 nth_element 分别用于什么？**

**参考回答：** `std::sort` 用于完整排序，不保证稳定性，C++17 的比较复杂度要求为 O(n log n)；`std::stable_sort` 保留相等键的相对顺序；`std::nth_element` 用于选择排名元素及划分两侧，不会把两侧整体排序，通常讨论其平均线性比较成本。`stable_sort` 的比较复杂度受可用额外内存影响，有足够内存时 O(n log n)，否则可为 O(n log² n)。

**追问：自定义比较器为什么不能写成 a <= b？**

**回答：** 排序比较器应满足严格弱序，其中 `comp(x, x)` 必须为 false，且顺序关系要自洽。`<=` 对自身为 true，违反约定，算法行为不受保证。比较浮点数时还需明确 NaN 的处理规则，不能假设普通大小比较自动构成合法顺序。

### 16.7 基数排序：逐位利用键的结构

以非负整数的最低位优先（LSD）方案为例，先按个位稳定排序，再按十位、百位等排序。处理完某一位，已处理低位的顺序在相同高位内保留下来，最终形成整体顺序。

若共有 d 位、每位基数为 B，采用稳定计数排序处理每一位，时间 O(d(n + B))，常见辅助空间 O(n + B)。它依赖键表示，处理负数、变长字符串或特殊排序规则时需要额外设计。

**Q16-11：最低位优先基数排序为什么要求每轮稳定？**

**参考回答：** 后续按更高位排序时，相同高位的元素还需要维持此前得到的低位顺序，否则已经完成的工作被打乱。例如处理个位后再排十位，相同十位内必须保留个位顺序，最终才能按完整数值有序。位数 d 并非在所有输入模型下都是固定常数，所以不能无条件说基数排序就是 O(n)。

**Q16-12：比较排序的 Ω(n log n) 下界怎么解释？**

**参考回答：** 对 n 个互异元素，一般比较排序需要区分 n! 种输入排列。把二元比较看作决策树，每个叶子对应一种确定顺序，树至少有 n! 个叶子，最坏深度至少 log₂(n!)，它与 n log n 同阶。这个结论针对一般比较模型，不排除利用整数范围等额外结构的非比较排序。

## 17. 综合面试题与答题方法

这一章练习“组合结构 + 说明限制”，把单个知识点转成完整问题的回答。

### 17.1 LRU 缓存：哈希表与双链表配合

LRU 淘汰最近最少使用的数据，成功读取和更新通常都视为一次使用。假设单线程、容量固定，每个键唯一：

```text
双链表：表头 = 最近使用，表尾 = 最久未使用
哈希表：key → 对应链表节点的迭代器

get(key)：
  未命中 → 返回明确的缺失结果
  命中 → 把节点移到表头，返回 value

put(key, value)：
  容量为 0 → 不保留记录
  已存在 → 更新 value，把节点移到表头
  新键且已满 → 先从哈希表删除尾节点的键，再移除尾节点
  将新记录加入表头，并记录迭代器
```

`std::list::splice` 可以把已知节点移到表头而不复制其记录，并保持该节点迭代器有效；被删除节点的迭代器则不能继续保存或使用。

**Q17-01：LRU 为什么需要哈希表加双链表？**

**参考回答：** 哈希表平均 O(1) 按键定位，双链表在已知节点时 O(1) 移到头部或删除尾部，两者分别解决定位和维护访问顺序的问题。只有链表时查键 O(n)，只有哈希表时难以快速确定最久未使用项。综合 get/put 通常平均 O(1)，但哈希部分不提供单次最坏 O(1) 保证。

**Q17-02：LRU 实现最容易遗漏哪些边界？**

**参考回答：** 容量为 0、容量为 1、更新已有键不应增加元素数、淘汰时两种结构必须同步、读取缺失键是否修改顺序，以及返回值能否与合法数据区分。若使用 -1 表示未命中但业务允许存 -1，就应改用可区分状态的接口。多线程还需要保护链表与哈希表的一致性。

### 17.2 数据流中位数：两个堆

用大根堆保存较小的一半，用小根堆保存较大的一半，维护：

1. 大根堆任意元素不大于小根堆任意元素。
2. 两堆数量相等，或大根堆多一个。

**Q17-03：如何支持不断插入并快速查询中位数？**

**参考回答：** 插入时与较小半区的大根堆顶比较，放入适当堆，再移动堆顶保持数量平衡。奇数个元素时中位数是大根堆顶；偶数时是两个堆顶的平均。插入 O(log n)，查询 O(1)，空间 O(n)。求平均应先转成足够宽或浮点类型，避免两个整数相加溢出；空数据时应返回缺失状态。

### 17.3 依赖调度：图、队列与优先队列

先用有向边表示“前置任务 → 后续任务”，再根据入度发现可以启动的任务。如果多个任务同时就绪且需按优先级选择，可以将拓扑排序的就绪队列换成优先队列。

**Q17-04：拓扑排序能直接解决并行任务调度吗？**

**参考回答：** 拓扑排序能识别依赖合法性并提供可行顺序，但完整调度还要考虑任务耗时、执行资源、并发上限和失败策略。实际运行中只有前置任务完成后，才能减少后继未完成依赖数，不能把“进入待执行队列”当作“已经完成”。就绪任务的选择规则可通过优先队列表达。

### 17.4 接到手写题后的作答顺序

1. 确认输入、输出、规模、重复值及异常情况。
2. 先给正确的基础方案与成本。
3. 说明需要维护的不变量，再提出优化结构。
4. 用一个小例子模拟关键操作。
5. 写代码后走空输入、边界与重复值。
6. 分别说明时间、辅助空间与适用前提。

**Q17-05：面试官问“为什么这样写一定正确”，该怎么回答？**

**参考回答：** 说明初始化时成立的不变量，每步如何保持它，以及结束时如何得到目标结果。例如二分维护左右区域的大小关系，单调队列维护有效且不被支配的候选，BFS 维护按距离层发现的顺序。只说“这是经典模板”不能说明当前代码正确。

**Q17-06：不会面试题时应该如何推进？**

**参考回答：** 先澄清问题并给出可行的直接方案，明确它的瓶颈，再结合限制寻找优化，例如重复查找可建索引、持续取极值可用堆、窗口极值可用单调队列。若暂时想不到最优解，也应把已知方案的正确性和成本讲清楚，不编造不存在的保证。
