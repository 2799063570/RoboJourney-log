# C++ 并发编程

## 结论

并发的核心不是“同时跑得更多”，而是让多个执行任务在共享资源时保持正确、可预测。机器人软件中常见的场景是：一个线程接收传感器数据，另一个线程执行规划或控制。

## 基本工具

| 工具 | 用途 |
|---|---|
| `std::thread` | 创建并管理执行线程 |
| `std::mutex` | 保护共享数据，避免竞态条件 |
| `std::lock_guard` | 用 RAII 管理互斥锁，避免遗漏解锁 |
| `std::condition_variable` | 在“等待新数据”这类场景中协调线程 |
| `std::atomic` | 用于简单、独立的状态或标志位 |

## 工程原则

- 先减少共享数据，再考虑加锁。
- 锁只保护读写共享状态；规划、日志和 I/O 等耗时操作放在锁外。
- 明确每个对象的所有权与生命周期，避免回调在对象析构后继续访问 `this`。
- 控制循环应避免频繁动态分配、长时间持锁和不可预测的阻塞操作。
