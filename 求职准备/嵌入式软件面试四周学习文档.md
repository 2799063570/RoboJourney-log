# 嵌入式软件面试四周学习文档

## 1. 这四周要达到什么水平

这不是一份“把嵌入式全部学完”的课程，而是一条面向 **机器人嵌入式、底层控制、运动控制、ROS + MCU 联合开发** 岗位的恢复路线。四周结束时，应当能够做到：

- 用 C 独立写出可靠的小模块，并解释指针、内存、对齐、字节序和 `volatile`。
- 不依赖教程逐步照抄，完成 STM32 常用外设的配置、驱动、调试和故障定位。
- 解释 GPIO、中断、定时器、UART、DMA、ADC、I2C、SPI、CAN 的硬件工作过程。
- 使用 FreeRTOS 设计控制、采集、通信任务，并正确选择 queue、semaphore 和 mutex。
- 完成一个“ROS/PC 上位机 + STM32 + FreeRTOS + UART/CAN + 模拟电机控制”的综合项目。
- 面试时按“用途 → 原理 → 配置 → 项目使用 → 故障排查”的顺序回答外设问题。

> [!important] 学习原则
> 每个知识点至少留下两类证据：可运行代码、逻辑分析仪/串口日志、手画架构图、口述答案、错误复盘。只看视频或只在 CubeMX 中点选配置，不算掌握。

## 2. 学习环境与资料

### 2.1 推荐硬件

- 一块你已经拥有且资料充足的 STM32 开发板；优先继续用熟悉的 F1/F4/G4/H7，不必为学习路线更换芯片。
- ST-Link 或板载调试器。
- USB 转串口模块，注意 3.3 V 电平和共地。
- 8 通道逻辑分析仪；没有示波器也可以先完成大多数数字通信调试。
- LED、按键、电位器或模拟传感器。
- 可选：CAN 收发器与第二个 CAN 节点、I2C 传感器、SPI 屏幕或 Flash、编码器和电机驱动板。

### 2.2 软件与手册

- STM32CubeMX + STM32CubeIDE，或者你原来使用的 Keil。
- 串口工具、逻辑分析仪软件、Git。
- 芯片 datasheet：确认引脚、电气参数、封装和外设资源。
- reference manual：查寄存器、时钟、总线和外设行为。
- board schematic：查 LED、按键、晶振、调试口和电源连接。
- HAL/LL 驱动源码与 FreeRTOS 官方文档。

三类手册的区别必须记住：datasheet 回答“这颗芯片有什么、引脚怎么接”，reference manual 回答“外设如何工作、寄存器如何配置”，开发板原理图回答“板子实际上怎么连接”。

### 2.3 每天固定节奏

按每天约 3 小时、每周 6 天安排：

## Day 1：指针、数组和二级指针

### 必须理解

变量有“值、类型、地址、生命周期”。指针本身也是变量，它保存另一个对象的地址。指针类型决定解引用时读取多少字节、按什么类型解释，以及指针加一跨过多少字节。

```c
uint32_t value = 0x12345678U;
uint32_t *p = &value;

printf("%p\n", (void *)p);
printf("%" PRIu32 "\n", *p);
```

需要区分：

| 表达式 | 含义 |
|---|---|
| `p` | 指针保存的地址 |
| `&p` | 指针变量自己的地址 |
| `*p` | 指针所指对象 |
| `p + 1` | 向后移动一个所指类型的大小 |

数组和指针不是同一个东西。数组是连续的一组对象，数组名在大多数表达式中会退化为指向首元素的指针，但 `sizeof(array)`、`&array` 和字符串字面量等场景必须单独分析。

```c
void inspect(uint8_t data[16])
{
    // 形参中的 data 实际上是 uint8_t *，这里无法得到调用方数组长度。
    printf("%zu\n", sizeof(data));
}
```

二级指针常用于修改调用者持有的指针、动态分配输出对象，以及管理指针数组。

```c
bool buffer_create(uint8_t **out, size_t size)
{
    if (out == NULL || size == 0U) {
        return false;
    }
    *out = malloc(size);
    return *out != NULL;
}
```

### 实操

1. 写 `swap_int(int *a, int *b)`，处理空指针。
2. 写 `array_reverse(int *data, size_t len)`，测试长度为 0、1、偶数和奇数。
3. 不调用 `strlen`，写 `my_strlen(const char *s)`。
4. 写一个函数，通过二级指针分配缓冲区；释放后立即置 `NULL`。
5. 在纸上画出 `char *argv[]`、`char **argv` 和二维数组的差别。

## Day 2：内存布局、生命周期与动态内存

### 程序内存区域

| 区域 | 常见内容 | 生命周期/特征 |
|---|---|---|
| 代码段 `.text` | 机器指令 | 通常只读，存于 Flash |
| 只读数据 `.rodata` | 字符串字面量、只读常量 | 通常存于 Flash |
| 已初始化数据 `.data` | 非零初始化的全局/静态变量 | 启动时从 Flash 复制到 RAM |
| 未初始化数据 `.bss` | 未显式初始化或零初始化的全局/静态变量 | 启动时清零，不必把大量零存入固件 |
| 栈 stack | 局部变量、参数、返回地址、保存的寄存器 | 随函数调用自动分配和回收 |
| 堆 heap | `malloc/calloc/realloc` 获得的对象 | 手动管理，可能碎片化 |

在 MCU 中，`.data` 的初值通常存于 Flash，启动代码在进入 `main()` 前将其复制到 SRAM；`.bss` 由启动代码清零。栈和堆通常共享有限的 SRAM，因此要从链接脚本和 map 文件确认边界，而不是只凭 PC 经验判断。

### 常见错误

- 栈上大数组导致栈溢出。
- 越界写破坏相邻变量、返回地址或 RTOS 任务控制块。
- `malloc` 后忘记 `free`，形成泄漏。
- `free` 后继续访问，形成 use-after-free。
- 重复 `free` 或释放非堆地址。
- 高频、不同尺寸动态分配造成堆碎片，实时任务最坏执行时间不可控。

嵌入式项目常优先使用静态分配、固定大小内存池、环形缓冲区；并不是说动态内存绝对不能用，而是要证明分配时机、失败处理、碎片风险和实时性均可接受。

### `memcpy`、`memset` 与字符串函数

- `memcpy(dst, src, n)` 复制原始字节，源和目标重叠时行为未定义；重叠应使用 `memmove`。
- `memset(ptr, 0, n)` 按字节填充；`memset(array, 1, sizeof(array))` 不会把整型数组每个元素设为整数 1。
- `strlen` 不包含结尾 `\0`，前提是输入一定存在终止符。
- `strcpy` 不知道目标容量，实际项目应显式检查长度或采用带容量的封装。

### 实操

1. 写固定容量环形缓冲区，接口包含 `init/push/pop/size/is_full`。
2. 使用 AddressSanitizer 在 PC 上观察越界、use-after-free 和 double-free；MCU 端理解相同问题为何更难定位。
3. 生成一次 STM32 工程的 `.map` 文件，找到 `.text/.data/.bss` 大小。
4. 声明一个 20 KB 的局部数组和一个 20 KB 的静态数组，对比 map 文件和运行结果。

## Day 3：`struct`、`union`、`enum`、对齐与字节序

### 结构体对齐

```c
typedef struct
{
    uint8_t  id;
    uint16_t speed;
    float    position;
} Motor;
```

在常见 32 位 ARM ABI 下，它通常布局为：

| 字段 | 偏移 | 大小 |
|---|---:|---:|
| `id` | 0 | 1 |
| padding | 1 | 1 |
| `speed` | 2 | 2 |
| `position` | 4 | 4 |

因此常见结果是 `sizeof(Motor) == 8`，但最终应以目标编译器、ABI、成员类型和编译选项为准。结构体整体大小通常补齐到其最大对齐要求的整数倍，便于结构体数组中的每个元素都正确对齐。

可以通过调整成员顺序减少 padding，但不要随意使用 packed 作为“优化”。非对齐访问在某些内核上会变慢，在另一些配置下会触发 fault；packed 还会把编译器布局细节带进通信协议。

### 不要直接发送结构体

直接 `HAL_UART_Transmit(..., (uint8_t *)&motor, sizeof(motor), ...)` 存在：

- padding 字节未定义或泄漏旧数据。
- 发送端与接收端的对齐规则可能不同。
- 多字节整数的大小端不同。
- `float` 格式、精度或解释方式不明确。
- 协议难以版本化，新增字段会破坏兼容性。

更好的方法是显式序列化：定义字段顺序、字节数、符号、缩放、大小端、版本、长度和校验。

```c
static void write_u16_le(uint8_t *dst, uint16_t value)
{
    dst[0] = (uint8_t)(value & 0xFFU);
    dst[1] = (uint8_t)((value >> 8U) & 0xFFU);
}
```

### `union` 与 `enum`

- `union` 的成员共享同一块内存，大小至少能容纳最大成员，并满足最严格的对齐。
- 联合体适合表达“同一存储的不同解释”或带标签的变体，但不要用未记录当前类型的 union 制造隐蔽错误。
- `enum` 提升状态和错误码的可读性；其底层大小可能受编译器影响，所以也不应直接作为跨平台线协议字段。

### 实操

1. 使用 `sizeof` 和 `offsetof` 打印 `Motor` 每个成员的偏移。
2. 调整字段顺序，比较结构体大小。
3. 写 `motor_encode()` 和 `motor_decode()`，协议固定为：帧头、版本、长度、ID、转速、位置定点值、CRC。
4. 在 PC 端为编解码函数写往返测试和非法长度测试。
5. 通过内存窗口观察 `0x12345678` 的字节排列，判断目标平台大小端。

## Day 4：`const`、`static`、`volatile` 与作用域

### `const`

```c
const uint8_t *p1;       // 指向只读数据的指针，可修改 p1
uint8_t *const p2 = buf; // 常量指针，不可修改 p2，可修改所指数据
const uint8_t *const p3 = buf;
```

`const` 主要是类型约束和接口承诺，不等价于“必然放入 ROM”。把本来定义为可写的对象通过去掉 `const` 后修改，可能在某些情况下可行，但破坏接口约束；修改真正定义为 const 的对象则是未定义行为。

### `static`

- 函数内 `static` 局部变量：静态存储期，只初始化一次，但作用域仍在函数内。
- 文件作用域 `static` 变量/函数：内部链接，只在当前翻译单元可见，适合隐藏模块实现。
- 不加 `static` 的全局函数/变量通常具有外部链接，需要通过头文件审慎暴露。

### `volatile`

`volatile` 告诉编译器：该对象可能被当前执行流看不到的因素改变，每次访问都应按抽象机要求实际发生。典型场景：

- 内存映射外设寄存器。
- 中断和主循环之间共享的简单标志。
- 某些由 DMA 或硬件更新的内存位置。

`volatile` **不保证原子性、不提供互斥、不建立完整的线程间同步顺序**。在 RTOS 多任务或多核程序中，应使用临界区、原子操作或 RTOS 同步原语。

```c
static volatile bool g_uart_rx_done;

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    g_uart_rx_done = true;
}
```

还要追问：这个 `bool` 的读写在当前 Cortex-M 上是否单指令完成？主循环清零与 ISR 置位是否可能丢事件？如果可能连续到达多个事件，就应该使用计数器、环形缓冲区或 queue，而不是单个布尔标志。

### 实操

1. 写 `motor.c/motor.h`，内部状态和辅助函数用 `static` 隐藏，只暴露最小接口。
2. 分别用 `const uint8_t *`、`uint8_t *const` 编译几段会失败的代码，理解约束位置。

4. 设计“ISR 更新计数，主循环读取并清零”的安全方式，说明临界区范围。

## Day 5：位运算、寄存器、宏与函数指针

### 位运算

```c
#define BIT(n) (1UL << (n))

reg |= BIT(3);          // 置位
reg &= ~BIT(3);         // 清零
reg ^= BIT(3);          // 翻转
bool set = (reg & BIT(3)) != 0U;

reg = (reg & ~MASK) | ((value << SHIFT) & MASK); // 更新字段，不破坏其他位
```

需要注意整数提升、符号扩展、移位范围和常量类型。对 32 位寄存器优先使用无符号常量，如 `1UL`；右移有符号负数的行为具有实现相关性。

### 安全宏

```c
#define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))
#define MAX(a, b) (((a) > (b)) ? (a) : (b))
```

`MAX(i++, j++)` 会产生副作用重复求值。能用 `static inline` 函数时通常更容易获得类型检查和调试体验。多语句宏使用 `do { ... } while (0)` 包裹，并为参数和整体表达式加括号。

### 函数指针与回调

```c
typedef void (*rx_callback_t)(const uint8_t *data, size_t len, void *context);

typedef struct
{
    rx_callback_t on_receive;
    void *context;
} UartListener;
```

回调可以把硬件驱动与上层业务解耦。`context` 让同一个回调函数服务多个实例，类似 C 语言中的简化对象上下文。必须明确回调运行在中断还是任务上下文，因为这决定了能否阻塞、能调用哪些 API、执行时间上限是多少。

### 实操

1. 写 `FIELD_SET/GET` 或等价 inline 函数，处理一个 32 位模拟寄存器。
2. 从参考手册任选一个 GPIO/定时器寄存器，手算设置某字段的掩码和值。
3. 写基于函数指针的命令表：`help/status/set_speed`，避免长串 `if-else`。
4. 编写一个具有副作用的宏失败案例，再改为 inline 函数。

## Day 6：编译、链接、启动流程与本周综合题

### 从源码到烧录

1. 预处理：展开 `#include`、宏和条件编译，生成翻译单元。
2. 编译：进行语义检查和优化，生成汇编或目标代码。
3. 汇编：生成包含机器码、符号和重定位信息的 `.o` 文件。
4. 链接：按照链接脚本合并目标文件和库，解析符号、放置 section，生成 ELF。
5. `objcopy`：从 ELF 提取 HEX/BIN 等烧录格式。
6. 调试器/Bootloader：将镜像写入 Flash，复位后从向量表和启动代码进入程序。

典型 MCU 启动过程：加载初始 MSP → 进入 `Reset_Handler` → 设置时钟/运行库环境 → 复制 `.data` → 清零 `.bss` → 调用系统初始化 → 调用 `main()`。中断向量表保存初始栈顶和各异常/中断入口地址。

### 常见错误分类

| 阶段 | 常见现象 | 优先检查 |
|---|---|---|
| 编译 | 类型错误、找不到声明 | 头文件、宏、语言规则 |
| 链接 | undefined reference | 实现是否加入 target、库顺序、C/C++ 符号名 |
| 链接 | multiple definition | 头文件中错误定义全局对象 |
| 下载 | 校验/连接失败 | 供电、SWD、复位、读保护、时钟 |
| 运行 | HardFault/跑飞 | 栈、非法地址、未对齐、函数指针、时钟配置 |


## Day 1：GPIO、电气属性与时钟

### 原理

GPIO 通常包括输入缓冲、输出驱动、上下拉、电气速度和复用选择。引脚只有在 GPIO 端口和目标外设时钟开启、模式和复用映射正确后才会工作。

| 模式 | 典型用途 | 注意点 |
|---|---|---|
| 浮空输入 | 外部电路已提供稳定电平 | 不可悬空，否则容易抖动 |
| 上拉/下拉输入 | 按键、默认状态 | 内部上下拉阻值较大，查 datasheet |
| 推挽输出 | LED、数字控制 | 能主动输出高低电平 |
| 开漏输出 | I2C、线与、多设备共享 | 高电平依赖上拉电阻 |
| 复用功能 | UART/SPI/CAN/定时器 | AF 编号和引脚映射必须匹配 |
| 模拟模式 | ADC、降低数字输入功耗 | 关闭数字输入缓冲 |

GPIO 的 speed 通常表示输出边沿驱动速度，不是软件翻转频率。速度越高，边沿更快，但 EMI、串扰和功耗也可能更高，应满足信号要求即可。

## Day 2：外部中断、NVIC 与消抖

### 中断链路

以按键 EXTI 为例：引脚电平变化 → EXTI 边沿检测与挂起位 → NVIC 判断使能和优先级 → CPU 保存现场并跳转 ISR → 清除挂起标志 → 返回被打断代码。

ISR 设计原则：

- 尽可能短，只做时间敏感的采样、清标志和通知。
- 不执行长时间循环、日志格式化、阻塞等待和动态内存分配。
- 与主循环/任务共享数据时分析原子性和竞态。
- 若事件不可丢失，不使用单一 bool 表达多个到达事件。

按键会产生机械抖动。可以采用定时采样状态机：检测边沿后记录时间，经过 10～30 ms 再确认稳定电平；不要在 ISR 中 `HAL_Delay(20)`。

### NVIC 优先级

在 Cortex-M 中，数值越小通常表示抢占优先级越高。优先级位数由实现决定，还要理解抢占优先级和子优先级分组。使用 FreeRTOS 后，调用 `...FromISR` API 的中断优先级必须满足端口对 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的限制。

### 实操

1. 使用 EXTI 捕获按键边沿，ISR 只记录时间戳和增加事件计数。
2. 在主循环实现非阻塞消抖状态机。
3. 配置两个中断源，通过 GPIO 翻转和逻辑分析仪观察抢占关系。
4. 人为忘记清中断标志，观察重复进入 ISR 的现象，再恢复。

## Day 3：通用定时器与时间基准

### 基本关系

定时器计数频率通常由定时器输入时钟、预分频器 PSC 和自动重装值 ARR 决定：

```text
f_counter = f_timer / (PSC + 1)
f_update  = f_counter / (ARR + 1)
T_update  = 1 / f_update
```

需要查清 APB 分频对定时器时钟的影响；很多 STM32 系列在 APB 预分频不为 1 时，定时器内核时钟可能是 APB 时钟的 2 倍，但不要脱离具体芯片系列背结论。

常用模式：

- 基本定时/周期中断。
- 输出比较：计数器与比较寄存器相等时产生事件。
- 输入捕获：在输入边沿锁存计数值，可测频率、脉宽和编码器信号。
- PWM 输出。
- 编码器接口模式。

### 非阻塞调度

与 `HAL_Delay` 相比，基于系统 tick 或硬件定时器的状态机允许多个任务协同推进：

```c
if ((uint32_t)(now - last_run) >= period_ms) {
    last_run += period_ms;
    control_update();
}
```

无符号减法写法能在满足时间跨度限制时自然处理 tick 回绕。

### 实操

1. 产生精确 1 kHz 更新中断，用 GPIO 翻转测得实际频率。
2. 不用阻塞延时，同时运行 1 Hz LED、100 Hz 采样和 1 kHz 控制占位函数。
3. 用输入捕获测量外部 PWM 的频率和占空比。
4. 可选：配置编码器模式，读取正反转计数并处理计数器回绕。

## Day 4：PWM、电机/舵机控制接口

### 基本关系

边沿对齐向上计数 PWM 的典型关系：

```text

duty  ≈ CCR / (ARR + 1)
```

## Day 5：UART、阻塞/中断接收与协议状态机

### UART 帧与波特率

典型 UART 使用起始位、5～9 个数据位、可选校验位和停止位。`115200 8N1` 表示 115200 bit/s、8 数据位、无校验、1 停止位；每传 1 个有效字节通常占 10 bit，因此理论有效载荷上限约为 11.52 KB/s，还未扣除上层协议开销。

UART 是字节流，不天然提供消息边界。一次接收回调可能只得到半帧、恰好一帧或多帧，因此协议层必须通过帧头、长度、转义/编码和校验恢复边界。

### 三种接收方式

| 方式 | 优点 | 风险/适用场景 |
|---|---|---|
| 阻塞轮询 | 简单 | 占用 CPU、影响实时性，适合启动阶段或极简 Demo |
| 字节中断 | 响应及时 | 高频中断开销大，ISR 只应入队 |
| DMA + IDLE | CPU 开销低，适合不定长数据 | 需处理缓冲区、DMA 位置、回绕和并发 |

### 实操

1. 实现阻塞发送，只用于启动日志。
2. 实现中断逐字节接收：ISR 将字节写入环形缓冲区，主循环解析第一周协议。
3. 处理噪声、粘连帧、拆分帧、CRC 错误和超长长度。
4. 测试高频连续发送，记录丢包点和 CPU 占用变化。
5. 用逻辑分析仪解码 UART，确认波特率、数据位和帧内容。

## Day 1：DMA、循环缓冲与 UART IDLE

### 工作过程

UART 收到字节后，接收数据寄存器产生 DMA request；DMA 按配置把数据从外设地址搬到 SRAM，并更新计数。CPU 不再逐字节执行搬运，只在半传输、传输完成、空闲线或错误等事件上介入。

配置时要明确：

- 源/目标地址，外设地址是否固定，内存地址是否递增。
- 数据宽度和对齐。
- normal 或 circular 模式。
- 传输长度、优先级、FIFO/burst（若芯片支持）。
- 谁产生 request，request 映射是否正确。
- DMA 与 CPU 同时访问缓冲区时的所有权。
- 带数据缓存的 Cortex-M7 等平台上，cache clean/invalidate 和内存区域属性。

### UART DMA + IDLE

IDLE 表示接收线上在至少一个帧时间内没有新数据，可用来提示“当前已有一批数据”，但它并不等于业务协议帧结束。正确做法仍是：获取 DMA 新增字节范围 → 推入流式解析器 → 依据协议长度和 CRC 组帧。

### 双缓冲/循环缓冲思想

生产者 DMA 正在写入时，消费者不能随意处理尚未完成的数据。常见方案：

- ping-pong 双缓冲：DMA 写 A 时 CPU 处理 B，然后交换。
- circular DMA：根据 DMA 剩余计数计算新写入位置，处理新增区间和回绕。
- 半传输/全传输回调：每次处理固定半块。

### 实操

1. 将第二周 UART 中断接收改为 DMA + IDLE。
2. PC 随机按 1～100 字节分块发送连续帧，验证拆包和粘包。
3. 打开半传输/全传输事件，画出 DMA 写指针和软件读指针变化。
4. 统计 1 分钟内字节数、帧数、CRC 错误、溢出和最大缓冲占用。

## Day 2：ADC、采样理论与 DMA

### 关键参数

- 分辨率：理想 N 位 ADC 将输入范围分成约 `2^N` 个码。
- 参考电压：换算电压必须知道 VDDA/VREF，而不是默认永远精确 3.3 V。
- 采样时间：采样保持电容需要通过信号源阻抗充电；源阻抗高时采样时间过短会产生偏差。
- 转换时间与采样率：由 ADC 时钟、采样周期和转换周期共同决定。
- 量化、噪声、偏置和非线性：多次平均只能降低部分随机噪声，不能消除系统误差。

不要在没有前端保护和分压的情况下让 ADC 引脚超出允许电压。测电位器时确认共地；测电流、编码器模拟量等信号时理解前端电路。

### 定时触发 + DMA

稳定采样应优先让定时器 TRGO 触发 ADC，再由 DMA 搬运结果，而不是主循环中“尽快轮询”。这样采样间隔由硬件确定，jitter 更小，便于数字滤波和控制。

### 实操

1. 单通道 ADC 读取电位器，换算原始码与电压。
2. 定时器以 1 kHz 触发 ADC，DMA circular 模式采集 128 或 256 点。
3. 实现均值、滑动平均和一阶低通，比较延迟与噪声。
4. 多通道 scan + DMA，明确缓冲区中通道交错顺序。
5. 串口输出原始值、滤波值、最小值、最大值和均方根噪声。

## Day 3：I2C

### 总线特点

I2C 使用 SDA、SCL 两根开漏线，多设备通过地址共享总线。主要概念：START、STOP、7/10 位地址、读写位、ACK/NACK、clock stretching、重复起始和仲裁。

开漏只主动拉低，总线高电平由上拉电阻产生。上拉过大导致上升慢，高速下无法满足时序；过小则低电平电流和功耗增大。总线电容、线长、设备数量和目标速率共同决定上拉选择。

### 常见“寄存器读取”流程

```text
START → Address+W → Register → Repeated START → Address+R → Data... → NACK → STOP
```

设备地址最常见的混乱是：datasheet 给 7 位地址，某些文档展示的是包含 R/W 位的 8 位值，而 HAL API 可能要求左移后的形式。必须查所用库的接口约定，不凭经验混用。

### 实操

1. 接入一个 I2C 传感器，先读 `WHO_AM_I` 或芯片 ID。
2. 用逻辑分析仪确认地址、ACK、寄存器和数据。
3. 拔掉设备或用错误地址，记录 NACK 和超时处理。
4. 设计总线恢复：SDA 被从设备拉低时，通过 SCL 脉冲和外设重置恢复；具体做法依芯片和设备手册验证。
5. 驱动接口分层为 `bus_read/write` 与 `sensor_init/read`。

## Day 4：SPI

### 总线特点

SPI 常见信号为 SCK、MOSI、MISO、CS。它通常是同步、全双工、无统一设备寻址和 ACK 的主从通信；每个设备协议由其 datasheet 决定。

CPOL 决定空闲时钟电平，CPHA 决定在哪个边沿采样/改变数据。主从的 mode 不一致会导致位移、数据错误或在低速偶然可用。还要确认 MSB/LSB first、字长、最大时钟和 CS 时序。

“读取”时主机也必须发送 dummy 字节来产生时钟；“写入”时同时也会移入数据，只是软件可能忽略。

### 实操

1. 使用 SPI 传感器、Flash 或回环连接完成收发。
2. 分别试错 CPOL/CPHA，用逻辑分析仪观察错误模式。
3. 实现片选控制、寄存器读写和超时错误码。
4. 较大数据块使用 DMA，测量轮询与 DMA 的 CPU 时间差异。
5. 多设备共享 SCK/MOSI/MISO 时，为每个设备独立管理 CS 和模式切换。

## Day 5：CAN

### 为什么机器人常用 CAN

CAN 是多主、差分、面向消息的总线，具有仲裁、错误检测、自动重发和故障隔离机制，适合电机驱动器、传感器和分布式控制节点。经典 CAN 数据字段最多 8 字节；CAN FD 可提供更长载荷和数据阶段更高速率，但是否支持取决于控制器和收发器。

必须区分：

- CAN 控制器在 MCU 内，处理帧、仲裁、过滤和错误计数。
- CAN 收发器连接控制器 TX/RX 与差分 CAN_H/CAN_L。
- 总线两端通常各有终端电阻；不要在每个节点都加终端。
- 标识符代表消息优先级/含义，不等同于传统网络的目标地址。

### 仲裁与错误

CAN 通过显性位覆盖隐性位进行无破坏仲裁，数值更小的标识符通常优先级更高。节点发送时也监视总线，发现自己发送隐性而总线为显性，就停止本次竞争，等待重发。

需要了解 bit timing 的名词：时钟分频、time quantum、同步段、传播段、相位段和采样点。实际配置可用厂商工具辅助，但要能解释两个节点波特率和采样点不匹配为什么无法通信。

错误状态包括 error active、error passive、bus-off。bus-off 后是否自动恢复、何时恢复必须由系统安全策略决定，不能只为了“恢复通信”盲目自动重启。

### 应用层设计

8 字节很宝贵，应显式定义缩放和端序。例如电机状态：

| Byte | 字段 | 说明 |
|---|---|---|
| 0～1 | position | `int16`，0.01 rad |
| 2～3 | velocity | `int16`，0.01 rad/s |
| 4～5 | current | `int16`，0.01 A |
| 6 | status | 位字段 |
| 7 | sequence | 序号/丢帧检测 |

同时定义发送周期、超时、有效范围、错误值和版本兼容策略。

### 实操

1. 两节点或 USB-CAN 互发心跳和状态帧。
2. 设置接收过滤器，只接收目标 ID 范围。
3. 设计 1 kHz 控制命令与 100 Hz 状态反馈，计算总线负载；若硬件不足，可先用脚本/表格估算。
4. 拔线或移除终端，观察错误计数和 bus-off 行为。
5. 实现通信超时状态机：正常 → 数据陈旧 → 安全停车 → 等待恢复。

## Day 1：Task、调度器、优先级与周期任务

### 任务状态

- Running：当前正在 CPU 上执行。
- Ready：具备运行条件，等待调度。
- Blocked：等待延时、队列、信号量或通知。
- Suspended：被显式挂起，不参与调度。

单核 MCU 同一时刻只有一个任务真正运行。并发来自快速切换和中断，不能把任务误认为“每个任务占一个核”。高优先级任务 Ready 时，抢占式调度器通常会让其先运行；同优先级任务是否时间片轮转取决于配置。

### 延时与周期

`vTaskDelay()` 是相对延时，任务执行时间会叠加到周期中；稳定周期任务优先使用 `vTaskDelayUntil()`。但高精度 1 kHz 电机控制是否适合由 RTOS tick 唤醒，要根据 tick 频率、jitter 要求和 MCU 负载决定；更严格的控制环可由硬件定时器中断触发/通知任务。

### 优先级设计

优先级依据截止时间、周期、最坏执行时间和后果分配，不依据“业务看起来重要”。一个可讨论的起点：

| 任务 | 周期/触发 | 建议关注点 |
|---|---|---|
| Control Task | 1 kHz 定时触发 | 最高实时性，不阻塞日志 |
| Communication RX | DMA/队列事件 | 及时清空缓冲并解析 |
| Sensor Task | 100 Hz | I/O 超时不能拖住控制 |
| Status TX | 10～100 Hz | 可丢弃旧状态，避免堵塞 |
| Logger | 后台 | 最低优先级、限流 |

### 实操

1. 创建 LED、通信、控制占位三个任务，打印运行时间戳。
2. 对比 `vTaskDelay` 与 `vTaskDelayUntil` 的周期漂移。

4. 使用 GPIO 在任务入口/出口翻转，测量调度周期和 jitter。

## Day 2：Queue、任务通知与数据所有权

### Queue 的语义

FreeRTOS queue 默认按值复制固定大小的 item。它同时提供数据传递和同步：队列空时消费者阻塞，队列满时生产者可阻塞或失败。大对象不适合频繁复制，可传递指向固定内存池对象的指针，但必须明确谁拥有对象、何时归还，防止悬空和重复使用。

### 选择工具

| 需求 | 首选思路 |
|---|---|
| 传递结构化小消息 | Queue |
| ISR 唤醒一个任务、传简单事件/计数 | Direct-to-task notification |
| 字节流/消息缓冲 | Stream buffer / message buffer，结合版本能力 |
| 只保留最新状态 | 长度 1 queue + overwrite 或受保护的快照 |

控制命令与传感器数据要区分“每条都必须处理”还是“只要最新值”。例如日志不能阻塞控制；控制任务若拿到陈旧 setpoint，应按时间戳拒绝或进入安全状态。

### 实操

1. UART 解析任务将 `Command` 结构体放入 queue，控制任务阻塞等待。
2. 状态 queue 只保留最新值，通信任务以固定频率发送。
3. 测试 queue 满：选择丢最新、丢最旧、阻塞或报告故障，并解释取舍。
4. 将大块传感器数据改为固定内存池 + 指针 queue，记录所有权转移。

## Day 3：Semaphore、Mutex、临界区与优先级反转

### 概念区分

| 工具 | 主要用途 | 是否有所有者 | 典型特性 |
|---|---|---|---|
| Binary semaphore | 事件同步 | 无 | ISR/任务 give，任务 take |
| Counting semaphore | 资源计数或累计事件 | 无 | 计数表示可用资源/待处理事件 |
| Mutex | 保护共享资源 | 有 | 通常支持优先级继承，持有者释放 |
| Critical section | 极短的原子访问 | 不按普通锁理解 | 屏蔽调度或部分中断，必须极短 |

不要用 mutex 表示“事件来了”，也不要从 ISR 获取普通 mutex。ISR 通知任务使用 `...FromISR` API，并在需要时请求退出 ISR 后立即切换到被唤醒的高优先级任务。

### 优先级反转

低优先级任务持有 mutex，高优先级任务等待该 mutex，中优先级任务持续抢占低优先级任务，导致高优先级任务间接被中优先级任务阻塞。优先级继承会临时提高 mutex 持有者优先级，使其尽快释放锁，但它不是所有设计问题的万能解法。

降低风险的方法：缩短锁持有时间、不在锁内阻塞 I/O、按统一顺序获取多个锁、通过单一所有者任务串行访问外设、减少共享可变状态。

### 实操

1. 多任务共享 UART TX，使用 mutex 观察日志帧是否仍交错；进一步改成单独 Logger Task + queue。
2. 构造低/中/高三个任务复现优先级反转，观察启用 mutex 优先级继承后的变化。
3. 构造 AB/BA 两锁死锁，再通过固定加锁顺序消除。
4. 对 32/64 位共享统计量设计最小临界区，测量临界区时长。

## Day 4：ISR 与 Task 协作、Event Group 与 Software Timer

### ISR 到任务

推荐模式：ISR 只清硬件标志、捕获必要数据，并通过 task notification、queue 或 semaphore 唤醒任务；任务完成解析、滤波、状态机和日志。

```c
void DMA_IRQHandler(void)
{
    BaseType_t higher_priority_woken = pdFALSE;
    /* 清中断、记录 DMA 位置 */
    vTaskNotifyGiveFromISR(rx_task_handle, &higher_priority_woken);
    portYIELD_FROM_ISR(higher_priority_woken);
}
```

具体 HAL 工程中常由 HAL IRQHandler 清标志并调用回调，应遵循当前库的调用链，避免重复清除或遗漏标志。

### Event Group

Event group 适合等待多个布尔条件，如 `SENSOR_READY | CAN_READY | CONFIG_LOADED`，可以等待任一位或全部位。它不携带详细数据，也不适合用同一位累计多次事件；重复 set 同一 bit 仍只是 1。

### Software Timer

软件定时器回调由 timer service task 执行，不是硬件 ISR。回调应短小且不阻塞，否则会拖延其他软件定时器。它适合低频超时、状态维护和延后动作，不替代高精度硬件定时器。

### 实操

1. UART DMA/IDLE ISR 用 task notification 唤醒解析任务。
2. 系统启动时用 event group 等待传感器、CAN、配置三项就绪。
3. 软件定时器实现通信看门狗；超时只投递安全事件，不在回调里做复杂处理。
4. 比较 queue、semaphore、notification 唤醒延迟与语义。

## Day 5：栈、堆、故障诊断、看门狗与安全状态

### 任务栈

每个任务有独立栈，保存局部变量、调用链和上下文。栈大小单位在不同 API/端口中可能是 word 而非 byte，必须查当前版本定义。调试手段：

- `uxTaskGetStackHighWaterMark()` 观察历史最小余量。
- 开启 stack overflow hook。
- 检查 map 文件、RTOS 对象列表和 fault 寄存器。
- 避免任务栈上的大数组、深递归和不可控格式化函数。

### FreeRTOS 堆

了解 `heap_1`～`heap_5` 的基本取舍即可：是否支持 free、是否合并相邻空闲块、是否管理多个不连续区域。项目究竟使用哪种实现要从配置和源码确认。生产项目应检查任务/队列创建返回值和 malloc failed hook。

### 看门狗不是“定时喂一下”

若只有一个低优先级任务无条件喂狗，即使控制任务死锁，系统也可能继续喂狗。更合理的 supervisor：各关键任务在完成本周期健康检查后更新心跳；监督任务验证所有必要心跳、调度延迟和错误状态后才喂硬件看门狗。

### 故障安全状态

机器人底层应定义：通信超时、传感器无效、过流/过温、任务失联、bus-off、协议失步时的安全输出。安全状态可能是 PWM 归零、受控减速、保持制动或断使能，必须结合真实硬件风险确定，不能统一假设“归零总是安全”。

### 实操

1. 故意减小任务栈，触发检测并定位。
2. 模拟 queue 创建失败，验证启动过程不会继续使用空句柄。
3. 让通信任务停止心跳，监督任务进入安全状态并停止喂狗。
4. 在 HardFault handler 中记录 CFSR/HFSR、堆栈指针和可能的 PC/LR，了解如何从 map/ELF 定位。
5. 建立错误码、错误计数和最近一次错误时间，而非只有一行日志。

## Day 6：FreeRTOS 综合架构与面试演练

### 综合项目：ROS/PC + STM32 控制节点

```text
ROS/PC Command Node
        │ UART DMA 或 CAN
        ▼
ISR/DMA ──notify──> Communication RX Task
                         │ Command Queue
                         ▼
Timer ISR ──notify──> Control Task (1 kHz) ──> PWM/Motor Driver
                         ▲                         │
                         │ latest state            ▼
                  Encoder/ADC DMA             Motor/Plant
                         │                         │
                         └──────── feedback ───────┘

Sensor Task ──> State Queue ──> Communication TX Task ──> ROS/PC
All critical tasks ──> Health Flags ──> Supervisor ──> Watchdog/Safe State
Logger Queue ──> Low-priority Logger Task
```

### 任务设计建议

| 任务 | 输入 | 输出 | 阻塞点 | 超时/错误策略 |
|---|---|---|---|---|
| RX Task | DMA 新数据通知 | Command Queue | 等通知 | CRC/长度错误计数，持续噪声时降级 |
| Control Task | 定时通知、最新命令、反馈 | PWM、控制状态 | 等周期通知 | 命令过期则安全减速/停机 |
| Sensor Task | 周期或 DRDY | 传感器快照 | 延时/通知 | 超时标记 invalid，不伪造旧数据为新值 |
| TX Task | 状态 queue | UART/CAN | 等 queue | 限流，必要时丢弃旧状态 |
| Supervisor | 各任务心跳、错误 | 看门狗/状态机 | 周期运行 | 分级故障与可观测复位原因 |
| Logger | 日志 queue | UART/SWO/存储 | 等 queue | 队列满时丢低等级日志 |

### 控制链最少实现

- PC 发送目标速度与序号。
- STM32 验证帧、范围和命令新鲜度。
- 1 kHz 控制任务读取编码器/模拟反馈，先实现 P 或 PI 控制和输出限幅。
- 无真实电机时，用简单一阶离散模型模拟 plant，重点验证任务和协议架构。
- 100 Hz 返回目标值、反馈值、输出值、错误状态和时间戳。
- 命令超过设定时间未更新，进入安全状态。

### 面试时如何讲项目

按以下顺序，控制在 3～5 分钟：

1. 需求：ROS 下发目标，MCU 保证确定性控制和硬件接口。
2. 架构：通信、控制、采集、状态、监控任务的边界。
3. 实时性：控制周期、优先级、最坏执行时间和 jitter 测量。
4. 通信：DMA、环形缓冲、协议、序号、CRC、超时和带宽。
5. 并发：queue/notification/mutex 的选择和数据所有权。
6. 安全：命令超时、传感器无效、看门狗和安全输出。
7. 验证：压力测试、故障注入、波形和日志证据。
