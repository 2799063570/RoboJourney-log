# 机器人算法岗位学习手册

> 依据 [[机器人算法岗位学习复习计划]] 的 8 周、48 个学习日安排展开。主线是**机械臂运动规划与机器人算法**，以 C++ 和 ROS 工程能力为底座，连接运动学、视觉、导航与项目验证。
>

## 1. 第 1 周：C++、Linux 与工程基础

**本周目标：** 写出的模块有清楚的所有权、线程边界、构建依赖与错误处理，能通过日志和调试工具定位问题。

材料：[[../CPP/C++现代用法]]、[[../CPP/并发编程]]、[[../CPP/程序开发知识]]、[[../CPP/调试方法与机器人项目实战]]、[[../CPP/数据结构学习手册]]。

### W1D1：对象生命周期、RAII 与智能指针

**知识讲解：** 对象的构造、复制、移动和析构决定资源何时取得与释放。RAII 把资源管理绑定到对象生命周期，使异常、提前返回等路径也能自动清理。资源包括内存、文件、锁与设备连接。

- `unique_ptr` 表示唯一所有权，可以移动但不能复制。
- `shared_ptr` 表示共享所有权，最后一个拥有者离开后释放对象；循环拥有关系可能泄漏。
- `weak_ptr` 观察共享对象但不增加强引用，访问前用 `lock()` 判断对象是否仍存在。
- 移动不是“自动零拷贝”，具体成本由类型决定；移动后源对象通常保持有效但状态不应任意假设。
- 继承层次通过基类指针删除派生对象时，基类析构通常需要是虚函数。

**实践步骤：** 写一个模拟 SDK 连接类，构造时建立资源、析构时释放，禁止复制，支持需要的移动；用普通返回与抛异常两条路径观察析构日志；再画出规划器、模型与设备之间的所有权关系。

**验收：** 无重复释放，无遗漏清理；能解释哪个模块拥有资源、哪个模块只借用，以及引用何时失效。

**Q-W1D1-1：unique_ptr 和 shared_ptr 如何选择？**

**参考回答：** 默认采用唯一所有权，优先 `unique_ptr`，让释放责任清晰。多个模块确实需要共同延长对象生命周期时才用 `shared_ptr`。观察关系或反向引用可用 `weak_ptr`。共享指针的计数管理不意味着被管理对象的成员访问也线程安全。

**Q-W1D1-2：RAII 比手动 new/delete 有什么优势？**

**参考回答：** 它把清理写在析构中，通过作用域退出统一处理正常、异常和提前返回路径，减少遗漏。比如锁守卫可以自动解锁。RAII 也要求明确所有权，不能把一个资源同时交给两个独立对象释放；析构还应避免传播异常。

### W1D2：STL、复杂度与迭代器失效

**知识讲解：** 选容器先看读写方式，再看顺序、内存与引用稳定性。轨迹点批量生成并按下标读取适合 `vector`，两端消费可考虑 `deque` 或环形缓冲，已知节点的转移可考虑 `list`。

| 容器 | 擅长 | 主要限制 |
|---|---|---|
| vector | 连续存储、随机访问、遍历 | 扩容会搬移；中间增删 O(n) |
| deque | 两端增删、随机访问 | 整体不保证连续；迭代器规则需核对 |
| list | 已知节点增删与转移 | 查位置 O(n)，节点开销较大 |
| unordered_map | 平均 O(1) 按键定位 | 不维护顺序，最坏可 O(n) |
| map | 有序键与范围访问 | 按键操作 O(log n) |

**实践步骤：** 用 `vector` 保存轨迹点，比较预留容量前后的扩容次数；分别实现保序删除与末尾覆盖删除；写一份修改容器时的引用有效性说明。不要通过解引用失效指针“验证”失效。

**验收：** 能解释 size/capacity、reserve/resize，以及一次追加的最坏成本与连续追加的摊还成本。

**Q-W1D2-1：为什么 vector::push_back 是摊还 O(1)？**

**参考回答：** 扩容单次可能搬移 O(n) 个元素，但在几何增长策略下，连续 n 次追加的累计搬移量为 O(n)，平均分摊每次 O(1)。这不是每次操作都恒定，控制线程中仍需考虑扩容带来的延迟峰值。

**Q-W1D2-2：vector 的指针什么时候失效？**

**参考回答：** 重新分配时，指向元素的全部指针、引用和迭代器失效；未重新分配时，插入或删除也会影响相关位置及之后的引用。避免长期缓存可能被移动的元素地址；容量可预估时提前 reserve，但预留容量不会增加元素数量。

### W1D3：线程、锁、条件变量与状态交换

**知识讲解：** 数据竞争是并发访问同一内存且至少一次写入、又没有适当同步。`mutex` 保护一组共享状态的不变量；条件变量用于等待状态变化；原子变量适合特定独立状态及经过设计的协议。

有界队列维护 `0 <= size <= capacity`。生产者等待“未满或已关闭”，消费者等待“非空或已关闭”。条件变量等待必须检查谓词，处理虚假唤醒；关闭时唤醒所有等待者。

**实践步骤：** 实现有超时与关闭操作的队列；启动生产者消费者，核对顺序和总数；演练队列满、等待超时、关闭空队列和关闭时仍有残留数据。明确关闭后的残留元素是否允许排空。

**验收：** 程序能够结束，等待没有漏唤醒；共享成员都有同步保护；临界区不执行网络 I/O 或长计算。

**Q-W1D3-1：为什么 condition_variable 要配合 while 或谓词？**

**参考回答：** 唤醒并不保证条件成立，可能是虚假唤醒，也可能在重新取得锁之前被别的线程改变。用谓词版本等待会在锁保护下反复检查真实状态。通知表示状态可能变化，不表示直接把资源交给某个线程。

**Q-W1D3-2：控制线程与通信线程怎么交换关节状态？**

**参考回答：** 首先明确要全部样本还是只要最新快照。低频快照可用短临界区复制，连续任务用有界队列；控制线程读取后还要检查采样时间与有效标志。对更严格时序要求可研究专用缓冲协议，但不能简单将一个标志改成 atomic 就宣称整体数据一致。

### W1D4：编译、链接、CMake 与 Linux 排障

**知识讲解：** 预处理展开头文件与宏，编译生成目标文件，链接解析跨文件符号，运行时再处理动态库加载。声明只告诉编译器接口，定义才提供实现。

在 CMake 中围绕 target 组织源文件与依赖：PRIVATE 只用于自身，PUBLIC 同时传播给消费者，INTERFACE 只向消费者传播。动态库部署还要考虑 ABI、搜索路径和依赖版本。

**实践步骤：** 建一个 `core` 库与 `demo` 可执行目标；故意删除定义、漏链接依赖、改变函数签名，记录各自报错；在 Linux 上用调试构建观察一次越界或崩溃的堆栈。调试工具练习链接到 [[../CPP/调试方法与机器人项目实战]]。

**验收：** 区分编译错误、链接错误与加载错误，能从首个相关报错追溯到目标、符号及库。

**Q-W1D4-1：头文件包含了，为什么仍然 undefined reference？**

**参考回答：** 包含头文件通常只提供声明，链接器还必须找到匹配定义。检查源文件是否加入 target、依赖库是否链接、签名与命名空间是否一致，以及库版本和 ABI。模板定义的位置也可能导致实例化缺失，应按错误符号定位。

**Q-W1D4-2：机器人节点突然崩溃，第一步怎么做？**

**参考回答：** 保存复现输入、日志、配置与代码版本，查看崩溃堆栈而不是先改参数。结合调试符号定位访问位置，再核查对象生命周期、下标、并发修改等原因。修复后用原始输入复现验证，并增加能够覆盖该故障的检查。

### W1D5：UDP、TCP、串口与协议边界

**知识讲解：** TCP 是有序字节流，没有应用消息边界，需要长度或分隔符分帧；UDP 保留数据报边界，但可能丢失、重复和乱序；串口也需要应用层帧结构和重同步。

建议状态帧显式包含版本、类型、发送者 ID、序号、采样时间、载荷长度、载荷和校验。不要直接发送 C++ 结构体内存，它可能受填充、字节序和类型宽度影响。跨机计算单向延迟需要可解释的时钟同步；本机超时可按接收时刻判断。

**实践步骤：** 编写不依赖网络的编码和解码函数；构造截断帧、错误长度、未知版本、重复序号、乱序帧；再在可用环境做 UDP 收发。关键命令与高频状态应采用不同可靠性策略。

**验收：** 解码前检查长度，非法帧不能修改控制状态；包中长度字段不能诱发越界；明确字节序、单位和序号回绕策略。

**Q-W1D5-1：UDP 没有 TCP 粘包，为什么还要长度字段？**

**参考回答：** UDP 自带数据报边界，但应用仍需要检查报文是否完整、版本是否兼容、载荷是否符合格式。长度有助于识别截断和格式错误，也便于复用协议。TCP 和串口还需通过长度等机制恢复消息边界，两者问题不同。

**Q-W1D5-2：15 Hz 状态协议怎么应对乱序和失联？**

**参考回答：** 接收端按发送者、序号和采样时间判断新旧，拒绝重复与过期状态，统计有效接收间隔。超过预设超时进入降级状态。15 Hz 约为每 66.7 ms 一次发送，但有效接收频率和控制频率要分别测量，旧状态不应无限延长使用。

### W1D6：手写题与工程化验证

**知识讲解：** 二分练区间不变量，Top K 练堆，LRU 练哈希表与双链表组合，生产者消费者练状态一致性。算法正确性、边界处理与接口语义同样重要。

**实践步骤：** 从四题选两题限时手写；用空输入、重复值、容量 0/1、非法 k 和关闭状态验证；补上复杂度及所有权说明。详细推导参见 [[../CPP/数据结构学习手册]]。

**验收：** 能在白板上解释状态变化；程序退出路径完整；不把平均、摊还和最坏复杂度混为一谈。

**Q-W1D6-1：LRU 为什么用哈希表加双链表？**

**参考回答：** 哈希表负责平均 O(1) 按键定位，双链表负责已知节点时 O(1) 移到最近使用位置及淘汰最旧节点。两者需同步维护，更新已有键不增加数量。总体通常平均 O(1)，不是哈希操作的最坏 O(1)。

**Q-W1D6-2：如何验证生产者消费者队列没有丢数据？**

**参考回答：** 给每个消息唯一序号，记录成功入队与成功出队集合，检查重复、遗漏和约定内的顺序，尤其覆盖满队列、超时及关闭。若接口允许拒绝入队，必须将拒绝数与丢失分开统计，不能把从未成功入队的消息算作内部丢失。

## 2. 第 2 周：ROS1、TF、MoveIt 与执行链

**本周目标：** 能从传感器、坐标系、规划请求一直追踪到控制器反馈，区分各层故障。

材料：[[../ROS/ROS1/ROS Learning]]、[[../ROS/ROS1/tf坐标变换]]、[[../ROS/MoveIt/教程/Moveit]]、[[../ROS/MoveIt/Trajectory Execution]]、[[../ROS/ROS1/aubo]]。

### W2D1：topic、service、action 与回调

**知识讲解：** topic 用于异步数据流，service 表达请求与响应，action 适合有过程反馈、可取消的长任务。回调进入队列后，需要 spinner 等执行机制处理；订阅到了不代表回调已按时运行。

ROS1 的单线程回调处理中，一个长回调可能拖慢其他回调。增加线程并不自动解决问题，还会引入共享状态竞争。请求处理、重计算与控制周期应明确职责。

**实践步骤：** 用模拟任务设计一个轨迹 action 的目标、反馈、结果和取消状态；记录消息采样、接收、回调开始与处理结束时间；将耗时计算从关键回调中移出，比较积压。

**验收：** 能区分通信成功、任务接受、任务运行和任务完成；解释取消后的停止流程。

**Q-W2D1-1：为什么轨迹执行使用 action 而不是普通 service？**

**参考回答：** 执行持续一段时间，需要反馈、结果与取消能力，action 的任务生命周期更合适。service 可以表达一次请求，但难以自然呈现运行进度和取消。action 被接受也不等于轨迹已执行成功，还必须等待最终结果及关节反馈。

**Q-W2D1-2：增加 AsyncSpinner 线程能解决控制延迟吗？**

**参考回答：** 它可能减轻长回调对其他回调的阻塞，但要先确认延迟来源。多线程也可能造成锁竞争、重复状态更新和乱序处理。应先测量采样到回调的各段延迟，再设计队列、线程与同步，不能把线程数作为唯一调参手段。

### W2D2：TF 树、时间戳与变换方向

**知识讲解：** TF 保存坐标系间随时间变化的关系。处理历史图像时，应查询图像采样时刻的变换，而不是把最新机器人状态套到旧图像上。

$$
{}^{base}p={}^{base}T_{camera}\,{}^{camera}p
$$

eye-in-hand 下，相机位姿还依赖当时的机械臂关节状态。静态变换描述不随时间变化的安装关系；动态变换描述运动关系。

**实践步骤：** 画出 base、tool、camera、camera optical 的关系；先用已知旋转与平移变换一个测试点，再检查逆变换是否恢复原点；模拟历史帧、缺失 TF、过早与过晚查询。

**验收：** 每条变换都注明方向、发布者和时间来源；能解释光学坐标与机器人坐标的轴定义差异。

**Q-W2D2-1：相机坐标的点怎样变到 base？**

**参考回答：** 先确认点属于哪个 camera frame 和哪个时间戳，再取得该时刻的 ${}^{base}T_{camera}$ 并左乘齐次点。相机在末端时还需结合 ${}^{base}T_{tool}(t)$ 与固定安装变换。所有长度单位、变换方向与时间必须一致。

**Q-W2D2-2：TF extrapolation 错误一般从哪里查？**

**参考回答：** 先看请求时间是否超出缓存范围，检查设备时钟、仿真时间、消息延迟和发布频率，再看变换链是否连通。未来外推可能来自时间不一致，过去外推可能来自旧消息或缓存不足。盲目改用最新变换可能隐藏错误并造成空间偏差。

### W2D3：URDF、SRDF、RobotModel 与 PlanningScene

**知识讲解：** URDF 描述链接、关节、几何和限位等物理结构；SRDF 补充规划组、默认状态及允许的自碰关系等语义。RobotModel 是模型，RobotState 是某个状态，PlanningScene 在机器人状态之外加入世界障碍物与碰撞关系。

看见 RViz 中有障碍物，不代表规划器使用的场景已正确更新。抓取后物体应由世界物体转为附着物体，并合理设置允许接触关系。

**实践步骤：** 从配置中提取关节名、顺序、限位与碰撞几何；设计加入障碍、更新障碍、移除障碍和附着物体四个场景变化；记录 object ID、frame 与更新时间。

**验收：** 同一关节状态在有障碍和无障碍场景下得到可解释的有效性结果；能指出碰撞几何简化可能带来的误判。

**Q-W2D3-1：RobotModel、RobotState、PlanningScene 有什么区别？**

**参考回答：** Model 描述机构与约束，State 描述某时刻关节与相关位姿，Scene 结合当前状态、障碍和碰撞规则。规划不能只看目标点可达，还要看整条路径是否在该场景下有效。场景由监控组件接收状态与环境更新维护。[MoveIt 概念说明](https://moveit.ai/documentation/concepts/)

**Q-W2D3-2：抓住物体后为什么要更新 attached collision object？**

**参考回答：** 抓取后物体随工具运动，若仍按固定世界物体处理，会出现错误碰撞关系；若完全删去又可能遗漏携带物与环境碰撞。附着模型表达随机器人运动的几何，同时要明确哪些触碰允许，避免放宽整场景碰撞约束。

### W2D4：规划请求经过哪些组件

**知识讲解：** 典型请求包含起始状态、目标约束、规划组、时间预算与规划器 ID。规划管线负责组织请求适配、规划插件和结果处理；具体上下文连接机器人场景与规划问题。

```text
应用请求 → move_group → PlanningPipeline
        → 规划插件 / PlanningContext
        → OMPL 搜索 → 路径处理与时间参数化
        → RobotTrajectory
```

具体适配器与调用顺序依项目版本和配置核对，不把某份源码阅读图当作所有版本的固定顺序。

**实践步骤：** 选一条 plan 调用，按类与日志追踪请求；记录起终点有效性、规划插件、预算、路径后处理和返回码；分别制造非法起点、不可达目标和搜索超时。

**验收：** 能把错误归到请求、模型、场景、搜索或后处理，而不是只报告“规划失败”。

**Q-W2D4-1：PlanningPipeline 和 Planner 有什么区别？**

**参考回答：** Pipeline 是组织请求和结果处理的框架，Planner 是负责搜索的具体算法或插件接口层。RRT-Connect 只解决其中的搜索问题，不承担全部参数配置、场景同步、轨迹执行与底层控制。讨论性能时也要说明计时覆盖的是哪一层。

**Q-W2D4-2：IK 有解，为什么还是无法规划？**

**参考回答：** IK 只说明目标位姿存在关节解，该解可能碰撞或违反其他约束；即使起终点都有效，中间通路也可能不存在，或有限预算内没有找到。检查有效性、目标容差、约束和场景，再分析采样及搜索参数。

### W2D5：ros_control、硬件接口与 SDK

**知识讲解：** 典型控制循环是读取硬件反馈、更新控制器、写入硬件命令。轨迹控制器解释时间轨迹并生成底层接受的目标，硬件接口负责单位、关节映射、通信与状态。

MoveIt 的 `move_group` 通常作为 `FollowJointTrajectory` action 客户端，机器人侧需提供服务端，MoveIt 本身不提供电机伺服闭环。[MoveIt 控制器接口](https://moveit.ai/documentation/concepts/)

**实践步骤：** 画出轨迹点、控制器目标、SDK 调用和 joint_states 的映射；用模拟 SDK 做 read/update/write，故意交换两个关节名或单位，观察离线验证结果；列出断开、故障码和反馈停更时的处理。

**验收：** 每个接口注明位置/速度/力矩语义、单位与顺序；能解释 fake execution 与真实硬件执行的差别。

**Q-W2D5-1：规划成功但机械臂不动，怎么查？**

**参考回答：** 先确认请求确实执行而非只规划，再查所选控制器、action 服务端、关节覆盖、轨迹格式与返回码，然后查驱动连接、硬件使能和反馈。RViz 的模拟动画不能证明 SDK 收到有效命令，更不能证明真机完成跟踪。

**Q-W2D5-2：控制器关节名与 SDK 顺序不同怎么办？**

**参考回答：** 建立显式的名字到 SDK 索引映射，输入时校验名称唯一且完整，再做单位与限位转换。不能假设两个数组天然同序。反馈也使用相同映射并记录时间，使命令和状态可比较。

### W2D6：分层故障演练

**知识讲解：** 按“输入 → TF → 状态 → 场景 → 搜索 → 控制器 → 驱动 → 硬件反馈”逐层定位。每层需要证据，避免同时改多个参数导致原因不可追踪。

**实践步骤：** 至少选择 TF 超时、控制器 action 缺失、起点碰撞三种故障；对每种记录症状、定位证据、修复动作和回归结果；无 ROS 环境时用真实日志或模拟接口做分析，注明范围。

**验收：** 每个故障有能排除其他假设的观察结果；架构图能在 5 分钟内讲清。

**Q-W2D6-1：规划请求超时应先增大时间预算吗？**

**参考回答：** 先确认起点、目标和约束是否有效，以及碰撞场景是否错误或过时。预算加大不能解决非法目标，也可能掩盖碰撞检查或接口开销异常。确定问题确实是搜索不足后，再用统一场景比较预算和参数影响。

**Q-W2D6-2：如何区分规划失败和执行失败？**

**参考回答：** 规划失败发生在生成有效结果之前，关注约束、场景和算法；执行失败发生在发送或跟踪轨迹时，关注控制器、通信、时间、容差与硬件反馈。两者应使用不同错误码和日志阶段，失败回退也不同。

## 3. 第 3 周：运动学、轨迹与视觉伺服

**本周目标：** 把“坐标变换 → 末端速度 → 关节速度 → 时间轨迹 → 反馈修正”连成可以解释和验证的数学链。

材料：[[../机器人学/机器人运动学与视觉伺服面试复习]]、[[../ROS/ROS2/项目/机械臂控制项目体检与完善清单]]。

### W3D1：齐次变换与旋转表示

**知识讲解：** 旋转矩阵满足 $R^TR=I$、$\det R=1$。齐次变换把旋转和平移放在同一矩阵中：

$$
{}^AT_B=\begin{bmatrix}R&p\\0&1\end{bmatrix},\qquad
({}^AT_B)^{-1}=\begin{bmatrix}R^T&-R^Tp\\0&1\end{bmatrix}.
$$

坐标链为 ${}^{A}T_C={}^{A}T_B{}^{B}T_C$，一般不能交换乘法顺序。欧拉角依赖轴序及内旋/外旋约定，存在表示奇异；单位四元数避免此类局部参数奇异，但 q 与 -q 表示同一旋转，插值时要处理符号。

**实践步骤：** 对一个“先旋转再平移”的点算例手算与程序互验；检查变换后再逆变换恢复；写清项目使用的欧拉角轴序与四元数存储顺序，如 xyzw 或 wxyz。

**验收：** 不靠记忆猜测矩阵方向；能解释两个矩阵互换后结果为何不同；旋转矩阵有正交性检查。

**Q-W3D1-1：欧拉角万向节锁与机器人运动学奇异是一回事吗？**

**参考回答：** 不是。万向节锁是某种姿态参数化失去局部独立性的表示问题；机器人奇异是机构 Jacobian 降秩、某些瞬时运动方向不可实现。改用四元数可改善姿态表示，但不会消除机械臂本身的奇异位形。

**Q-W3D1-2：四元数可以直接做元素平均吗？**

**参考回答：** 不能不加处理地平均。q 与 -q 同旋转，直接相加可能抵消，结果也不保证单位长度。应先处理符号一致性，再采用适当的旋转平均或插值方法，并归一化；路径插值常用球面线性插值等方法。

### W3D2：正运动学、逆运动学与解的选择

**知识讲解：** FK 由关节状态得到末端位姿，IK 寻找满足目标位姿的关节状态。标准 DH 可用 $R_z(\theta)T_z(d)T_x(a)R_x(\alpha)$ 描述相邻坐标变换，但不能混用改进 DH 的参数约定。POE 用关节旋量与零位姿描述运动。

平面二连杆位置模型：

$$
x=l_1\cos q_1+l_2\cos(q_1+q_2),\quad
y=l_1\sin q_1+l_2\sin(q_1+q_2).
$$

解析 IK 中，$\cos q_2=(x^2+y^2-l_1^2-l_2^2)/(2l_1l_2)$，目标可能不可达，也可能存在肘上与肘下多解。数值 IK 通常迭代计算误差、Jacobian 与关节增量，受初值和约束影响。

**实践步骤：** 实现二连杆 FK；选择一个可达点求两组 IK，并通过 FK 回代；测试目标超出可达半径、接近边界、受限位排除某解三种情况。

**验收：** IK 输出不能只看位姿误差，还检查限位、碰撞与和当前姿态的连续性。

**Q-W3D2-1：IK 有多个解时如何选择？**

**参考回答：** 首先过滤关节限位、碰撞和任务约束不合格解，再比较与当前状态的距离、可操作度及路径连续性。最接近当前关节值不一定最容易避障。连续轨迹上还要避免相邻目标突然切换到不同分支。

**Q-W3D2-2：数值 IK 为什么可能不收敛？**

**参考回答：** 目标不可达、初值不合适、姿态误差定义错误、Jacobian 坐标不一致、奇异性和过大步长都可能造成问题。先验证 FK 与误差，再检查约束和数值条件，最后考虑多初值、阻尼或步长控制；不能仅增加迭代次数。

### W3D3：几何 Jacobian 与有限差分

**知识讲解：** 几何 Jacobian 把关节速度映射到末端原点线速度和角速度，$[\dot p;\omega]=J(q)\dot q$。在共同基座系中，转动关节 i 的列为：

$$
J_i=\begin{bmatrix}z_i\times(p_e-p_i)\\z_i\end{bmatrix},
$$

其中 $z_i$ 是关节轴，$p_i$ 是轴上一点，$p_e$ 是末端原点；移动关节对应列为 $[z_i;0]$。

二连杆的位置 Jacobian：

$$
J_p=\begin{bmatrix}
-l_1\sin q_1-l_2\sin(q_1+q_2)&-l_2\sin(q_1+q_2)\\
l_1\cos q_1+l_2\cos(q_1+q_2)&l_2\cos(q_1+q_2)
\end{bmatrix}.
$$

**实践步骤：** 对每个关节用中心差分 `(p(q+εei)-p(q-εei))/(2ε)` 与解析列比较；扫描 ε，观察截断误差与数值舍入的权衡。验证旋转增量时用相对旋转的 log，而不是直接减欧拉角。

**验收：** 多个非奇异姿态下两种计算一致；写清表达坐标系、参考点和速度排列。

**Q-W3D3-1：Jacobian 的每一列代表什么？**

**参考回答：** 它代表该关节以单位速度运动、其他关节不动时，对末端瞬时速度的贡献。各列线性组合得到总速度。这是局部微分关系，不能把较大关节位移直接乘 J 当作精确位姿变化。

**Q-W3D3-2：Jacobian 数值验证不一致，先查什么？**

**参考回答：** 先核对 FK、关节单位、轴方向、末端偏置和坐标系，再查速度排列与旋转误差计算。最后调整扰动量，太大会出现线性近似误差，太小会受浮点舍入影响。不要先认定解析公式错或只在一个姿态验证。

### W3D4：奇异性、SVD、阻尼逆与零空间

**知识讲解：** 奇异位形使 Jacobian 的秩低于该机构能达到的最大秩；某些运动方向会丢失。SVD 写成 $J=U\Sigma V^T$，普通伪逆对非零奇异值使用 $1/\sigma_i$，因此小的非零奇异值会放大关节速度。[Modern Robotics：奇异性](https://modernrobotics.northwestern.edu/nu-gm-book-resource/5-3-singularities/)

阻尼最小二乘解决：

$$
\min_{\dot q}\|J\dot q-v_d\|^2+\lambda^2\|\dot q\|^2,
\qquad
\dot q=J^T(JJ^T+\lambda^2I)^{-1}v_d,\quad\lambda>0.
$$

各奇异方向系数由 $1/\sigma_i$ 变成 $\sigma_i/(\sigma_i^2+\lambda^2)$，抑制速度放大，但产生跟踪残差。实际求解优先用矩阵分解，不显式计算逆矩阵。

精确伪逆下，冗余系统可加 $\dot q=J^+v_d+(I-J^+J)z$ 实现关节限位等次目标；阻尼逆对应项通常不再是精确零空间投影，可能影响主任务。

**实践步骤：** 二连杆取 $q_2\to0$，固定小任务速度，对比普通伪逆与不同 λ 的关节速度范数和残差；检查限幅后末端速度；记录阻尼增大带来的精度损失。

**验收：** 有速度、残差与最小奇异值的对应记录；能区分奇异、近奇异与算法阈值截断。

**Q-W3D4-1：阻尼逆为什么更稳定？代价是什么？**

**参考回答：** 正则项限制关节速度范数，避免沿很小奇异值方向放大指令。它以任务误差换数值稳定性，阻尼越大通常速度越受抑制，残差也可能更大。仍需速度、加速度、限位与碰撞约束，阻尼本身不是完整安全措施。

**Q-W3D4-2：零空间运动能保证不影响末端吗？**

**参考回答：** 使用精确伪逆时，`J(I-J⁺J)=0`，因此在瞬时线性模型中不影响主任务。但有限步长、离散积分、限幅和阻尼近似都可能破坏这一性质。若使用阻尼逆，不能直接声称对应次目标严格不影响末端。

### W3D5：路径、轨迹与三次五次插值

**知识讲解：** 路径 $q(s)$ 描述几何，时间律 $s(t)$ 决定轨迹 $q(t)$。无碰路径未必满足速度和加速度限制，也不等于可立即执行的控制目标。

起终点速度为零的三次插值，令 $\tau=t/T$：

$$
q(t)=q_0+(q_f-q_0)(3\tau^2-2\tau^3).
$$

若起终点速度与加速度均为零，可用五次：

$$
q(t)=q_0+(q_f-q_0)(10\tau^3-15\tau^4+6\tau^5).
$$

三次端点加速度通常不为零，多段独立拼接可能产生加速度跳变；五次零边界适合停到停，若每个途经点都停下也会降低效率。任意关节插值还可能改变原规划路径，需重新验证碰撞。

**实践步骤：** 求位置的一二阶导，代入端点验证；比较同一 T 下速度和加速度峰值；延长 T 直到满足约束；检查采样点与段间连续性。

**验收：** 能从边界条件确定所需多项式阶数；明确限位、速度和加速度约束不靠“轨迹看起来平滑”证明。

**Q-W3D5-1：路径无碰，为什么时间参数化后仍可能有问题？**

**参考回答：** 若只沿同一路径改变时间且障碍静态，几何无碰性质保留；但速度、加速度与执行误差仍需检查。若平滑或重新插值改变几何，就可能引入碰撞；动态障碍还使有效性依赖时间，因此必须区分纯重定时与改路径。

**Q-W3D5-2：三次与五次插值如何选择？**

**参考回答：** 由边界条件决定。三次能约束起终点位置和速度，共四个条件；五次还能约束起终点加速度，共六个条件。更高阶不自动表示更好，要同时考虑段间连续性、动态限制、数值稳定和任务是否需要中途停车。

### W3D6：PBVS、IBVS 与模式切换

**知识讲解：** PBVS 根据估计的三维位姿构造误差；IBVS 根据图像特征误差 e=s-s* 闭环，通过交互矩阵 L 关联图像变化与相机速度。眼在手上、目标静止等相应模型下，可写 $v_c=-\kappa L^+e$。

PBVS 的局部速度反馈也需要匹配误差、表达坐标和参考点。把相机速度转换成工具运动时，若参考点不同，要考虑旋转引起的线速度项，不能只旋转两个三维向量。外置相机的模型也不能照搬移动相机控制式。

推荐状态链：全局规划 → 接近 → 局部伺服 → 收敛确认 → 抓取；目标丢失、过期、碰撞风险或控制异常进入停止/重检测。切换阈值可用滞回和连续有效帧防止频繁跳变。

**实践步骤：** 在离线模型中加入视觉延迟、噪声和丢帧；记录误差、指令饱和、数据年龄与模式；画出切换及回退条件，不同时向硬件发送互相冲突的规划与伺服指令。

**验收：** 明确反馈量、控制律、周期、坐标、限幅及终止条件；区分“估计到目标”与“闭环已收敛”。

**Q-W3D6-1：为什么采用远距离规划、近距离视觉伺服？**

**参考回答：** 规划处理全局障碍与大范围运动，近距离伺服处理标定误差、目标扰动与跟踪残差。局部视觉控制缺少全局搜索能力，目标也可能出视野，所以不能承担全程无碰保证。切换应检查目标稳定性、距离、视野、碰撞裕量与控制器状态。

**Q-W3D6-2：增大控制增益能更快收敛吗？**

**参考回答：** 只在模型与时延允许的范围内可能更快。过大增益会放大噪声，造成指令饱和或振荡，延迟也可能降低稳定裕量。应在实际周期和数据年龄下验证误差趋势，并设置限幅、超时与发散判断，而不是只追求误差瞬间下降。

## 4. 第 4 周：采样规划、OMPL 与学习引导

**本周目标：** 能手写 RRT-Connect 流程，解释几何有效性、采样策略与理论条件，并设计公平的学习引导实验。

材料：[[../motion_planning/学习引导RRT-Connect复习]]、[[../motion_planning/modifyRRT]]、[[../ompl/src/ompl/geometric/planners/rrt/src/RRTConnect.cpp|本地 RRTConnect 源码]]。

### W4D1：配置空间、碰撞与局部连接

**知识讲解：** 配置 q 描述机器人内部自由度，障碍在工作空间中表现为几何，在配置空间中表现为一组不可行关节状态。起终点有效不代表连线有效。

- 状态检查：关节限位、自碰、环境碰撞及任务约束。
- 运动检查：沿连接边检查中间状态，或使用适当连续碰撞检测。
- 局部连接器：定义两个配置间如何插值或推进，不负责绕远路找通道。
- 连续转动关节、SE(2)/SE(3) 等空间不能全部按无界普通向量处理。

**实践步骤：** 在二维配置空间构造障碍，使两个端点有效但线段穿障；改变边检查间隔，观察漏检；记录状态有效性与运动有效性的独立调用数。

**验收：** 说明碰撞检查分辨率与速度的取舍；明确离散检查不能自动提供连续无碰证明。[OMPL 状态与运动检查](https://ompl.kavrakilab.org/stateValidation.html)

**Q-W4D1-1：为什么机械臂通常在关节空间规划？**

**参考回答：** 关节状态直接描述机构配置，可统一检查限位与整条机械臂的碰撞。只规划末端直线不代表存在连续无碰的关节运动，也会遇到多解切换和奇异性。笛卡尔路径仍有适用场景，但需求 IK 并验证沿途完整机器人状态。

**Q-W4D1-2：端点都无碰，为什么还要 checkMotion？**

**参考回答：** 连杆在两个配置之间扫过的区域可能碰撞，端点检查无法覆盖中间状态。必须使用与实际插值一致的边检查。离散分辨率太粗会漏薄障碍，太细则增加开销，应结合几何和误差选择，而非只追求运行快。

### W4D2：RRT、RRT-Connect 与 RRT*

**知识讲解：** RRT 采样后从树中最近点朝样本延伸；RRT-Connect 采用双树并让另一棵树重复向新节点连接；RRT* 加入近邻选父与重连，以改善已有路径代价。

| 方法 | 主要机制 | 要能解释的性质 |
|---|---|---|
| RRT | 单树探索 | 在相应条件下概率完备，通常不渐近最优 |
| RRT-Connect | 双向扩展与贪婪连接 | 适合快速首解，不保证渐近最优 |
| RRT* | 代价选父、邻域重连 | 在相应条件下渐近最优 |

概率完备讨论的是预算无限增加时找到解的概率；渐近最优讨论解的代价趋向最优，两者不是“每次有限时间都成功”的保证。[RRT* 原论文](https://arxiv.org/abs/1105.1186)

**实践步骤：** 在同一个二维环境比较首次可行解；保留相同有效性检查和预算；记录首解时间及后续代价变化。先用手工轨迹检查恢复路径的方向是否正确。

**验收：** 能画双树连接，并解释 start/goal 树交换后仍要正确恢复起点到终点路径。

**Q-W4D2-1：RRT-Connect 为什么常能较快找到首解？**

**参考回答：** 两棵树从两端搜索，一方得到新节点后，另一方连续尝试连接，而非只走一步后等待下一次随机采样。这样减少会合所需迭代，但性能依赖环境与碰撞开销；它关注可行首解，不自动优化最终代价。[作者的规划论文入口](https://kuffner.org/james/plan/)

**Q-W4D2-2：RRT* 为什么不能只理解为“多运行一会儿的 RRT”？**

**参考回答：** RRT* 在插入节点时比较邻域中父节点代价，还会重连已有邻居，持续改善树中的路径。普通 RRT 缺少这些机制，即使继续采样也不因此获得同样的最优性保证。相关结论还有邻域、成本、采样与问题可行性的假设。

#### RRT-Connect 白板伪代码

```text
验证起点和目标；分别建立 start 树和 goal 树
while 未达到终止条件:
    q_rand = SAMPLE()
    statusA, q_new = EXTEND(treeA, q_rand)
    if statusA != TRAPPED:
        repeat:
            statusB, last = EXTEND(treeB, q_new)
        until statusB != ADVANCED 或到达终止/连接预算
        if statusB == REACHED:
            根据两树身份恢复 start → 连接点 → goal
            返回经过验证的路径
    交换 treeA 和 treeB，并保留各自身份
返回无解或超时状态

EXTEND(tree, target):
    near = NEAREST(tree, target)
    candidate = 按状态空间规则向 target 推进至多 range
    若无有效进展或连接无效，返回 TRAPPED
    添加 candidate 与父连接
    到达 target 返回 REACHED，否则返回 ADVANCED
```

该伪代码适用于所讨论的几何连接模型。动力学、单向运动限制和一般目标区域需要扩展，不能直接照搬可逆双树连接。

### W4D3：距离、最近邻、步长与采样偏置

**知识讲解：** 最近邻结果受距离度量决定。角度周期、各关节权重和任务空间要求都应明确。高维近邻结构的剪枝可能变弱，不能假定所有查询 O(log n)。

range 控制一次推进距离，碰撞检查间隔控制沿边验证，两者不是同一参数。goal bias 是采样偏置概念，不是所有 RRT-Connect 实现都提供相同命名的参数；实际支持项以源码与配置为准。

**实践步骤：** 对 range、均匀采样比例和检查分辨率分别做单变量实验；使用多个种子；记录节点数、碰撞检查次数、成功率与失败类别，而非只看最快一次。

**验收：** 用数据解释过大与过小参数的行为；区分采样失效、边连接失败和预算消耗。

**Q-W4D3-1：步长越大是不是规划越快？**

**参考回答：** 不一定。大步长可以减少节点，但在狭窄通道更容易跨到障碍，单边检查也可能更贵；小步长更细致，却增加扩展和近邻成本。应在固定场景集上比较综合效果，不把步长与碰撞检查间隔混淆。

**Q-W4D3-2：提高目标偏置为什么可能变差？**

**参考回答：** 它会集中尝试朝目标推进，若目标方向被障碍挡住，就反复产生无效扩展并减少绕障探索。适度偏置有利于会合，过强偏置可能降低多样性。学习采样也有类似风险，因此需要保留可靠探索来源。

### W4D4：OMPL 接口与 MoveIt 适配

**知识讲解：** OMPL 提供通用规划结构，具体机器人几何与碰撞模型由集成层提供。

| 对象 | 职责 |
|---|---|
| StateSpace | 状态表示、边界、距离、插值与采样 |
| SpaceInformation | 有效性与运动检查等规划所需信息 |
| ProblemDefinition | 起点、目标、优化目标与解 |
| Planner | setup、solve、clear 等求解生命周期 |
| PathGeometric | 几何状态序列，不自带可执行时间律 |

这些接口的关系可由 [OMPL 规划上下文说明](https://ompl.kavrakilab.org/genericPlanning.html) 核对。MoveIt 适配层把机器人场景与请求接入上述对象。

**实践步骤：** 从本地 RRTConnect 源码追踪采样、growTree、运动检查和解恢复；对照 [[../motion_planning/OMPL/自定义Planner骨架]] 标记需要实现的部分。现有骨架含省略逻辑和示意路径，不能当作已可运行的完整规划器。

**验收：** 自定义设计包含状态分配释放、重复求解清理、目标类型检查、超时和完整路径恢复；未初始化采样状态不能拿去有效性检查。

**Q-W4D4-1：自定义 Planner 最容易遗漏什么？**

**参考回答：** 常见遗漏包括状态内存、clear 后残留树、错误目标类型转换、忽略终止条件、只检查节点不检查边，以及返回没有到达目标的路径却声明精确解。接口继承完成不等于算法完整，应从生命周期与成功条件逐项检查。

**Q-W4D4-2：OMPL 为什么不直接负责所有碰撞检测？**

**参考回答：** 它面向不同状态空间和机器人问题，碰撞几何与约束由应用提供更灵活。集成层必须设置正确的状态与运动验证器，不能把规划器返回结果当作未配置检查也安全。模型更新和场景一致性仍属于系统责任。

### W4D5：点云编码、CVAE 与 Transformer

**知识讲解：** 学习模块用环境与起终点作为条件 c，生成路径节点或骨架。训练时可以看到参考路径 y，推理时不能将真实答案当作输入。

CVAE 的典型目标为：

$$
\mathcal L=-\mathbb E_{q_\phi(z\mid y,c)}[\log p_\theta(y\mid z,c)]
+\beta D_{KL}(q_\phi(z\mid y,c)\|p_\psi(z\mid c)).
$$

也可使用固定先验。重构项鼓励匹配路径，KL 项约束训练后验与推理先验；潜变量表达同一问题的多种候选。[CVAE 原论文](https://proceedings.neurips.cc/paper/2015/hash/8d55a249e6baa5c06772297520da2051-Abstract.html)

点云编码需要明确单位、参考系、点数与采样策略；Transformer 需要明确 token、位置编码、注意力方向与输出。自回归路径预测还要检查训练与推理上下文差异。这里是通用理解框架，个人项目的具体网络结构必须从实际代码补足。

**实践步骤：** 画训练与推理两张图；列出各张量形状、归一化和输出约束；按场景划分训练/验证/测试，防止同场景近似路径泄漏；检查模型是否只是记住固定环境。

**验收：** 能说明潜变量来自哪里、测试时有哪些输入、输出如何进入规划器，且有数据划分记录。

**Q-W4D5-1：为什么不直接回归唯一最短路径？**

**参考回答：** 相同起终点可能有多条可行通道，单点回归可能把不同模式平均成碰撞路径。条件生成模型可以给出多个候选，提高多样性，但不保证每个候选可行。使用哪种目标还要看训练数据与任务成本定义。

**Q-W4D5-2：Transformer 在这个系统中具体解决什么？**

**参考回答：** 它可用于融合环境、起终点和路径节点上下文，建模节点间依赖。回答必须继续说明项目的 token 含义、位置编码、输出粒度及推理方式；“注意力更强”不能证明作用。还需通过去除或替换该模块的消融验证贡献。

### W4D6：混合采样、失效回退与消融

**知识讲解：** 可以采用 $p(q)=\alpha p_{learn}(q)+\beta p_{uniform}(q)+\gamma p_{opposite}(q)$，权重非负且和为 1。学习先验提高候选质量，均匀探索覆盖先验未命中的区域，对向树偏置促进连接。

讨论概率完备性时，需对均匀探索概率给出不会消失的条件，如每轮 $\beta_n\ge\beta_0>0$，并满足相应扩展、有效性、终止预算和稳健可行路径假设。仅“每轮概率大于零”不充分，例如概率快速衰减可能无法保证无限次有效探索。低维约束流形还需要适合该空间的采样。

这保留了标准论证的基础，**具体修改后的算法仍需核查条件或给出证明**。有限预算成功率必须通过实验测量，不能用完备性替代。

**实践步骤：** 原始 RRT-Connect、仅预测、预测+均匀、再加入对向树、完整方法去除新增连接策略，至少比较这些组；分别记录网络耗时和搜索耗时。标准 RRT-Connect 本就含贪婪 CONNECT，新增“骨架贪婪连接”必须定义清楚，不能把原算法机制当成新增贡献。

**验收：** 每一消融只有明确因素变化；错误预测仍经过状态与边验证；单次模型调用和连接有预算，能够回退。

**Q-W4D6-1：保留一点随机采样就能保证完备性吗？**

**参考回答：** 不能只凭这句话保证。要看探索概率是否长期保持、采样覆盖、扩展是否允许有效进展，以及标准问题条件。学习分支若占用全部预算、强制拒绝正常扩展或使概率快速消失，都可能破坏所需条件。实际实现的理论性质与有限时间性能要分别说明。

**Q-W4D6-2：如何证明模型预测真的带来收益？**

**参考回答：** 在相同场景、预算、硬件、检查精度与后处理下对比基线，包含推理成本，并用多个种子报告成功率、时间分布、节点与检查次数。通过仅预测、混合采样和去连接策略等消融区分贡献，再加入分布外失败案例验证回退。

- [ ] benchmark 表格，包含失败、超时和统计口径。

**加练：** 对狭窄通道和错误点云分别构造失败样例，比较失效回退消耗的时间。

## 5. 第 5 周：视觉、RGB-D 与手眼标定

**本周目标：** 从检测框得到有坐标、时间和误差含义的抓取候选，而不是把检测成功直接等同于抓取成功。

材料：[[../视觉/YOLO-OBB、RGB-D与手眼标定]]、[[知识缺口与证据清单]]。

### W5D1：IoU、Precision、Recall、AP 与 mAP

**知识讲解：** $IoU=|B_{pred}\cap B_{gt}|/|B_{pred}\cup B_{gt}|$，OBB 采用旋转几何。给定匹配规则与置信度阈值后，$Precision=TP/(TP+FP)$，$Recall=TP/(TP+FN)$。

AP 汇总单类精确率-召回率曲线，mAP 对类别取平均。`mAP@0.5` 固定 IoU 匹配阈值为 0.5；它与多个 IoU 阈值平均的指标不同。具体匹配、插值与汇总细节以评估脚本为准。

**实践步骤：** 构造少量预测与真值，按置信度排序并做一对一匹配；观察重复框计为 FP；变更置信度阈值比较 Precision/Recall；确认训练、验证、测试按物体、场景或采集批次适当隔离。

**验收：** 能说明 TP 如何判定、分母是什么、测试是否泄漏；77.2% 只作为待核验项目数字。

**Q-W5D1-1：mAP@0.5=77.2% 能证明抓取精度吗？**

**参考回答：** 它描述在规定匹配与数据集上，各类别 AP 的平均，不等于三维位姿精度，也不等于抓取成功率。需要同时给出旋转 IoU、划分、类别、位姿误差和系统成功率。定位、标定与控制仍可能成为主要瓶颈。

**Q-W5D1-2：为什么同一个物体预测多个框会影响 Precision？**

**参考回答：** 评估通常采用预测与真值的一对一匹配，最合适的预测匹配后，其余重复预测不能再算同一个真值的 TP，会成为 FP。这解释了后处理的重要性，但过强抑制又可能漏掉相邻物体，需要平衡并检查评估规则。

### W5D2：YOLO 检测头、OBB 与 NMS

**知识讲解：** 检测模型通常包含特征提取、尺度融合和预测输出。具体检测头是 anchor-based、anchor-free，是否有独立 objectness，以及框与角度的编码，都由版本决定。

OBB 常用 `(cx,cy,w,h,θ)` 或四顶点表示。矩形存在角度周期与宽高交换等价性，如交换 w/h 并旋转 90° 可能描述同一几何。旋转 NMS 使用相应重叠关系，不能直接套水平框 IoU。

**实践步骤：** 画四个不同方向的同一矩形，统一角度约定；检查接近角度边界时标签是否跳变；分别观察细长物体、近正方形物体与密集场景的后处理表现。

**验收：** 从真实配置说出模型版本、输出维度与损失；没有消融证据时不把常规调参称为结构创新。

**Q-W5D2-1：OBB 的角度能直接作为机械臂抓取姿态吗？**

**参考回答：** 它通常只是图像平面内方向，并不等于基座系完整 6D 姿态。需要结合相机姿态、平面法向、深度几何与夹爪约束。外参倾斜、遮挡或正方形目标也会让方向推断不可靠，因此它更适合作为候选初值。

**Q-W5D2-2：角度在边界附近突然跳变怎么处理？**

**参考回答：** 先核对标签、预测和后处理的角度范围及宽高交换规则，再选择适合周期性的表示或损失。近正方形目标角度本来就可能不稳定，需要结合抓取对称性定义误差，而非把等价方向当作大错误。跟踪平滑也不能替代定义一致。

### W5D3：内参、畸变、深度与反投影

**知识讲解：** 去畸变后的针孔模型为 $u=f_xX/Z+c_x$、$v=f_yY/Z+c_y$，因此：

$$
X=(u-c_x)Z/f_x,\qquad Y=(v-c_y)Z/f_y.
$$

这里 Z 是相机光轴方向深度，不是到相机中心的欧氏距离。对齐后的图像应使用相应的内参；缩放和裁剪也需要正确更新内参或坐标映射。[OpenCV 相机模型](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

合成算例：`fx=fy=600`、`cx=640`、`cy=360`，像素 `(700,390)`、Z=0.8 m，得到 `(0.08,0.04,0.8) m`。这些参数仅用于学习，不代表实际相机配置。

**实践步骤：** 验证上述算例；在目标有效区域过滤零值、越界与离群深度，用多点中位数或平面模型估计；模拟中心像素为背景、深度空洞、毫米误用为米。

**验收：** 写清深度单位、像素所属图像和采样时刻；低质量数据返回无效状态，不产生伪造坐标。

**Q-W5D3-1：为什么不直接取 OBB 中心像素深度？**

**参考回答：** 中心可能落在空洞、反光区域或凹形物体背景上。应在真正属于目标的区域采样，剔除无效和离群值，再结合几何模型估计。OBB 内仍可能有背景，不能把整个矩形中的有效深度都当作物体点。

**Q-W5D3-2：深度和彩色图都收到了，还会不对齐吗？**

**参考回答：** 会。两传感器有不同内外参与视角，必须进行几何配准；采样时间差还会在运动时造成位置偏差。应核对对齐目标、内参、像素映射与时间戳，不能只看图像尺寸相同就认为对应正确。

### W5D4：外参与手眼标定

**知识讲解：** eye-in-hand 相机随机械臂运动，常求固定 ${}^{tool}T_{camera}$；eye-to-hand 相机固定，常求 ${}^{base}T_{camera}$。接口中的 gripper、tool、flange 与 TCP 也需区别。

以标定板固定、相机在手上为例，令 $H_i={}^{base}T_{tool,i}$、$X={}^{tool}T_{camera}$、$C_i={}^{camera_i}T_{board}$：

$$
H_iXC_i=Y,
\qquad (H_j^{-1}H_i)X=X(C_jC_i^{-1}).
$$

这给出一套明确方向的 AX=XB。外置相机、移动标定板的坐标链不同，输入可能需要重排或取逆，不能只凭函数名套用。[OpenCV 手眼标定接口](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

**实践步骤：** 写出实际安装的每个坐标系；采集具有足够不同旋转方向的姿态并做好时间匹配；用未参与估计的观测验证已知点或标定板；核对结果方向与工具偏置。

**验收：** 能画出闭合坐标链，说明姿态激励不足与纯平移数据的风险；不只报告参与标定数据的残差。

**Q-W5D4-1：为什么标定需要多种旋转姿态？**

**参考回答：** 变换参数需要足够运动激励才能被辨识，只有很少方向或近似重复姿态会使方程退化或病态。平移估计也与旋转约束相关。应覆盖不同旋转轴与适当工作空间，再通过独立姿态验证，不能只增加重复照片数量。

**Q-W5D4-2：重投影误差小，为什么抓取仍有偏差？**

**参考回答：** 重投影衡量图像拟合，不直接覆盖机器人运动、手眼外参、工具偏置和深度偏差。还可能存在时间不同步或错误坐标方向。需要在相机坐标、基座坐标和末端到达三个阶段分别验证，分离系统性误差。

### W5D5：位姿误差与误差传播

**知识讲解：** 位置误差可定义为 $e_p=\|p_{pred}-p_{gt}\|_2$；姿态误差可用相对旋转角：

$$
R_e=R_{gt}^TR_{pred},\qquad
e_R=\arccos\left(\operatorname{clip}\left(\frac{\operatorname{tr}(R_e)-1}{2},-1,1\right)\right).
$$

clip 处理浮点误差，不能掩盖严重不合法的旋转矩阵。对有对称性的物体，姿态评价需考虑等价姿态。

内参固定时，X 的一阶扰动含 $\delta X\approx(Z/f_x)\delta u+((u-c_x)/f_x)\delta Z$。深度与像素误差对不同位置影响不同，外参角度偏差还会产生随距离变化的位置误差。协方差传播常用 $\Sigma_{out}\approx J\Sigma_{in}J^T$，需说明线性化与相关性假设。

**实践步骤：** 分别注入像素、深度和外参扰动；记录位置误差变化；用独立真值评估均值、RMSE、中位数与尾部误差，标明样本数。5.8 mm/3.3° 的实际口径仍须查证。

**验收：** 区分精度、重复性、偏差与噪声；不把各阶段标量误差直接相加当作严格总误差。

**Q-W5D5-1：位置误差的均值与 RMSE 有什么区别？**

**参考回答：** 均值对每次误差取算术平均，RMSE 对误差平方平均后开方，对较大误差更敏感。必须说明是位置距离的统计，还是各坐标分量的统计，不能只写一个毫米数字。真值精度与空间分布也会影响结论。

**Q-W5D5-2：如何判断误差来自外参还是检测？**

**参考回答：** 先在相机坐标下用已知目标验证像素与三维恢复，再加入外参观察基座系误差。外参误差常表现为随空间位置变化的系统偏差；检测误差可能与目标、角度和遮挡有关。应使用分层、重复且覆盖空间的实验，而非凭一次失败猜原因。

### W5D6：部署、GPU 计时与端到端延迟

**知识讲解：** 耗时至少分为采样/排队、预处理、传输、模型、NMS、三维估计、规划和命令生效。GPU 异步执行时，未同步的 CPU 计时可能只测到提交工作时间。

计时需预热，固定硬件、batch、精度与分辨率；用相应同步或设备事件覆盖所测区间。吞吐率、单帧延迟与端到端延迟不同，批处理提升吞吐也可能增加等待。

**实践步骤：** 为每阶段定义起止时刻；记录 P50/P95 及有效帧处理率；人为增加输入频率观察队列积压；检查丢帧后系统用的是新数据还是旧数据。5.4 ms 必须先明确是哪一段。

**验收：** 有计时边界与完整环境记录；不能把模型 forward 数字当作从图像到动作的总延迟。

**Q-W5D6-1：为什么 5.4 ms 推理不意味着系统能以约 185 Hz 控制？**

**参考回答：** 它可能只覆盖模型计算，系统还包含相机采样、排队、预后处理、坐标变换、规划和执行。各阶段频率与并行方式也不同，简单取倒数只表示该计时区间的理想处理能力。闭环需要测量数据年龄与命令生效延迟。

**Q-W5D6-2：如何降低闭环延迟而不只优化网络？**

**参考回答：** 先分解实际耗时，再处理积压、重复拷贝、同步等待和不必要后处理。感知若只需最新状态，可以采用有界最新帧策略，并保证时间戳完整。优化后同时核对精度与尾延迟，避免只提高吞吐却让旧帧排队更久。

## 6. 第 6 周：SLAM、导航与多机器人编队

**本周目标：** 区分定位、建图、路径规划和速度控制；把坐标、通信与失效状态一起设计。

材料：[[../ROS/导航/SLAM导航与多机器人编队]]、[[../ROS/ROS2/通信协议-DDS-TCP-UDP]]。

### W6D1：差速里程计、编码器与 IMU

**知识讲解：** 理想差速底盘，两轮半径 r、轮距 b，左右轮角速度 ωL、ωR：

$$
v=\frac r2(\omega_R+\omega_L),\qquad
\omega=\frac rb(\omega_R-\omega_L),
$$

$$
\dot x=v\cos\theta,\qquad\dot y=v\sin\theta,\qquad\dot\theta=\omega.
$$

轮径误差、打滑和时间戳会引入漂移；IMU 角速度有偏置，直接积分同样漂移。融合利用互补观测，不会凭空产生绝对位置。滤波需定义状态、过程模型、观测、噪声和坐标关系。

**实践步骤：** 模拟直线、原地旋转和圆弧，验证左右轮符号；加入轮径偏差与角速度偏置，观察漂移；对比真实时间间隔和固定假定周期积分。

**验收：** 能解释单位、符号与误差来源；没有实现具体滤波器时不把“编码器+IMU”说成已经实现某种融合算法。

**Q-W6D1-1：编码器与 IMU 为什么需要融合？**

**参考回答：** 编码器提供轮式运动信息但受打滑和标定影响，IMU 的角速度短期响应快但受偏置影响。融合可降低部分不确定性，并检测不一致，但长期位置仍可能漂移，需要激光、地图或其他观测校正。实际效果依赖模型与噪声设置。

**Q-W6D1-2：差速机器人能直接执行任意二维速度吗？**

**参考回答：** 不能。理想差速模型不能直接侧向运动，控制输入通常是前向速度与角速度。上层生成的位置或二维速度目标需转换成满足非完整约束的可执行指令，不能把平面向量的两个分量直接当成轮子命令。

### W6D2：Gmapping 与粒子滤波建图

**知识讲解：** Rao–Blackwellized 粒子滤波用粒子表示轨迹假设，并在各轨迹条件下维护地图估计。运动模型提出候选，激光匹配改善位姿假设，观测权重衡量一致性，必要时重采样。

粒子数不是唯一质量因素。错误里程计、激光时间、TF、最大量程及地图分辨率都可能让地图重影。栅格概率更新是观测融合，不是把每条射线终点永久认定为固定障碍。

**实践步骤：** 用同一段回放检查直线和转弯地图质量；逐项调整一个参数；记录回环附近、玻璃区域或动态障碍的表现；先确认数据与 TF，再比较粒子数。

**验收：** 能画输入 laser/odom/TF 与输出 map 的关系；说明计算开销和地图分辨率变化的影响。

**Q-W6D2-1：Gmapping 的粒子表示地图还是位姿？**

**参考回答：** 核心是用粒子表示机器人轨迹假设，并为每条假设维护条件地图，利用这种分解处理 SLAM。不能简单说“粒子就是地图像素”。scan matching 和观测权重帮助选择更一致的轨迹与地图解释。

**Q-W6D2-2：地图重影应该先增加粒子数吗？**

**参考回答：** 先检查激光与运动时间匹配、安装 TF、轮径轮距和里程计质量。输入错误会让更多粒子仍围绕错误解释工作。排除输入问题后，再比较粒子数、更新阈值与匹配参数，并控制计算预算。

### W6D3：AMCL 与 map、odom、base_link

**知识讲解：** AMCL 在已知地图上用粒子表示位姿，不负责像 SLAM 那样持续构建未知地图。运动模型传播，激光与地图一致性更新权重，重采样维持有效假设。

`odom` 局部连续但可漂移，`map` 提供全局参考但定位校正可跳变。常见 TF 链为 `map → odom → base_link → laser`，每条边应有明确发布者。[ROS REP-105 坐标约定](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)

使用同一时刻的估计，${}^{map}T_{odom}={}^{map}T_{base}({}^{odom}T_{base})^{-1}$。多机编队还要确保各机器人共享或可转换的全局参考，不可直接相减不同 odom 系的位置。

**实践步骤：** 画正常运行、定位校正与重新初始化三种 TF 变化；模拟同一边由两个节点发布；分析机器人被移动到别处时的恢复策略。

**验收：** 能说明哪个层适合局部控制，哪个层用于全局目标；排查时能区分定位跳变与里程计突变。

**Q-W6D3-1：为什么 map 和 odom 不合并？**

**参考回答：** 局部控制需要连续状态，全局定位又要纠正累计漂移，这两个要求可能冲突。让 odom 保持连续，用 map 到 odom 的关系吸收全局校正，便于分开处理。控制器若直接使用跳变的全局误差，仍需特别设计过渡。

**Q-W6D3-2：机器人被搬走后 AMCL 一定能自行恢复吗？**

**参考回答：** 不一定，原粒子分布可能集中在错误区域，环境也可能高度对称。可以重新设置初始位姿或做全局重定位，并在定位不可信时限制导航。恢复效果取决于传感器模型、粒子覆盖、环境可区分性与配置。

### W6D4：move_base、costmap 与局部控制

**知识讲解：** 全局规划在全局代价图上寻找路径，局部规划结合当前姿态、运动约束和局部障碍输出速度。常见 costmap 层有静态、障碍和膨胀；具体插件以项目配置为准。

footprint 描述机器人占据几何，膨胀代价鼓励与障碍保持裕量，两者不能互相替代。障碍清除受传感器射线、量程和观测持久性影响。恢复行为并不等于忽视物理障碍继续前进。

**实践步骤：** 观察窄通道中不同 footprint 与 inflation 配置；核查全局路径存在但局部速度为零的情况；按 TF、定位、地图、障碍层、路径、速度和底盘响应逐层分析。

**验收：** 能区分没有全局路径、局部轨迹不可行、速度被安全层覆盖和底盘不响应。

**Q-W6D4-1：有全局路径，为什么机器人仍不走？**

**参考回答：** 局部控制可能无法在速度或非完整约束下跟随，也可能看到新的障碍、定位过期或 footprint 与环境冲突。还需检查速度是否发布、是否被仲裁层覆盖及底盘是否执行。路径存在只证明某层找到了几何路线。

**Q-W6D4-2：减小机器人半径就能解决窄通道失败吗？**

**参考回答：** 若原配置错误，可按真实几何修正；若只是为了通过而缩小模型，会虚假增加可行空间，可能导致真机碰撞。应结合真实外形、定位误差与动态约束判断通道是否可行，必要时改变路径或任务。

### W6D5：前沿探索与覆盖率

**知识讲解：** 前沿是已知自由区域与未知区域之间的边界。探索流程包括候选检测、聚类去重、可达性过滤、效用评分、任务执行与失败反馈。

效用可组合信息增益、路径长度、风险与已分配区域，例如 $U=w_gG-w_dD-w_rR$；各项单位和权重需要归一化或解释。前沿近不代表收益高，也不保证可达。

**实践步骤：** 在一张固定地图上标前沿，过滤孤立与危险候选；对比只选最近点与综合效用；固定区域与分辨率记录探索进展和失败目标。

**验收：** 覆盖率分母预先定义；无可达真值时报告可解释的代理指标，不将当前地图大小冒充真值区域。

**Q-W6D5-1：RRT-Exploration 中 RRT 直接负责导航控制吗？**

**参考回答：** 在典型系统中，它可用于产生探索候选或检测前沿，目标分配后仍由导航栈规划和执行。需要按实际实现说明各模块，不能因名字含 RRT 就把探索、导航路径和底盘控制混成同一算法。

**Q-W6D5-2：96.3% 覆盖率该如何证明？**

**参考回答：** 先说明可达区域真值、边界、栅格分辨率及何谓已探索，再用固定 mask 计算已探索可达格数除以真值可达格数。保留原地图、mask、脚本和实验次数。若没有真值，只能换成有明确意义的代理指标，不能推定该百分比有效。

### W6D6：编队、通信与超时状态机

**知识讲解：** 主从编队首先要定义相对偏移属于世界系还是主机坐标系。若主机位置 $p_l$、航向 $\theta_l$，偏移 $d_i$ 属于主机系，则：

$$
p_i^*=p_l+R(\theta_l)d_i,\qquad
\dot p_i^*=\dot p_l+\omega_lR(\theta_l)S d_i,
\quad S=\begin{bmatrix}0&-1\\1&0\end{bmatrix}.
$$

前馈包含主机转弯导致的偏移点速度，反馈可按位置误差修正；最终还需转成底盘可执行 v/ω 并限幅。避障、安全和失联处理优先于保持队形。

| 状态 | 进入条件 | 行为 | 恢复条件 |
|---|---|---|---|
| WAIT | 尚无有效主机状态 | 不追踪未知目标 | 收到连续有效新状态 |
| FOLLOW | 状态新鲜、定位与控制正常 | 编队跟随并监测障碍 | 持续检查 |
| AVOID | 局部障碍触发 | 避障或停止，暂时放宽队形 | 障碍解除且路径可行 |
| STALE_STOP | 超时或数据过期 | 按限定减速度停车并记录 | 连续新数据及状态检查通过 |
| RECOVER | 从停止或避障恢复 | 平滑恢复目标，限制突变 | 误差和状态进入正常范围 |

**实践步骤：** 15 Hz 生成主机状态，注入丢包、乱序、停发和延迟；用本地接收时刻检查超时；记录状态转移、指令限幅与恢复突变，模拟主机转弯。

**验收：** 能解释有效接收频率与控制频率；失联后不无限预测或追旧位置；没有实测前不认定 15 Hz 足够。

**Q-W6D6-1：15 Hz 对编队是否足够？**

**参考回答：** 取决于速度、转弯、可接受误差、端到端延迟和本地控制频率。约 66.7 ms 的更新周期不是全部延迟，丢包会进一步增加数据年龄。需要在相应最坏通信情形下测误差与稳定性，再决定频率和超时策略。

**Q-W6D6-2：编队目标与避障冲突怎么办？**

**参考回答：** 通过明确仲裁或状态机让安全控制优先，必要时放弃暂时队形、减速或停止。不要把两套输出简单相加，可能产生抵消或振荡。障碍解除后再平滑回归队形，同时验证主机状态仍有效。

## 7. 第 7 周：项目证据与系统设计

**本周目标：** 每个项目有明确分工、可回放流程、统一指标和失败案例，能够支持简历表述。

材料：[[知识缺口与证据清单]]、[[面试问题与标准答案]]、[[错题与复盘日志]]。

### W7D1：智能分拣项目证据包

**知识讲解：** 检测、定位、规划、执行和抓取是不同成功事件。记录端到端结果时，还要保留各阶段失败原因，才能知道改进哪个模块有效。

| 材料 | 必须填写 |
|---|---|
| 数据集 | 类别、数量、采集方式、划分与泄漏检查 |
| 模型 | 版本、训练配置、修改点与基线 |
| 标定 | 安装形式、坐标方向、采集姿态、独立验证 |
| 性能 | 硬件、计时边界、样本数、统计量 |
| 抓取 | 成功定义、总次数、重试是否计入、失败分类 |
| 贡献 | 本人模块、协作边界、代码或实验路径 |

**实践步骤：** 给每次试验分配 trial ID，关联图像、检测、位姿、规划结果和执行结果；挑一个失败样例复盘完整链路；将 77.2%、5.8 mm/3.3°、5.4 ms 和 92.6% 逐一对应材料，没有材料则标待核验。

**验收：** 任意抽取一次试验能解释发生了什么；一个指标不能通过另一个指标代替证明。

**Q-W7D1-1：抓取成功率提高了，怎么知道是模型改进带来的？**

**参考回答：** 在其他模块、场景和任务条件固定时替换检测模型，并同时看检测、位姿与端到端结果；必要时做模块消融。若同时修改标定、抓取策略与网络，就不能将收益全部归因于模型。还需记录失败分布和试验不确定性。

**Q-W7D1-2：抓取重试成功应该怎么算？**

**参考回答：** 应预先定义并分别报告首尝试成功率与允许重试后的任务成功率，说明最多重试次数与总耗时。不能把重试成功混入“单次成功率”。对失败样本也要保留记录，避免只筛选最终完成的任务。

### W7D2：规划 benchmark 与消融证据

**知识讲解：** 随机规划结果受场景和随机种子影响，比较需要同样的难度、预算、碰撞检查、硬件与后处理。固定种子帮助复现，但单个固定种子不代表统计结论。

结果表建议每次运行一行：方法、场景、种子、预算、结果状态、首解耗时、推理耗时、搜索耗时、后处理耗时、节点数、检查次数、路径代价和配置版本。

“成功样本平均时间”会受成功集合影响，必须与成功率和超时一起看。也可报告所有任务的实际消耗时间，但超时样本不能被当成真实求解成功时间；两种口径明确分开。

路径代价先定义：例如关节空间长度 $\sum_k\|q_{k+1}-q_k\|$ 与折线转折角是不同量，不能据 1.031 rad 推断其公式。关节角差还要遵循周期与权重约定。

**实践步骤：** 先写实验协议，再运行小规模检查，再开展多场景多种子实验；保留失败和无效路径；做第 4 周的消融；在没有原始记录时不复述 93% 或 0.75 s 为已验证结果。

**验收：** 所有方法采用相同成功定义和计时边界；能从原始行复算汇总表。

**Q-W7D2-1：只比较成功样本时间有什么问题？**

**参考回答：** 一个方法可能只在简单场景成功，另一个解决更难场景，直接比较各自成功集合平均时间并不公平。应同时报告成功率、超时和分场景结果，必要时在共同成功任务上做补充比较，并明确筛选规则。

**Q-W7D2-2：消融实验与对比实验有什么区别？**

**参考回答：** 对比实验回答完整方法相对基线表现如何；消融实验移除或替换具体模块，分析其贡献。消融也要控制其他条件，不能去掉模块时顺便改变预算或后处理。结果不如预期也要报告，帮助识别冗余或负贡献。

### W7D3：导航、覆盖与编队指标

**知识讲解：** 系统指标必须有时间窗口、事件定义与统计单位。导航成功需规定目标位置/航向容差、超时和恢复行为；编队误差需说明期望偏移参考系、稳态区间和统计量。

- 覆盖率：固定可达真值区域内，已探索区域占比。
- 导航成功率：规定规则下成功任务数 / 全部任务数。
- 编队误差：可分别报告位置误差均值、RMSE、P95 与最大值，转弯及避障阶段单列。
- 通信：有效收包频率、序号缺口、间隔分布、延迟与失联次数。

**实践步骤：** 使用地图 mask、任务日志和消息日志重新计算；检查 96.3%、96.7%、15 cm、15 Hz 的口径；时间窗口在统计前确定，不删除波动区间后称为“全程”。

**验收：** 稳态与过渡期分别可追踪；导航失败按定位、规划、控制、通信或任务条件分类。

**Q-W7D3-1：编队误差小于 15 cm，面试官会问什么？**

**参考回答：** 会问是最大误差、均值还是 RMSE，稳态窗口怎么选，是否包括转弯、避障和失联，以及真值和定位精度。回答应引用具体日志与公式，不能把稳态均值描述成全程最大值上界。

**Q-W7D3-2：发送 15 Hz 就代表有效接收 15 Hz 吗？**

**参考回答：** 不代表。要从接收日志中剔除重复和旧包，再统计有效消息与间隔，同时报告丢包和抖动。发送频率、有效接收频率、本地控制频率与端到端延迟是不同指标，分别测量才有意义。

### W7D4：系统设计——多机械臂分拣与低延迟链路

**知识讲解：** 先明确工作区、机械臂数量、目标速率、共享资源和失败成本，再设计模块。典型职责为感知、任务分配、规划、执行、状态监控与日志回放。

共享抓取区或传送带需要任务与空间时间协调，不能仅让各臂独立规划“当前其他臂静止”的场景。感知目标要有 ID、坐标与时间，执行前检查目标是否仍有效。故障隔离与恢复流程要和正常路径同时设计。

**实践步骤：** 画模块图；给每个接口定义输入输出、更新率、错误码与拥有者；构造同一物体被两臂选择、共享区域同时进入、感知过期和控制器失败四个场景；说明协调与回退。

**验收：** 设计包含正确性、时效性、碰撞与资源冲突处理，不只画算法模块；明确集中协调和分布式协作的取舍。

**Q-W7D4-1：两个机械臂各自路径无碰，为什么仍可能相撞？**

**参考回答：** 它们的独立规划可能基于不同或静态的对方状态，执行时占据空间随时间变化。需要考虑联合状态、时序预约、共享区互斥或其他协调策略，并持续更新状态。单臂静态场景的无碰不能推出并发执行无碰。

**Q-W7D4-2：低延迟系统是否应该丢弃所有旧消息？**

**参考回答：** 取决于语义。最新状态流可以丢弃过期样本避免积压，但任务命令、确认和事件可能必须可靠处理。应分别设计最新快照、可靠任务队列与日志通道，而不是对所有消息采用同一种丢弃策略。

### W7D5：崩溃、延迟、TF 跳变与超时排障

**知识讲解：** 排障遵循证据驱动：可复现输入 → 时间线 → 分层假设 → 单变量验证 → 修复 → 回归。需要把应用日志、消息时间、计算耗时与控制状态对齐。

| 症状 | 首批检查 | 需要的证据 |
|---|---|---|
| 进程崩溃 | 堆栈、生命周期、下标、数据竞争 | core/堆栈与复现输入 |
| 消息延迟 | 输入频率、队列、回调与耗时 | 各阶段时间戳 |
| TF 跳变 | 重复发布、时钟、定位校正 | TF 来源和历史变化 |
| 规划超时 | 起终点、场景、检查成本、搜索 | 返回码、有效性和计数 |
| 执行偏差 | 映射、单位、时间、限幅、反馈 | 命令与实际关节曲线 |

**实践步骤：** 选择一种症状，列至少三个可能原因；用日志逐一区分；记录被排除的假设；修复后回放原输入及相邻边界场景。不能以“重启后正常”作为根因证明。

**验收：** 问题描述包括触发条件与影响；修复有可重复证据；不同时改多项设置后将某一项认定为原因。

**Q-W7D5-1：TF 跳变一定是发布冲突吗？**

**参考回答：** 不一定，map 到 odom 的定位校正可能正常跳变，也可能有重复发布、时间异常或里程计错误。先看具体哪条边、哪个发布者及同一时刻的输入，再判断。将所有跳变都滤掉可能掩盖定位问题。

**Q-W7D5-2：没有复现条件如何推进排障？**

**参考回答：** 先保留有限成本的结构化日志、状态快照和关键输入，建立触发上下文，再收集能区分主要假设的观测。优先缩小到最小组件并加输入回放。证据不足时说明当前结论是候选原因，不把猜测写成已确认根因。

### W7D6：证据索引与简历表述修订

**知识讲解：** 一个可信条目应能回答“做了什么、为什么、由谁做、如何验证、在哪些条件下成立”。结论、证据路径和限制需要同时保存。

**实践步骤：** 将三份项目包链接到 [[知识缺口与证据清单]]；对每个数字标明已验证、待补材料或无法复算；为个人分工建立模块表；把未证明的强保证改写成与材料相符的表述建议。

**验收：** 抽取一个数字能在几分钟内找到公式、配置、样本和结果；未核验项不会被自动标成已完成。

**Q-W7D6-1：项目指标没有原始日志怎么办？**

**参考回答：** 如实说明目前缺少可复算材料，优先寻找原记录或按原协议重做；重做结果标明日期与条件。如果仍无法证明，就减少数字化承诺或改用能够支持的定性描述，不能为补齐简历猜一个样本数或统计口径。

**Q-W7D6-2：如何区分个人贡献与团队成果？**

**参考回答：** 先说团队整体目标与最终结果，再明确本人负责模块、接口、代码和实验，指出协作者职责。证据可来自提交、设计文档和实验记录。参与联调不等于独立实现全部算法，清楚边界比笼统说“都做过”更可信。

## 8. 第 8 周：模拟面试与投递闭环

**本周目标：** 在有限时间内独立说明原理、实现、证据与限制，依据模拟结果修订答案和材料。

每次按三步执行：先限时模拟并录音，再对照证据评分，最后只挑最关键的 2–3 个问题回炉。不能边看答案边模拟后记为独立通过。

### W8D1：C++ 与手写代码模拟，45 分钟

**安排：** 5 分钟所有权与生命周期，10 分钟 STL 选型，10 分钟并发，15 分钟手写题，5 分钟复杂度与边界复核。题目从 LRU、二分、Top K 和有界队列中抽取。

**重点学习：** 先说不变量再写实现；先明确单线程或并发场景；复杂度需区分平均与最坏；代码走一遍空输入、重复值与异常结束。

**实践与验收：** 保留未修改的首稿与改正稿，标注错误属于概念、边界、语法还是表达。允许编译检查，但不能把看过修正答案后的版本作为首次独立结果。

**Q-W8D1-1：你写完算法后怎么检查？**

**参考回答：** 先验证核心不变量，再走空、单元素、重复值和非法参数，核对所有权与容器失效规则。之后分析总操作次数和额外空间，必要时用标准容器作为参照。代码能运行一次不代表所有状态转换正确。

**Q-W8D1-2：先写复杂方案还是先讲朴素方案？**

**参考回答：** 可以简短说明正确的基础方案和瓶颈，再提出优化结构，避免在未澄清问题时直接套复杂模板。若优化推导已明确，就重点讲优化的不变量和成本；不要为了展示多个方法耗掉全部编码时间。

### W8D2：ROS/MoveIt 与系统排障模拟，45 分钟

**安排：** 画分拣执行链与 TF 图，回答控制器接口与场景更新，再抽取“规划成功不动”“TF 超时”“局部导航无速度”三个故障中的两个。

**重点学习：** 用消息、坐标、时间和反馈说明箭头；将观察到的事实与推测原因分开；给出下一步检查及预期区分结果。

**实践与验收：** 形成两张图和一份排障顺序，能将故障定位到层级，不依赖无限加预算或频繁重启。

**Q-W8D2-1：你如何证明整个执行链真正闭环？**

**参考回答：** 关联请求、轨迹、action 反馈、硬件命令与实际关节状态，确认结果不只是发送成功。闭环还需定义误差、反馈周期和异常处理。视觉闭环与驱动关节闭环是不同层，应该分别说明。

**Q-W8D2-2：只有 RViz 演示，能证明哪些能力？**

**参考回答：** 可以证明部分模型配置、场景显示与离线规划流程，具体取决于演示内容；不能据此证明硬件通信、实际跟踪和安全降级。回答应明确仿真与真机验证范围，并列出转真机尚需的接口与检查。

### W8D3：运动规划与数学推导模拟，45 分钟

**安排：** 10 分钟配置空间与 RRT-Connect，15 分钟 Jacobian 或阻尼逆推导，10 分钟学习模型接口，10 分钟实验和失败回退。

**重点学习：** 不混淆概率完备与渐近最优；混合采样说明条件；路径质量要给公式；学术性质与实测性能分别回答。

**实践与验收：** 能现场写伪代码、维度正确的矩阵式以及至少一个失效案例；回看模型接口时能指出待核验参数。

**Q-W8D3-1：你说方法更快，快在哪里？**

**参考回答：** 应将时间分为输入处理、网络推理、搜索与后处理，说明减少了节点、检查或无效探索中的哪部分，并给同预算实验。不能只凭搜索循环快而忽略前置推理，也不能用一次最快结果支持总体提升。

**Q-W8D3-2：理论有完备性，为什么实验还会失败？**

**参考回答：** 理论描述在相应假设与预算趋向无限时的概率性质，实际运行时间有限，也可能有建模、约束或实现问题。实验应记录超时与非法输入等不同结果。理论不保证某个固定时间内一定找到路径。

### W8D4：视觉、控制与项目深挖模拟，45 分钟

**安排：** 10 分钟反投影与 OBB，10 分钟手眼坐标链，15 分钟伺服与模式切换，10 分钟误差、延迟及失败案例。

**重点学习：** 提问深入到真实接口：深度是谁的坐标、图像与关节是否同时刻、工具偏置如何处理、目标丢失后谁停止动作。

**实践与验收：** 一张计算链、一份模式表、一段真实或明确标记为练习的失败分析；不把教材方案冒充项目已实现功能。

**Q-W8D4-1：如何判断控制误差来自感知还是执行？**

**参考回答：** 分阶段验证：先用固定真值测感知位姿，再验证坐标转换，最后对比命令与实际末端状态。若感知输出变化而机器人固定，优先分析感知与标定；若目标估计稳定但跟踪偏差大，则检查时间、控制映射和动力学约束。

**Q-W8D4-2：如果视觉丢帧但上一次目标很准确，可以一直执行吗？**

**参考回答：** 不可以无限依赖旧状态。要根据目标是否移动、数据年龄与任务风险定义有限保持或预测窗口，超过阈值就停止局部闭环或回退。使用旧目标时仍需检查环境与控制状态，准确的历史值不等于当前值。

## 9. 四个核心 demo 的实施与验收规范

以下是原计划四个最小 demo 的实施规格，供各周练习落地。**它们是待实现或待验证的学习任务，不表示已经运行通过。** 不必为完成手册就安装完整机器人软件栈。

### 9.1 Demo A：有界线程安全队列

**输入输出：** 任意合法消息、有限容量；提供 push/pop 的成功、超时、关闭状态，元素返回与错误状态可以区分。

**实施顺序：**

1. 单线程实现 FIFO 与容量检查。
2. 加 mutex 保护容器与关闭状态。
3. 加条件变量，分别等待有数据与有空间。
4. 加超时和 close，定义是否排空残留数据。
5. 接入并发生产消费并记录唯一序号。

**验收矩阵：** 空等待、满等待、超时、正常收发、关闭时阻塞唤醒、关闭后 push、残留排空、所有线程退出。统计成功入队/出队与拒绝次数，不能只看输出数量。

**产物：** 源码、编译运行方法、接口约定、验证记录和一页并发状态图。

### 9.2 Demo B：二连杆 Jacobian 与阻尼逆

**输入输出：** 连杆长度、关节姿态和期望二维速度；输出 FK、解析与差分 Jacobian、奇异值、关节速度与任务残差。

**实施顺序：**

1. 按 W3D2 实现 FK，验证零位与已知姿态。
2. 按 W3D3 实现解析 Jacobian。
3. 中心差分验证多姿态和不同 ε。
4. SVD 伪逆与阻尼求解对比，写清奇异值截断规则。
5. 扫描 q2 接近零的姿态，并比较速度及残差。

**验收：** 非奇异处解析与差分一致；近奇异时能解释速度放大；λ 增大时呈现正则化的权衡。对于二连杆位置 Jacobian，`det(J)=l1*l2*sin(q2)` 可作额外核对。

**产物：** 数学推导、程序与数值表。图形展示是可选项，不用图代替数字验证。

### 9.3 Demo C：二维 RRT-Connect

**输入输出：** 边界、障碍、起终点、步长、验证精度、种子与预算；输出路径或明确失败状态及搜索计数。

**实施顺序：**

1. 用已知边和点验证碰撞检查。
2. 实现最近邻、插值及 EXTEND 三种状态。
3. 双树交替与 CONNECT，保留树身份。
4. 恢复路径并独立检查端点、每条边和 parent 链。
5. 加空场景、绕障、狭窄通道、封闭无解与非法起点。

**验收：** 固定种子可复现；无解能够按预算停止；CONNECT 不死循环；所有输出路径通过约定验证。更密离散复查只增强检查覆盖，不等于连续无碰的数学证明。

**产物：** 伪代码、运行配置、路径文件、失败状态及计数表。先完成传统版本，再接学习采样，避免同时调试两套逻辑。

### 9.4 Demo D：UDP 状态与超时保护

**输入输出：** 编码后的主机状态或模拟网络事件；输出有效状态、拒绝原因、数据年龄、状态机状态与限幅命令。

**实施顺序：**

1. 先实现独立编码/解码与长度、版本、单位验证。
2. 按机器人 ID 和序号维护最近有效状态。
3. 用可注入的单调时钟实现本地超时。
4. 按 W6D6 实现 WAIT/FOLLOW/STALE_STOP/RECOVER。
5. 注入停发、长延迟、乱序、重复和时钟异常。

**验收：** 非法或陈旧包不更新有效目标；超时进入受限停止；恢复需要通过明确定义的有效性条件；命令变化满足所定限幅。用软件模拟验证状态逻辑不能证明真实机器人制动距离。

**产物：** 协议文档、状态表、事件日志与故障验证记录；实际网络测试另记环境、收包率及延迟口径。
