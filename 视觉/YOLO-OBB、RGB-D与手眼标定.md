# YOLO-OBB、RGB-D 与手眼标定

## 分拣系统的数据链

```text
RGB-D 图像
→ OBB 检测：类别、置信度、中心、尺寸、角度
→ RGB 与深度对齐、中心邻域深度估计
→ 像素反投影到相机三维坐标
→ 相机外参/手眼变换到机器人基座
→ 生成预抓取与抓取位姿
→ 碰撞规划
→ 近距离视觉伺服修正
```

## OBB 为什么适合分拣

水平框对旋转物体包含大量背景，难以直接提供平面朝向；OBB 增加方向角，更贴合细长或任意朝向物体，也能为抓取姿态提供初值。代价是角度存在周期性和宽高交换歧义，标注、损失与 NMS 都需要旋转框版本。

常见表示包括 $(c_x,c_y,w,h,\theta)$ 或四个顶点。需要统一角度范围，并说明在 $w/h$ 交换时如何处理等价框，否则角度会在边界附近跳变。

## 检测指标

- IoU 衡量预测框和真值框的重叠；OBB 应使用旋转 IoU。
- Precision 关注预测为正的结果中有多少正确；Recall 关注真实目标中有多少被检出。
- AP 是某一类别在不同置信度阈值下 PR 曲线的汇总，mAP 是类别平均。
- `mAP@0.5` 只说明 IoU 阈值 0.5 下的检测表现，不能替代定位误差、姿态误差、速度和最终抓取成功率。

回答 77.2% 时必须补充：测试集划分、类别数、样本数、基线、是否为 OBB mAP、推理分辨率及硬件。

## RGB-D 反投影

针孔模型下，像素 $(u,v)$ 和深度 $Z$ 转为相机坐标：

$$
X=(u-c_x)Z/f_x,\qquad Y=(v-c_y)Z/f_y,\qquad Z=Z
$$

前提是图像已经去畸变，深度与彩色图对齐，并且深度单位正确。不要只取中心单像素：可在中心邻域或目标 mask 内剔除 0 值和离群点，再取中位数或做平面拟合。

主要误差源：深度空洞、反光/透明材质、目标边缘混入背景、RGB-depth 外参误差、时间不同步和相机内参误差。

## 手眼与外参

- Eye-to-hand：相机固定在外部，通常需要求 ${}^{base}T_{camera}$。
- Eye-in-hand：相机随末端运动，需要求 ${}^{tool}T_{camera}$。
- 经典手眼问题常写成 $AX=XB$；通过多组机器人运动和标定板观测求固定变换 $X$。

标定后验证不能只看重投影误差。还应把已知空间点转换到基座坐标，检查位置和姿态误差，并覆盖工作空间不同位置。

## 抓取位姿生成

检测框角度通常只能直接提供图像平面内的方向初值，并不自动等于完整 6D 姿态。需要结合场景假设、平面法向、深度几何或点云估计确定抓取方向；再生成预抓取位姿、接近位姿和离开位姿，并检查工具偏置、关节限位与碰撞。

## 延迟与部署

“5.4 ms 推理”应明确是否只计模型 forward，还是包含预处理、CPU-GPU 拷贝、NMS 和后处理。CUDA 计时需同步并预热；除了均值，最好报告 P50/P95 和端到端帧率。机器人闭环更关心从图像时间戳到控制指令生效的端到端延迟。

## 误差链与实验

最终抓取误差来自检测中心/角度、深度、内参、外参、机器人重复定位精度、工具坐标、控制跟踪和物体移动。建议做分层实验：

1. 只测检测与像素误差。
2. 测相机坐标下的三维位置误差。
3. 测变换到基座后的位姿误差。
4. 测机械臂到达误差。
5. 测端到端抓取成功率并分类失败原因。

## 高频追问

### 为什么中心点深度不可靠？

中心可能落在空洞、反光区域或背景上。目标内多点采样、离群点剔除和中位数/平面拟合更稳健。

### mAP 提升是否一定提高抓取成功率？

不一定。mAP 是检测指标，抓取还受三维定位、姿态、标定、规划和控制影响。应同时报告位姿误差和端到端成功率。

### 如何区分检测角度误差和标定误差？

在相机坐标系先验证检测/三维恢复，再引入外参转换；用分阶段实验隔离误差来源，而不是只看最终抓取结果。

### 目标丢失怎么办？

检查时间戳和置信度；短时丢失可保持最后状态但限制时长，超过阈值立即停止视觉伺服并重新检测/规划，禁止无限使用陈旧位姿。
